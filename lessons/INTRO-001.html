What is React?

1 · Visual Introduction

Think of a page like a LEGO model. Instead of carving the whole thing from one block, you snap small, reusable bricks together. In React each brick is a component (a JavaScript function that returns UI).

   Food delivery app screen               React components
 +--------------------------------+
 | [Logo]  Search...   Cart (2)   |  ---> <Header />
 +--------------------------------+
 | Pizza Palace   4.5 *   30 min  |  ---> <RestaurantCard />
 | Burger Barn    4.2 *   20 min  |  ---> <RestaurantCard />  (same brick, new data)
 | Sushi Stop     4.8 *   40 min  |  ---> <RestaurantCard />
 +--------------------------------+
 |  Home   Orders   Profile       |  ---> <BottomNav />
 +--------------------------------+
                 all inside  ---> <App />
One line: React is a JavaScript library (not a full framework) for building user interfaces out of components.

2 · Why Do We Need It?

Wrong
// Without React: build every card by hand
const list = document.getElementById('list');
list.innerHTML =
  '<div class="card">Pizza Palace 4.5</div>' +
  '<div class="card">Burger Barn 4.2</div>' +
  '<div class="card">Sushi Stop 4.8</div>';
// Change the card design? Edit every string.
// Data changes? Rebuild by hand.
Fixed
// With React: one reusable brick
function RestaurantCard({ name, rating }) {
  return <div className="card">{name} {rating}</div>;
}

// Use it many times with different data
<RestaurantCard name="Pizza Palace" rating={4.5} />
<RestaurantCard name="Burger Barn" rating={4.2} />

3 · Core Concept

  • Library, not framework — React only handles the view (what you see). Routing, data fetching, etc. come from other tools or a framework (e.g. Next.js, React Router in framework mode).
  • Components (building blocks) — plain JavaScript functions that return UI.
  • JSX (HTML-like syntax inside JavaScript) — describes what the UI should look like.
  • Declarative (describe the result, not the steps) — you say "show 3 cards", React works out the DOM changes.
  • Props (inputs to a component) — data passed from parent to child.
  • State (memory inside a component) — when it changes, React re-renders (redraws) that part.
  • react package = components and hooks; react-dom package = puts them on a web page.

4 · Syntax

// 1. A component is a function whose name starts with a Capital letter
function Greeting() {
  return <h1>Hello, food lover!</h1>;
}

// 2. Use it like an HTML tag
<Greeting />

// 3. Mount the root component once (main.jsx)
import { createRoot } from 'react-dom/client';
createRoot(document.getElementById('root')).render(<App />);

With the automatic JSX runtime (default in Vite) you do not need import React from 'react' just to write JSX.

5 · Practical Example

Create the app: npm create vite@latest food-app -- --template react, then cd food-app, npm install, npm run dev.

src/main.jsx

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);

src/App.jsx

const restaurants = [
  { id: 1, name: 'Pizza Palace', rating: 4.5, time: 30 },
  { id: 2, name: 'Burger Barn', rating: 4.2, time: 20 },
  { id: 3, name: 'Sushi Stop', rating: 4.8, time: 40 },
];

function Header() {
  return (
    <header>
      <h1>QuickBite</h1>
      <p>Food in minutes</p>
    </header>
  );
}

function RestaurantCard({ name, rating, time }) {
  return (
    <li>
      <strong>{name}</strong> — {rating} stars — {time} min
    </li>
  );
}

export default function App() {
  return (
    <main>
      <Header />
      <ul>
        {restaurants.map((r) => (
          <RestaurantCard key={r.id} name={r.name} rating={r.rating} time={r.time} />
        ))}
      </ul>
    </main>
  );
}

QuickBite

7 · Execution Flow

 1. Browser loads index.html  (has an empty <div id="root">)
          |
 2. Vite serves src/main.jsx  (JSX compiled to jsx() calls from react/jsx-runtime)
          |
 3. createRoot(#root).render(<App />)
          |
 4. React calls App()  --> returns a tree description (React elements)
          |            calls Header()           --> <header>...
          |            calls RestaurantCard() x3 --> <li>...
          |
 5. react-dom turns the description into real DOM nodes inside #root
          |
 6. Screen shows header + 3 cards

8 · Real-World Application

  • Shopping sites — one ProductCard component reused for thousands of products.
  • Chat apps — MessageBubble, ChatList, TypingIndicator as separate pieces.
  • Movie streaming — rows of MoviePoster components filled from an API.
  • Mobile apps — the same component idea powers React Native (iOS/Android).

9 · Common Mistakes

Mistake 1: lowercase component name

Wrong
function card() {
  return <div>Pizza</div>;
}
// React treats <card /> as an unknown HTML tag
export default function App() {
  return <card />;
}
Fixed
function Card() {
  return <div>Pizza</div>;
}

export default function App() {
  return <Card />;
}

Mistake 2: returning two siblings without a wrapper

Wrong
function Header() {
  return (
    <h1>QuickBite</h1>
    <p>Food in minutes</p>
  ); // Syntax error: adjacent JSX elements
}
Fixed
function Header() {
  return (
    <>
      <h1>QuickBite</h1>
      <p>Food in minutes</p>
    </>
  ); // Fragment groups them, adds no extra DOM
}

Mistake 3: using the old ReactDOM.render

Wrong
import ReactDOM from 'react-dom';
ReactDOM.render(<App />, root);
// Removed in React 19
Fixed
import { createRoot } from 'react-dom/client';
createRoot(root).render(<App />);

Challenge

Split a todo screen into TodoHeader, TodoItem and TodoFooter (shows "3 items").

Solution
const todos = [
  { id: 1, text: 'Buy milk' },
  { id: 2, text: 'Call mom' },
  { id: 3, text: 'Book movie' },
];

function TodoHeader() { return <h2>My Todos</h2>; }
function TodoItem({ text }) { return <li>{text}</li>; }
function TodoFooter({ count }) { return <p>{count} items</p>; }

export default function App() {
  return (
    <section>
      <TodoHeader />
      <ul>
        {todos.map((t) => <TodoItem key={t.id} text={t.text} />)}
      </ul>
      <TodoFooter count={todos.length} />
    </section>
  );
}

11 · Quick Revision

  • React = JavaScript library for UIs.
  • UI is built from components (functions returning JSX).
  • Component names start with a capital letter.
  • Declarative: describe what, React handles how.
  • Mount once with createRoot(...).render(...) from react-dom/client.
  • Start new projects with Vite (or a framework), not Create React App (deprecated Feb 2025).

12 · Interview Corner

Is React a library or a framework?

A library. It focuses on the view layer. Frameworks such as Next.js or React Router (framework mode) add routing, data loading and server rendering on top.

What is a component?

A reusable JavaScript function that returns a description of UI (JSX). It can take props and keep state.

What does "declarative" mean here?

You describe what the screen should look like for the current data; React figures out the DOM operations needed to get there.

Difference between react and react-dom?

react has components, hooks and elements; react-dom renders them into a browser DOM (createRoot lives in react-dom/client).

A · Concept in 30 Seconds

React is a JavaScript library that builds screens from small reusable functions called components. You describe the UI for the current data, and React updates the real page for you.

B · Important Syntax

function Card({ title }) { return <h3>{title}</h3>; }     // component + props
<Card title="Pizza" />                                    // use it
<>...</>                                                  // Fragment
import { createRoot } from 'react-dom/client';            // mount
createRoot(document.getElementById('root')).render(<App />);

C · Must-Know Points

  • React is a library, focused on the view.
  • Components are functions; names start with a capital letter.
  • JSX compiles to jsx() calls (automatic runtime, from react/jsx-runtime).
  • A component must return one root element (or a Fragment).
  • Props flow down from parent to child (one-way data flow).
  • State changes trigger a re-render of that component.
  • ReactDOM.render was removed in React 19; use createRoot.
  • Create React App is deprecated; use Vite or a framework.

D · Interview Questions

Basic

Who maintains React and what is it for?

Meta and the open-source community. It is for building user interfaces from components.

Intermediate

What is a React element vs a component?

A component is the function (Card). An element is the plain object it produces when used (<Card />) that describes what to render.

Advanced

What does JSX turn into?

With the automatic runtime, <h1>Hi</h1> compiles to roughly jsx('h1', { children: 'Hi' }), imported automatically from react/jsx-runtime.

Tricky

Can React be used without JSX?

Yes. JSX is optional syntax sugar; you can call createElement('h1', null, 'Hi') directly. JSX is simply more readable.

E · Output-Based Questions

function Hello({ name }) { return <p>Hi {name}</p>; }
export default function App() {
  return <><Hello name="Asha" /><Hello /></>;
}
What shows?
Hi Asha
Hi

The second has no name, so it is undefined and renders nothing.

F · Debugging Questions

function menu() { return <ul><li>Tea</li></ul>; }
export default function App() { return <menu />; }
Why is the list missing?

Lowercase menu is treated as an HTML tag (<menu>), not your component. Rename to Menu.

G · Scenario-Based Questions

A shop shows 500 product tiles that look the same. How would React help?

Write one ProductTile component, keep products in an array, and map over it. Design changes happen in one place.
