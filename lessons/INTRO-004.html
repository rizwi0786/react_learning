React vs Vanilla JavaScript

1 · Visual Introduction

Two ways to get coffee: vanilla JS is like telling the barista every step ("grind beans, heat milk, pour..."). React is like ordering "one latte" and letting the barista handle the steps.

  VANILLA (imperative)                    REACT (declarative)
 +-----------------------------+        +-----------------------------+
 | 1. find <p id="count">      |        | "count is {count}"          |
 | 2. find <button>            |        | onClick -> setCount(c + 1)  |
 | 3. add click listener       |        |                             |
 | 4. count = count + 1        |        |  React: re-render + patch   |
 | 5. p.textContent = count    |        |                             |
 +-----------------------------+        +-----------------------------+
   You own data AND the DOM.              You own data; React owns DOM.

2 · Why Do We Need It?

Wrong
// Vanilla: adding a "-1" and a "Reset" means
// remembering to update the text in 3 handlers
plus.onclick  = () => { count++; p.textContent = count; };
minus.onclick = () => { count--; p.textContent = count; };
reset.onclick = () => { count = 0; /* forgot p! */ };
Fixed
// React: handlers only change data
<button onClick={() => setCount(count + 1)}>+1</button>
<button onClick={() => setCount(count - 1)}>-1</button>
<button onClick={() => setCount(0)}>Reset</button>
<p>{count}</p> // one place shows it, always right

3 · Core Concept

  • Vanilla JS (plain JavaScript, no library) — you select elements and change them yourself.
  • React — you keep data in state (useState) and return JSX; React updates the DOM.
  • Event handling — vanilla: addEventListener('click', fn); React: onClick={fn} (camelCase prop).
  • Re-render (run the component again) — happens after a state setter call; vanilla has no such concept.
  • Reuse — vanilla needs ids/classes per copy; React just renders <Counter /> twice, each with its own state.
  • Trade-off — vanilla has zero dependencies and is fine for tiny widgets; React shines as UI and team size grow.

5 · Practical Example

Vanilla counter — index.html

<!doctype html>
<html>
  <body>
    <h2>Coffee cups today</h2>
    <p id="count">0</p>
    <button id="minus">-1</button>
    <button id="plus">+1</button>
    <button id="reset">Reset</button>
    <script>
      let count = 0;
      const p = document.getElementById('count');

      function update() {
        p.textContent = count;
        p.style.color = count > 3 ? 'red' : 'inherit';
      }

      document.getElementById('plus').addEventListener('click', () => {
        count++;
        update();
      });
      document.getElementById('minus').addEventListener('click', () => {
        if (count > 0) count--;
        update();
      });
      document.getElementById('reset').addEventListener('click', () => {
        count = 0;
        update();
      });
    </script>
  </body>
</html>

React counter — src/App.jsx (Vite)

import { useState } from 'react';

function Counter({ label }) {
  const [count, setCount] = useState(0);

  console.log('render', label, count); // see Execution Flow note

  return (
    <section>
      <h2>{label}</h2>
      <p style={{ color: count > 3 ? 'red' : 'inherit' }}>{count}</p>
      <button onClick={() => setCount((c) => Math.max(0, c - 1))}>-1</button>
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </section>
  );
}

export default function App() {
  return (
    <main>
      <Counter label="Coffee cups today" />
      <Counter label="Glasses of water" />
    </main>
  );
}

Notice: two independent counters cost one extra line in React. In vanilla you would duplicate the HTML and all the ids and listeners.

7 · Execution Flow

 VANILLA click +1
   listener -> count++ -> update() -> p.textContent = 1   (you did all of it)

 REACT click +1
   onClick
     |
   setCount(c => c + 1)        queue update for THIS Counter only
     |
   React re-runs Counter("Coffee...")   count = 1
     |
   new JSX: <p>1</p>  vs old  <p>0</p>
     |
   diff -> change only that text node
     |
   Water counter untouched (its own state)

8 · Real-World Application

  • Shop quantity picker — the +/- stepper on every cart line is a reusable counter.
  • Food delivery — item counts per dish; each dish has its own state.
  • Chat reactions — like/heart counters on each message.
  • When vanilla is fine — a single "copy to clipboard" button on a static blog doesn't need React.

9 · Common Mistakes

Mistake 1: using a normal variable in React

Wrong
function Counter() {
  let count = 0;
  return (
    <button onClick={() => count++}>{count}</button>
  ); // no re-render; and reset to 0 each render
}
Fixed
function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>{count}</button>
  );
}

Mistake 2: expecting state to change immediately

Wrong
function handle() {
  setCount(count + 1);
  console.log(count); // still old value
  setCount(count + 1); // still uses old value -> +1 total
}
Fixed
function handle() {
  setCount((c) => c + 1);
  setCount((c) => c + 1); // +2 total
}
// read the new value in the next render

Mistake 3: vanilla habits in JSX

Wrong
<button class="btn" onclick="add()">+1</button>
// class -> warning; onclick string -> not how React works
Fixed
<button className="btn" onClick={add}>+1</button>

10 · Practice

Beginner 1

In vanilla JS, write a click counter for a "Likes" button.

Solution
let likes = 0;
const btn = document.getElementById('like');
btn.addEventListener('click', () => {
  likes++;
  btn.textContent = 'Likes: ' + likes;
});

Beginner 2

Write the same in React.

Solution
function Like() {
  const [likes, setLikes] = useState(0);
  return <button onClick={() => setLikes(likes + 1)}>Likes: {likes}</button>;
}

Intermediate 1

Add a step prop so <Counter step={5} /> adds 5.

Solution
function Counter({ step = 1 }) {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount((c) => c + step)}>{count}</button>;
}

Intermediate 2

Show "Limit reached" and disable +1 when the counter hits 10.

Solution
const atLimit = count >= 10;
return (
  <>
    <button disabled={atLimit} onClick={() => setCount((c) => c + 1)}>+1</button>
    {atLimit && <p>Limit reached</p>}
  </>
);

Challenge

A pizza order: Small/Medium/Large quantity counters and a total price line (S 199, M 299, L 399), in React.

Solution
import { useState } from 'react';

const sizes = [
  { id: 'S', price: 199 },
  { id: 'M', price: 299 },
  { id: 'L', price: 399 },
];

export default function App() {
  const [qty, setQty] = useState({ S: 0, M: 0, L: 0 });

  function change(id, delta) {
    setQty((q) => ({ ...q, [id]: Math.max(0, q[id] + delta) }));
  }

  const total = sizes.reduce((sum, s) => sum + s.price * qty[s.id], 0);

  return (
    <div>
      {sizes.map((s) => (
        <p key={s.id}>
          {s.id} (Rs {s.price}):
          <button onClick={() => change(s.id, -1)}>-</button>
          {qty[s.id]}
          <button onClick={() => change(s.id, 1)}>+</button>
        </p>
      ))}
      <h3>Total: Rs {total}</h3>
    </div>
  );
}

11 · Quick Revision

  • Vanilla: you change data and the DOM yourself.
  • React: you change state; React updates the DOM.
  • onClick={fn} replaces addEventListener; className replaces class.
  • Each component instance has its own state.
  • State updates show in the next render; use c => c + 1 for back-to-back updates.
  • Strict Mode double-renders in dev only.
  • Tiny static widgets: vanilla is fine. Growing apps: React.

12 · Interview Corner

Why can't a normal let variable replace useState?

Changing it doesn't tell React to re-render, and it is reset every time the function runs. State is kept by React between renders.

When would you choose vanilla JS over React?

Small, mostly static pages with a few interactions, where adding a library and build step isn't worth it.

Why do my console logs appear twice?

In development, <StrictMode> renders components twice to expose impure code. Production builds render once.

What is the updater form of setState?

setCount(c => c + 1) — React passes the latest queued value, so multiple updates in one event stack correctly.

A · Concept in 30 Seconds

Vanilla JS: you hold the data and edit the DOM by hand after every change. React: you hold the data in state and describe the UI; React re-renders and patches the DOM. The counter shows it: React handlers only change numbers.

B · Important Syntax

// vanilla
let count = 0;
btn.addEventListener('click', () => { count++; p.textContent = count; });

// React
const [count, setCount] = useState(0);
<button onClick={() => setCount((c) => c + 1)}>{count}</button>

C · Must-Know Points

  • React events are camelCase props: onClick, onChange.
  • Pass a function, don't call it: onClick={add}, not onClick={add()}.
  • Use className, not class.
  • Local let variables reset on every render.
  • State is per component instance.
  • State reads inside a handler show the value from that render.
  • Updater function for sequential updates.
  • Strict Mode double render: dev only.

D · Interview Questions

Basic

How do you handle a click in React vs vanilla?

Vanilla: el.addEventListener('click', fn). React: <button onClick={fn}>.

Intermediate

Two <Counter /> components — do they share count?

No. Each rendered instance gets its own state. To share, lift state to the parent and pass it down.

Advanced

Does React update the DOM synchronously inside setCount?

No. It queues the update; React 18+ batches updates (even in timeouts and promises) and re-renders after the handler finishes.

Tricky

Is React always faster than vanilla JS?

No. Hand-tuned vanilla code can be faster for a single widget. React adds overhead but makes complex UIs correct and maintainable.

E · Output-Based Questions

const [n, setN] = useState(0);
function click() {
  setN(n + 5);
  setN((c) => c + 1);
}
// one click
Answer
6

First queues "set to 5", then the updater gets 5 and returns 6.

F · Debugging Questions

function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={setCount(count + 1)}>{count}</button>;
}
// Error: Too many re-renders
Answer

setCount is called during render, which triggers another render, forever. Fix: onClick={() => setCount(count + 1)}.

G · Scenario-Based Questions

A restaurant menu page lists 40 dishes, each with a +/- quantity. Vanilla or React?

React: one QuantityStepper component reused 40 times, each with its own count, plus a derived cart total. Vanilla would need 40 sets of ids/listeners.

H · Coding Challenges

Build a "Votes" widget for a movie with Upvote/Downvote and a score that turns green above 0, red below 0.

Solution
import { useState } from 'react';

export default function Votes() {
  const [score, setScore] = useState(0);
  const color = score > 0 ? 'green' : score < 0 ? 'red' : 'inherit';
  return (
    <div>
      <button onClick={() => setScore((s) => s + 1)}>Upvote</button>
      <strong style={{ color }}> {score} </strong>
      <button onClick={() => setScore((s) => s - 1)}>Downvote</button>
    </div>
  );
}
