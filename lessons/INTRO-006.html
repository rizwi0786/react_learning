Library vs framework

1. Visual Introduction

  • Library = ordering from a food app. You decide when to order, what, and where to eat. You call it.
  • Framework = a fixed-menu restaurant. The restaurant decides the courses and timing; you only fill in your choices when asked. It calls you.
  LIBRARY                               FRAMEWORK
  (you are in control)                  (it is in control)

  your code                             framework
     |                                     |
     |  calls when YOU want                |  calls when IT wants
     v                                     v
  library function                      your code (hooks / callbacks)
     |                                     |
     +--> returns result to you            +--> returns to framework

  "Don't call us, we'll call you"  =  Inversion of Control (IoC)

2. Why Do We Need It?

  • Explains why React feels “small” yet still runs your components for you.
  • Explains why you add React Router, a data library, or a full framework later.
  • A classic interview question: “Is React a library or a framework?”
Wrong

Fixed

3. Core Concept

  • Library (library): a set of functions you call. You own the flow.
  • Framework (framework): a skeleton that calls your code at set points. It owns the flow.
  • Inversion of control (IoC): the control flow is flipped — the tool calls you.
  • React sits in between: you call React once (createRoot(...).render(...)), then React decides when to call your components (rendering).
  • So React has IoC for rendering only; routing, data and project structure are your choice → React calls itself a library.
  • Frameworks on top of React: Next.js, React Router framework mode — they add IoC for routing, data loading and server rendering.

4. Syntax

Library style: you call it

// Intl is a built-in JS library-style API
const price = new Intl.NumberFormat('en-IN', {
  style: 'currency', currency: 'INR'
}).format(250);   // you decide when this runs

React: you call it once, then it calls you

import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(<App />);
// From here, React calls App() whenever it needs to render.

Framework style (React Router framework mode, framework-only)

// app/routes/menu.jsx — the framework calls these exports
export async function loader() {
  return { dishes: ['Biryani', 'Dosa'] };
}
export default function Menu({ loaderData }) {
  return <ul>{loaderData.dishes.map((d) => <li key={d}>{d}</li>)}</ul>;
}

5. Practical Example

See who is in control. Log messages show the order in which code runs.

src/main.jsx

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

console.log('1. main.jsx: I call React');
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);
console.log('2. main.jsx: render() returned');

src/App.jsx

import { useState } from 'react';

// "Library" part: a plain helper YOU call
function formatPrice(amount) {
  return new Intl.NumberFormat('en-IN', {
    style: 'currency',
    currency: 'INR',
  }).format(amount);
}

export default function App() {
  const [qty, setQty] = useState(1);
  console.log('3. App(): React called me, qty =', qty);

  return (
    <div>
      <h1>Pizza order</h1>
      <p>Quantity: {qty}</p>
      <p>Total: {formatPrice(qty * 299)}</p>
      <button onClick={() => setQty(qty + 1)}>Add one more</button>
    </div>
  );
}
You never write App() yourself. You hand <App /> to React and React decides when to run it. That is inversion of control.

8. Real-World Application

  • Small widget (weather card on a blog): use React as a library, mount it into one div.
  • Single-page shop: React + React Router 7 (library/declarative mode) + Vite.
  • SEO-heavy movie site: a React framework (Next.js or React Router framework mode) controls routing, data loading and server rendering.
  • Utility libraries you call: date formatting, fetch, validation helpers — classic library calls inside components.

9. Common Mistakes

Mistake 1: Calling the component yourself

Wrong
root.render(App());
// App runs outside React's render, so its
// useState call fails ("Invalid hook call").
Fixed
root.render(<App />);
// React calls App when it wants.

Mistake 2: Editing DOM that React controls

Wrong
// React owns #root's children
document.getElementById('root').innerHTML =
  '<p>Order placed</p>';
Fixed
const [placed, setPlaced] = useState(false);
// ...
{placed && <p>Order placed</p>}

Mistake 3: Calling createRoot on every update

Wrong
function refresh() {
  createRoot(document.getElementById('root'))
    .render(<App />);
} // warns: container already passed to createRoot
Fixed
const root = createRoot(document.getElementById('root'));
root.render(<App />);
// update via state inside App, not new roots

Challenge

Write a vanilla JS “like” button (you control every step) and the React version (React controls rendering). Count the lines that touch the DOM.

Solution
// Vanilla: you call DOM APIs directly
let likes = 0;
const btn = document.createElement('button');
btn.textContent = 'Likes: 0';
btn.addEventListener('click', () => {
  likes++;
  btn.textContent = 'Likes: ' + likes; // you update DOM
});
document.body.appendChild(btn);

// React: you describe, React updates DOM
import { useState } from 'react';
export default function App() {
  const [likes, setLikes] = useState(0);
  return <button onClick={() => setLikes(likes + 1)}>Likes: {likes}</button>;
}
// Vanilla: 4 DOM-touching lines. React: 0.

11. Quick Revision

  • Library: you call it. Framework: it calls you.
  • Inversion of control (IoC) = the tool owns the flow.
  • React has IoC for rendering only → officially a library.
  • You call createRoot().render() once; React calls components after that.
  • Frameworks on React (Next.js, React Router framework mode) add routing, data and SSR.
  • Never call components as plain functions; never edit React-owned DOM.

12. Interview Corner

Q1. What is inversion of control?

Instead of your code calling the tool, the tool calls your code at defined points. “Don’t call us, we’ll call you.”

Q2. Is React a library or framework?

A library for user interfaces. It applies IoC to rendering, but leaves routing, data fetching and app structure to you or to a framework.

Q3. Why does React feel framework-like?

Because React, not you, decides when components run and re-run, and hooks only work inside that React-controlled flow.

Q4. When would you choose a React framework?

When you need server rendering, file-based or config routing with data loading, or SEO — e.g., a public movie catalogue.

A. Concept in 30 Seconds

You call a library; a framework calls you (inversion of control). React is a UI library: you call render() once, then React calls your components. Routing, data and SSR come from other libraries or frameworks built on React.

B. Important Syntax

import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root'));
root.render(<App />);      // hand control to React

function App() { return <h1>Menu</h1>; } // React calls this

C. Must-Know Points

  1. Library = you control the flow.
  2. Framework = it controls the flow and calls your code.
  3. IoC = Inversion of Control.
  4. React applies IoC only to rendering.
  5. root.render() schedules rendering; it does not run components synchronously in your script.
  6. Write <App />, not App().
  7. Do not manually change DOM React manages.
  8. Next.js and React Router framework mode are frameworks built on React.

D. Interview Questions

Basic

Give an everyday analogy for library vs framework.

Library: ordering any dish from an app when you want. Framework: fixed-menu restaurant serving courses on its schedule.

Intermediate

Where exactly does IoC happen in React?

In rendering: React calls components, runs effects, and calls event handlers you pass. You never call them directly.

Advanced

Why do hooks require React to call the component?

Hooks store state in React’s internal record for the component being rendered. If you call the function yourself, there is no such record for it, so the hooks attach to whatever component called it (or fail).

Tricky

Is React Router a library or framework?

Both: React Router 7 can be used as a library (declarative/data mode) or as a framework (framework mode with loaders, file-based route config and SSR).

F. Debugging Questions

Warning: “You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before.”

You create a new root repeatedly. Create it once, store it, update with state.

Text you set with innerHTML disappears after a click.

React re-rendered and overwrote it. Put the text in state and render it with JSX.
