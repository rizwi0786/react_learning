Features of React

1. Visual Introduction

A todo app is built like a LEGO set: small blocks, snapped together, with data flowing down.

              +-------------------------+
              |  App   (holds state)    |   hooks: useState
              |  todos = [...]          |
              +-----------+-------------+
                          | props (one-way, downward)
          +---------------+----------------+
          v                                v
 +------------------+            +-------------------+
 | AddTodo          |            | TodoList          |
 | onAdd(text) -----+--> up via  |  todos            |
 +------------------+   callback +---------+---------+
                                           | props
                                           v
                                 +-------------------+
                                 | TodoItem  x N     |  written in JSX
                                 +-------------------+

 state changes -> new element tree (virtual DOM) -> diff -> minimal real DOM update

2. Why Do We Need It?

  • Plain DOM code mixes data, markup and updates in one long script.
  • React’s features split the UI into reusable pieces and keep data predictable.
Wrong
// Vanilla: one big script
const ul = document.querySelector('#list');
todos.forEach((t) => {
  const li = document.createElement('li');
  li.textContent = t.text;
  ul.appendChild(li);
});
// adding one todo? rebuild or patch by hand
Fixed
// React: reusable component, data in, UI out
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((t) => <li key={t.id}>{t.text}</li>)}
    </ul>
  );
}

3. Core Concept

  • Components (components): reusable UI pieces written as functions that return markup.
  • JSX (JSX): HTML-like syntax inside JavaScript; compiled to jsx() calls from react/jsx-runtime automatically.
  • One-way data flow (unidirectional data flow): data goes parent → child through props; children ask parents to change data through callback props.
  • Virtual DOM (virtual DOM): React keeps a lightweight in-memory tree of elements, compares old and new trees (reconciliation), and changes only what differs in the real DOM.
  • Hooks (hooks): functions like useState and useEffect that give function components state and side effects.
  • Also in React 19: Actions (useActionState, useOptimistic), use(), ref as a normal prop. Server Components are framework-only (need Next.js or similar).

4. Syntax

// Component + JSX
function Greeting({ name }) {          // props in
  return <h2>Hi, {name}!</h2>;          // JSX out
}

// Hook
const [count, setCount] = useState(0);

// One-way data flow
<Greeting name="Asha" />                 // parent passes data down
<AddTodo onAdd={handleAdd} />           // child calls back up

// What JSX compiles to (automatic runtime, done by Vite for you)
import { jsxs as _jsxs } from 'react/jsx-runtime';
_jsxs('h2', { children: ['Hi, ', name, '!'] });
// (jsxs = jsx for static multiple children)

5. Practical Example

A todo app that uses all five features. Paste into src/App.jsx of a Vite React app.

import { useState, useEffect } from 'react';

// Component: one todo row (receives data via props)
function TodoItem({ todo, onToggle }) {
  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={todo.done}
          onChange={() => onToggle(todo.id)}
        />
        {todo.done ? <s>{todo.text}</s> : todo.text}
      </label>
    </li>
  );
}

// Component: input box, sends new text UP via a callback
function AddTodo({ onAdd }) {
  const [text, setText] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    if (!text.trim()) return;
    onAdd(text.trim());
    setText('');
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="e.g. Buy milk"
      />
      <button type="submit">Add</button>
    </form>
  );
}

// Root component: owns the state (single source of truth)
export default function App() {
  const [todos, setTodos] = useState([
    { id: 1, text: 'Order groceries', done: true },
    { id: 2, text: 'Book movie tickets', done: false },
  ]);

  const pending = todos.filter((t) => !t.done).length;

  // Hook for a side effect: keep the tab title in sync
  useEffect(() => {
    document.title = `${pending} pending`;
  }, [pending]);

  function addTodo(text) {
    setTodos([...todos, { id: Date.now(), text, done: false }]);
  }

  function toggleTodo(id) {
    setTodos(
      todos.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
    );
  }

  return (
    <main>
      <h1>My Todos ({pending} pending)</h1>
      <AddTodo onAdd={addTodo} />
      <ul>
        {todos.map((t) => (
          <TodoItem key={t.id} todo={t} onToggle={toggleTodo} />
        ))}
      </ul>
    </main>
  );
}

7. Execution Flow

 1. User types in AddTodo  -> setText (local state)  -> AddTodo re-renders
 2. User clicks Add        -> handleSubmit -> onAdd("Pay electricity bill")
                                               |  (callback goes UP)
 3. App.addTodo            -> setTodos([...todos, newTodo])
 4. React re-runs App()    -> new JSX tree (virtual DOM)
 5. React compares old tree vs new tree (reconciliation)
       - h1 text changed   "1 pending" -> "2 pending"
       - one new <li> with key = new id
       - other <li>s same key, same props -> DOM left alone
 6. Commit: React updates h1 text, inserts 1 <li>
 7. useEffect runs (pending changed) -> document.title = "2 pending"

9. Common Mistakes

Mistake 1: Changing props in a child

Wrong
function TodoItem({ todo }) {
  return (
    <input type="checkbox"
      onChange={() => { todo.done = !todo.done; }} />
  ); // breaks one-way flow, no re-render
}
Fixed
function TodoItem({ todo, onToggle }) {
  return (
    <input type="checkbox" checked={todo.done}
      onChange={() => onToggle(todo.id)} />
  ); // ask the parent to change state
}

Mistake 2: Missing key in lists

Wrong
{todos.map((t) => <TodoItem todo={t} />)}
// Warning: Each child in a list should
// have a unique "key" prop.
Fixed
{todos.map((t) => <TodoItem key={t.id} todo={t} />)}

Mistake 3: Calling a hook inside a condition

Wrong
if (todos.length > 0) {
  useEffect(() => { document.title = 'Todos'; });
} // breaks the Rules of Hooks
Fixed
useEffect(() => {
  if (todos.length > 0) document.title = 'Todos';
}, [todos.length]);

Mistake 4: Lowercase component name

Wrong
function todoItem() { return <li>Hi</li>; }
<todoItem /> // treated as an unknown HTML tag
Fixed
function TodoItem() { return <li>Hi</li>; }
<TodoItem />

Challenge

Build a movie “watchlist” with a MovieRow child that has a Remove button. State lives only in App.

Solution
import { useState } from 'react';

function MovieRow({ movie, onRemove }) {
  return (
    <li>
      {movie.title} ({movie.year}){' '}
      <button onClick={() => onRemove(movie.id)}>Remove</button>
    </li>
  );
}

export default function App() {
  const [movies, setMovies] = useState([
    { id: 1, title: 'Lagaan', year: 2001 },
    { id: 2, title: 'Inception', year: 2010 },
  ]);

  return (
    <ul>
      {movies.map((m) => (
        <MovieRow
          key={m.id}
          movie={m}
          onRemove={(id) => setMovies(movies.filter((x) => x.id !== id))}
        />
      ))}
    </ul>
  );
}

11. Quick Revision

  • Components = reusable functions that return JSX; names start with a capital letter.
  • JSX compiles to jsx() calls (automatic runtime); no import React needed.
  • Data flows down via props; changes go up via callbacks.
  • Virtual DOM + reconciliation = only changed DOM nodes are updated.
  • Hooks give state and effects; call them at the top level only.
  • Keys help React match list items between renders.
  • Server Components exist but are framework-only.

12. Interview Corner

Q1. What are the main features of React?

Components, JSX, one-way data flow, virtual DOM with reconciliation, and hooks. React 19 adds Actions, use() and ref-as-prop.

Q2. Why one-way data flow?

Each piece of data has one owner, so you always know where a change came from. Debugging is easier than two-way binding.

Q3. Is the virtual DOM always faster than direct DOM edits?

No. Hand-written targeted DOM edits can be faster. The virtual DOM gives “fast enough” updates while you write simpler declarative code.

Q4. Do I need import React from 'react' to use JSX?

No. With the automatic JSX runtime (default in Vite), the compiler imports jsx from react/jsx-runtime for you.

Q5. What are the Rules of Hooks?

Call hooks only at the top level of a component or custom hook, never in loops, conditions or nested functions, and only from React functions.

A. Concept in 30 Seconds

React apps are trees of components written in JSX. Data flows one way, parent to child, through props. Hooks add state and effects. When state changes, React builds a new element tree (virtual DOM), diffs it, and updates only the changed real DOM.

B. Important Syntax

function Card({ title }) { return <h3>{title}</h3>; }   // component + JSX
<Card title="Weather" />                                 // props down
const [city, setCity] = useState('Pune');                // state hook
useEffect(() => { /* fetch */ }, [city]);                // effect hook
<Search onSearch={setCity} />                            // callback up
{items.map((i) => <Row key={i.id} item={i} />)}          // list + key

C. Must-Know Points

  1. Component names start with a capital letter.
  2. Components must be pure during render: same props/state → same JSX.
  3. Props are read-only.
  4. JSX expressions go in single braces { }.
  5. JSX uses className and camelCase events (onClick).
  6. Keys must be stable and unique among siblings.
  7. Hooks only at the top level.
  8. Reconciliation compares element type and key to decide reuse vs replace.
  9. Strict Mode double-calls components in development only, to surface impure code.

D. Interview Questions

Basic

What is JSX?

A syntax extension that looks like HTML and compiles to JavaScript function calls creating React elements.

Intermediate

How does a child update the parent’s state?

The parent passes a function as a prop; the child calls it with new data; the parent sets its own state.

Advanced

What does React compare during reconciliation?

Element type and key at each position. Same type + key → update props on the existing node. Different → unmount old, mount new.

Tricky

Why is using the array index as a key risky?

If items are inserted, removed or reordered, indexes shift and React may reuse the wrong component, keeping stale input text or state.

F. Debugging Questions

Checkbox toggles visually but count never changes. Child does todo.done = !todo.done.

Mutating props. Pass onToggle from the parent and update state there immutably.

Error: “Rendered more hooks than during the previous render.”

A hook is inside a condition or after an early return. Move it to the top level.

G. Scenario-Based Questions

Both the header badge and the checkout page need the cart count. Where should state live?

In their closest common parent; pass it down as props (lifting state up).

A chat list of 1,000 messages re-renders when one arrives. Is the DOM rebuilt?

No. With stable keys, React inserts only the new <li>; existing nodes are reused.

import { useState } from 'react';
export default function Counter() {
  const [n, setN] = useState(0);
  return (
    <div>
      <button onClick={() => setN(Math.max(0, n - 1))}>−</button>
      <span> {n} </span>
      <button onClick={() => setN(n + 1)}>+</button>

  );
}
