Declarative vs imperative programming

1. Visual Introduction

  • Imperative = giving a taxi driver every turn: “Left, 200 m straight, right at the signal…”
  • Declarative = telling the driver the destination: “Take me to the railway station.” The driver works out the turns.
 IMPERATIVE (how)                      DECLARATIVE (what)

 event happens                         event happens
     |                                     |
 find element                          change the data (state)
 change its text                           |
 show/hide badge                       UI = f(state)
 add/remove class                          |
 append/remove nodes                   React works out the DOM steps
     |                                     |
 hope you did not forget a step        screen always matches state
UI = f(state) — the screen is the result of a function (your component) applied to the current data (state).

2. Why Do We Need It?

  • With imperative code, every new feature adds more “if this changed, also update that” steps.
  • Forget one step → the screen shows old data (stale UI).
  • Declarative code describes the final look once; it cannot drift out of sync.
Wrong
// Imperative: 3 places to update by hand
function markRead() {
  unread = 0;
  badge.textContent = '0';
  badge.style.display = 'none';
  // forgot: title still says "(3) Chat"
}
Fixed
// Declarative: change data, UI follows
function markRead() {
  setUnread(0);
}
// badge and title are both derived from unread

3. Core Concept

  • Imperative (imperative programming): you write step-by-step instructions to change the DOM.
  • Declarative (declarative programming): you describe what the UI should look like for a given state.
  • State (state): the data that can change over time (unread count, cart items).
  • UI as a function of state: same state → same UI, every time.
  • React does the imperative part for you: it compares the new description with the old (reconciliation) and runs the DOM steps (commit).
  • Escape hatches: refs and effects let you write imperative code when needed (focus an input, play a video).

4. Syntax

Imperative (vanilla DOM)

const el = document.querySelector('#status');
if (isOnline) {
  el.textContent = 'Online';
  el.classList.add('green');
} else {
  el.textContent = 'Offline';
  el.classList.remove('green');
}

Declarative (React JSX)

<span className={isOnline ? 'green' : ''}>
  {isOnline ? 'Online' : 'Offline'}
</span>

5. Practical Example

A chat inbox with an unread badge and a “Mark all read” button, written both ways.

Imperative: index.html + vanilla JS

<h1 id="heading"></h1>
<ul id="list"></ul>
<button id="readAll">Mark all read</button>

<script>
  const messages = [
    { id: 1, from: 'Riya', text: 'Lunch at 1?', read: false },
    { id: 2, from: 'Kabir', text: 'Movie tonight!', read: false },
    { id: 3, from: 'Mom', text: 'Call me', read: true },
  ];

  const heading = document.getElementById('heading');
  const list = document.getElementById('list');

  // Step 1: build list by hand
  messages.forEach((m) => {
    const li = document.createElement('li');
    li.id = 'msg-' + m.id;
    li.textContent = m.from + ': ' + m.text;
    if (!m.read) li.style.fontWeight = 'bold';
    list.appendChild(li);
  });

  // Step 2: set heading by hand
  let unread = messages.filter((m) => !m.read).length;
  heading.textContent = 'Inbox (' + unread + ' unread)';

  // Step 3: on click, update EVERY affected piece by hand
  document.getElementById('readAll').addEventListener('click', () => {
    messages.forEach((m) => {
      m.read = true;
      document.getElementById('msg-' + m.id).style.fontWeight = 'normal';
    });
    unread = 0;
    heading.textContent = 'Inbox (0 unread)';
    document.getElementById('readAll').disabled = true;
  });
</script>

Declarative: src/App.jsx (Vite React app)

import { useState } from 'react';

const initialMessages = [
  { id: 1, from: 'Riya', text: 'Lunch at 1?', read: false },
  { id: 2, from: 'Kabir', text: 'Movie tonight!', read: false },
  { id: 3, from: 'Mom', text: 'Call me', read: true },
];

export default function App() {
  const [messages, setMessages] = useState(initialMessages);

  // Derived from state — never stored separately
  const unread = messages.filter((m) => !m.read).length;

  function markAllRead() {
    setMessages(messages.map((m) => ({ ...m, read: true })));
  }

  // Describe WHAT the UI looks like for this state
  return (
    <main>
      <h1>Inbox ({unread} unread)</h1>
      <ul>
        {messages.map((m) => (
          <li key={m.id} style={{ fontWeight: m.read ? 'normal' : 'bold' }}>
            {m.from}: {m.text}
          </li>
        ))}
      </ul>
      <button onClick={markAllRead} disabled={unread === 0}>
        Mark all read
      </button>
    </main>
  );
}
Imperative version: 3 separate DOM-update steps you must keep in sync. React version: one description; React figures out which nodes changed.

8. Real-World Application

  • Food-delivery tracker: status “Preparing → On the way → Delivered” is one state value; the progress bar, map pin and ETA text all derive from it.
  • Shop filters: the product grid is products.filter(...) of the selected filters — no manual show/hide.
  • Weather app: icon, background and text are all chosen from weather.condition.
  • Imperative still needed: focusing a search box, scrolling a chat to the bottom, playing a video — use refs/effects.

9. Common Mistakes

Mistake 1: Reaching into the DOM from React

Wrong
function markAllRead() {
  document.querySelector('h1').textContent =
    'Inbox (0 unread)';
} // next render overwrites it
Fixed
function markAllRead() {
  setMessages(messages.map((m) => ({ ...m, read: true })));
} // h1 is derived from messages

Mistake 2: Storing derived data as extra state

Wrong
const [messages, setMessages] = useState(initial);
const [unread, setUnread] = useState(2);
// must remember to update both = imperative thinking
Fixed
const [messages, setMessages] = useState(initial);
const unread = messages.filter((m) => !m.read).length;

Mistake 3: Toggling visibility by hand

Wrong
useEffect(() => {
  document.getElementById('badge').style.display =
    unread ? 'inline' : 'none';
}, [unread]);
Fixed
{unread > 0 && <span id="badge">{unread}</span>}

10. Practice

Beginner 1

Label each as imperative or declarative: (a) el.classList.add('open') (b) <div className={open ? 'open' : ''}>

Solution

(a) imperative, (b) declarative.

Beginner 2

Write JSX that shows “Shop open” or “Shop closed” based on isOpen.

Solution
<p>{isOpen ? 'Shop open' : 'Shop closed'}</p>

Intermediate 1

Convert to React: if (items.length === 0) { msg.textContent = 'Cart is empty'; } else { msg.textContent = items.length + ' items'; }

Solution
<p>{items.length === 0 ? 'Cart is empty' : `${items.length} items`}</p>

Intermediate 2

A weather card stores temp and also isHot (temp > 35) in state. Remove the redundant state.

Solution
const [temp, setTemp] = useState(38);
const isHot = temp > 35; // derived, not state
return <p>{temp}°C {isHot && '- Stay indoors'}</p>;

Challenge

Build a food-order status tracker in React with a “Next step” button cycling through Placed → Preparing → On the way → Delivered. The button disappears at Delivered.

Solution
import { useState } from 'react';

const STEPS = ['Placed', 'Preparing', 'On the way', 'Delivered'];

export default function App() {
  const [step, setStep] = useState(0);
  const done = step === STEPS.length - 1;

  return (
    <div>
      <h2>Order status: {STEPS[step]}</h2>
      <ol>
        {STEPS.map((s, i) => (
          <li key={s} style={{ fontWeight: i === step ? 'bold' : 'normal' }}>
            {i <= step ? '✔ ' : ''}{s}
          </li>
        ))}
      </ol>
      {!done && <button onClick={() => setStep(step + 1)}>Next step</button>}
    </div>
  );
}

11. Quick Revision

  • Imperative = how (step-by-step DOM edits).
  • Declarative = what (describe UI for the current state).
  • React: UI = f(state); change state, not the DOM.
  • Derive values from state instead of storing copies.
  • React performs the imperative DOM work after diffing.
  • Use refs/effects only for true imperative needs (focus, scroll, media).

12. Interview Corner

Q1. What does “React is declarative” mean?

You describe what the UI should look like for each state; React decides how to update the DOM to match.

Q2. Give an example of imperative code React hides from you.

createElement, appendChild, removeChild, setting textContent and attributes — React does these during the commit phase.

Q3. Is declarative always better?

For UI state, usually yes. But some browser actions are inherently imperative (focus, scroll, animations); React provides refs and effects for them.

Q4. What is “derived state” and why avoid storing it?

A value computable from existing state/props (e.g., unread count). Storing it separately means two sources of truth that can disagree.

A. Concept in 30 Seconds

Imperative code says how: find this element, change that text. Declarative code says what: for this state, the UI looks like this. In React, UI = f(state). You update state; React computes and applies the DOM changes.

B. Important Syntax

// conditional text
<p>{online ? 'Online' : 'Offline'}</p>
// conditional element
{unread > 0 && <span>{unread}</span>}
// conditional class
<li className={done ? 'done' : ''}>{text}</li>
// list from data
{items.map((i) => <li key={i.id}>{i.name}</li>)}
// derived value
const total = cart.reduce((s, i) => s + i.price, 0);

C. Must-Know Points

  1. Imperative = step-by-step instructions.
  2. Declarative = describe the desired result.
  3. React components are declarative descriptions.
  4. Same state + props → same JSX (pure render).
  5. Never edit React-managed DOM directly.
  6. Compute derived values during render.
  7. React runs the imperative DOM operations in the commit phase.
  8. Refs and effects are escape hatches for imperative tasks.

D. Interview Questions

Basic

Define declarative programming in one line.

Describing what the result should be, not the steps to get there.

Intermediate

Why does declarative UI reduce bugs?

There is one description per state, so the screen cannot drift; no forgotten manual update steps.

Advanced

How does React turn a declarative description into DOM changes?

Render phase: call components to get a new element tree. Reconciliation: diff with the previous tree. Commit phase: apply the minimal DOM mutations.

Tricky

Is useEffect declarative or imperative?

You declare when it should run (dependencies), but the code inside is usually imperative (it syncs with something outside React).

E. Output-Based Questions

const unread = 0; → <p>Inbox {unread && <b>{unread}</b>}</p>
Inbox 0

0 && … returns 0, which React renders. Use unread > 0 &&.

const temp = 40; → <p>{temp > 35 ? 'Hot' : 'Pleasant'}</p>
Hot

F. Debugging Questions

You set h1.textContent in a click handler; it reverts after the next click.

React re-rendered from state and overwrote it. Change state instead.

Cart badge shows 3 but list shows 2 items.

Count stored as separate state and not updated. Derive it: cart.length.

G. Scenario-Based Questions

A chat should scroll to the newest message. Declarative or imperative?

Imperative: use a ref to the list and call scrollIntoView() in an effect after messages change.

A shop page shows/hides a “Free delivery” banner when the cart passes ₹500.

Declarative: {total > 500 && <Banner />}.

H. Coding Challenges

Rewrite declaratively: btn.disabled = cart.length === 0;
<button disabled={cart.length === 0}>Checkout</button>
Focus a search input on mount (imperative escape hatch).
import { useEffect, useRef } from 'react';

export default function Search() {
  const inputRef = useRef(null);
  useEffect(() => {
    inputRef.current.focus(); // imperative, inside an effect
  }, []);
  return <input ref={inputRef} placeholder="Search movies" />;
}
