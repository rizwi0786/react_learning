Single Page Applications

1. Visual Introduction

Think of a food delivery app as one restaurant table. The waiter swaps the plates (views) on the table; you never walk to a new restaurant (a new page load).

  Browser asks ONCE:  GET /  ----------------->  Server
                      <-- index.html + app.js --

  +------------------------------------------------+
  |  index.html   (loaded one time)                |
  |  +------------------------------------------+  |
  |  |  <div id="root">                         |  |
  |  |    click "Menu"   -> show <Menu />       |  |
  |  |    click "Cart"   -> show <Cart />       |  |
  |  |    click "Orders" -> show <Orders />     |  |
  |  +------------------------------------------+  |
  |  URL bar changes: /menu  /cart  /orders        |
  |  but NO new HTML document is downloaded        |
  +------------------------------------------------+

  Later data?  fetch('/api/menu')  ->  JSON only (small)

2. Why Do We Need It?

  • Full page reloads blank the screen and re-download the header, footer, CSS and scripts.
  • Typed text, scroll position and in-memory state are lost on every click.
  • An SPA keeps the page alive and only swaps the part that changed.
Wrong
<!-- Every link = new document from the server -->
<nav>
  <a href="/menu.html">Menu</a>
  <a href="/cart.html">Cart</a>
</nav>
<!-- click -> white flash -> whole page rebuilt
     -> cart count in JS memory is gone -->
Fixed
// SPA: change the view, keep the page
import { Link } from "react-router";

function Nav() {
  return (
    <nav>
      <Link to="/menu">Menu</Link>
      <Link to="/cart">Cart</Link>
    </nav>
  );
}
// click -> URL updates -> only <main> re-renders

3. Core Concept

  • One HTML page (document) is loaded once; JavaScript draws every screen inside it.
  • Changing screens = changing what React renders, based on the URL (client-side routing).
  • The URL is changed without a reload using the browser's History API (history.pushState).
  • Back/Forward buttons fire a popstate event; the app listens and re-renders.
  • After the first load, the app talks to the server only for data, usually JSON (API calls).
  • In practice you use a router library such as React Router 7 instead of writing this by hand.
  • The server must return index.html for every app URL (history fallback), or deep links give 404.

4. Syntax

The raw browser tools (what routers use underneath)

// change the URL without reloading
window.history.pushState({}, "", "/cart");

// read the current path
window.location.pathname; // "/cart"

// react when the user presses Back / Forward
window.addEventListener("popstate", () => {
  console.log("now at", window.location.pathname);
});

The same idea with React Router 7 (declarative mode)

// npm install react-router
import { BrowserRouter, Routes, Route, Link } from "react-router";

<BrowserRouter>
  <Link to="/cart">Cart</Link>
  <Routes>
    <Route path="/" element={<Menu />} />
    <Route path="/cart" element={<Cart />} />
  </Routes>
</BrowserRouter>
React Router 7 ships from the react-router package. react-router-dom still exists only as a re-export for older code.

5. Practical Example

A tiny food-delivery SPA with a hand-made router, so you can see exactly how views swap. Paste into src/App.jsx of a Vite React app (npm create vite@latest my-spa -- --template react).

// src/App.jsx
import { useEffect, useState } from "react";

const DISHES = [
  { id: 1, name: "Paneer Wrap", price: 149 },
  { id: 2, name: "Veg Biryani", price: 199 },
  { id: 3, name: "Masala Dosa", price: 99 },
];

function Menu({ onAdd }) {
  return (
    <section>
      <h2>Menu</h2>
      <ul>
        {DISHES.map((d) => (
          <li key={d.id}>
            {d.name} - Rs {d.price}{" "}
            <button onClick={() => onAdd(d)}>Add</button>
          </li>
        ))}
      </ul>
    </section>
  );
}

function Cart({ items }) {
  const total = items.reduce((sum, d) => sum + d.price, 0);
  return (
    <section>
      <h2>Cart</h2>
      {items.length === 0 ? <p>Your cart is empty.</p> : (
        <ul>{items.map((d, i) => <li key={i}>{d.name}</li>)}</ul>
      )}
      <p>Total: Rs {total}</p>
    </section>
  );
}

function NavLink({ to, current, onNavigate, children }) {
  return (
    <a
      href={to}
      onClick={(e) => {
        e.preventDefault();   // stop the browser's full page load
        onNavigate(to);
      }}
      style={{ fontWeight: current === to ? "bold" : "normal", marginRight: 12 }}
    >
      {children}
    </a>
  );
}

export default function App() {
  const [path, setPath] = useState(window.location.pathname);
  const [cart, setCart] = useState([]);

  // Back / Forward buttons
  useEffect(() => {
    const onPop = () => setPath(window.location.pathname);
    window.addEventListener("popstate", onPop);
    return () => window.removeEventListener("popstate", onPop);
  }, []);

  function navigate(to) {
    window.history.pushState({}, "", to); // URL changes, no reload
    setPath(to);                          // React swaps the view
  }

  return (
    <div>
      <header>
        <strong>QuickBite</strong> | Cart items: {cart.length}
      </header>
      <nav>
        <NavLink to="/" current={path} onNavigate={navigate}>Menu</NavLink>
        <NavLink to="/cart" current={path} onNavigate={navigate}>Cart</NavLink>
      </nav>
      <main>
        {path === "/cart"
          ? <Cart items={cart} />
          : <Menu onAdd={(d) => setCart([...cart, d])} />}
      </main>
    </div>
  );
}
Vite's dev server already serves index.html for unknown paths, so refreshing on /cart works locally. A production host needs the same fallback rule.

7. Execution Flow

 1. Browser: GET /            -> server sends index.html + JS bundle
 2. main.jsx: createRoot(...).render(<App />)
 3. App reads location.pathname "/"  -> renders <Menu />
 4. User clicks "Add"         -> setCart([...])  -> header shows 1
 5. User clicks "Cart" link
        |
        v
    e.preventDefault()        (browser does NOT load /cart)
        |
        v
    history.pushState("/cart") (URL bar updates)
        |
        v
    setPath("/cart")  -> React re-renders -> <Cart /> replaces <Menu />
 6. User presses Back
        |
        v
    browser fires "popstate" -> setPath("/") -> <Menu /> again
    (cart state survives: the page never unloaded)

8. Real-World Application

  • Email web apps: open a message, go back to the inbox, no reload.
  • Music/movie streaming: the player keeps playing while you browse pages.
  • Chat apps: switch conversations instantly; the socket connection stays open.
  • Dashboards behind a login: SEO does not matter, smooth navigation does.

9. Common Mistakes

Mistake 1: Using a plain <a> inside a router app

Wrong
// full reload: all React state is thrown away
<a href="/cart">Cart</a>
Fixed
import { Link } from "react-router";

<Link to="/cart">Cart</Link>

Mistake 2: Changing the URL but not the view

Wrong
function navigate(to) {
  window.history.pushState({}, "", to);
  // URL changed, but React never re-renders
}
Fixed
function navigate(to) {
  window.history.pushState({}, "", to);
  setPath(to); // state change triggers re-render
}

Mistake 3: Forgetting the server fallback

Wrong
# user refreshes on /cart in production
GET /cart  ->  404 Not Found
# server looked for a real file called /cart
Fixed
# host rule: any unknown path -> index.html
GET /cart  ->  200 index.html
# React then reads "/cart" and shows <Cart />

Beginner 2

Open DevTools → Network, filter "Doc", click between Menu and Cart. How many document requests appear?

Solution

Intermediate 1

Show a "Page not found" view for any path other than /, /cart, /orders.

Solution 
const views = {
  "/": <Menu onAdd={(d) => setCart([...cart, d])} />,
  "/cart": <Cart items={cart} />,
  "/orders": <Orders />,
};
<main>{views[path] ?? <p>Page not found</p>}</main>

Intermediate 2

Rewrite the routing with React Router 7 (BrowserRouter, Routes, Route, Link).

Solution 
import { useState } from "react";
import { BrowserRouter, Routes, Route, Link } from "react-router";

export default function App() {
  const [cart, setCart] = useState([]);
  return (
    <BrowserRouter>
      <header>QuickBite | Cart items: {cart.length}</header>
      <nav><Link to="/">Menu</Link> <Link to="/cart">Cart</Link></nav>
      <Routes>
        <Route path="/" element={<Menu onAdd={(d) => setCart([...cart, d])} />} />
        <Route path="/cart" element={<Cart items={cart} />} />
        <Route path="*" element={<p>Page not found</p>} />
      </Routes>
    </BrowserRouter>
  );
}

Challenge

Update the browser tab title (document.title) to "Menu · QuickBite" or "Cart · QuickBite" whenever the view changes, including Back/Forward.

Solution 
useEffect(() => {
  const names = { "/": "Menu", "/cart": "Cart", "/orders": "Orders" };
  document.title = (names[path] ?? "Not found") + " · QuickBite";
}, [path]); // runs after every path change, including popstate

React 19 also lets you render <title> inside a component and hoists it to <head>.

11. Quick Revision

  • SPA = one HTML document, many views drawn by JavaScript.
  • Navigation = URL change via pushState + state change → re-render.
  • Back/Forward → popstate event.
  • Only data (JSON) travels after the first load.
  • Use <Link>, never plain <a>, for in-app links.
  • Production server needs an index.html fallback for deep links.

12. Interview Corner

Q1. What is a Single Page Application?

A web app that loads one HTML document once and then updates the screen with JavaScript, changing views without full page reloads.

Q2. How does an SPA change the URL without reloading?

With the History API: history.pushState() updates the URL; the router then renders the matching component. Back/Forward fire popstate.

Q3. Why do SPA deep links sometimes return 404?

The server looks for a real file at that path. It must be configured to return index.html for app routes (history fallback).

Q4. Is React itself a router?

No. React only renders UI. Routing comes from a library like React Router or from a framework.

Q5. Main downsides of a pure SPA?

Bigger initial JavaScript, blank screen until JS runs, weaker SEO/link previews without server rendering, and you must manage titles, focus and scroll yourself.

A. Concept in 30 Seconds

One page loads once. Clicking a link changes the URL (History API) and React swaps the view. No white flash, state survives, only JSON comes from the server afterwards.

C. Must-Know Points

  • One HTML document for the whole app.
  • Views are components chosen by the current URL.
  • pushState does not fire popstate; only Back/Forward do.
  • App state (cart, form input) survives navigation.
  • First load is heavier; later navigation is faster.
  • Needs server-side index.html fallback for deep links.
  • SEO needs extra work (SSR or prerendering) for public pages.
  • Routing is a library feature (React Router), not part of React.

D. Interview Questions

Basic

What does "single page" really mean?

One HTML document is downloaded; the app can still have many URLs and screens.

Intermediate

Difference between pushState and replaceState?

pushState adds a new history entry (Back returns to the old URL). replaceState overwrites the current entry (no new Back step), useful for redirects.

Advanced

What accessibility work does an SPA need on navigation?

Move focus to the new main heading or content, update document.title, and announce the change, because screen readers do not get a new-page event.

Tricky

Does an SPA never talk to the server after load?

False. It still calls APIs for data and may lazy-load more JavaScript chunks. It just does not fetch new HTML documents.

F. Debugging Questions

<nav>
  <a href="/cart">Cart</a>   {/* inside a React Router app */}
</nav>
// Bug report: "cart empties every time I open Cart"
Fix

The plain anchor causes a full reload, wiping in-memory state. Use <Link to="/cart">.

G. Scenario-Based Questions

Users share a link to /movies/42; it works on your laptop but gives 404 on the live site. Why?

The Vite dev server has a built-in fallback; the production host does not. Add a rewrite rule sending all app paths to index.html.

A music app must keep playing while users browse. SPA or MPA?

SPA (or an app shell): the page never unloads, so the audio element keeps playing.

H. Coding Challenges

Write a usePath() hook that returns [path, navigate].

Solution 
import { useEffect, useState } from "react";

export function usePath() {
  const [path, setPath] = useState(window.location.pathname);
  useEffect(() => {
    const onPop = () => setPath(window.location.pathname);
    window.addEventListener("popstate", onPop);
    return () => window.removeEventListener("popstate", onPop);
  }, []);
  const navigate = (to) => {
    window.history.pushState({}, "", to);
    setPath(to);
  };
  return [path, navigate];
}
