Multi Page Applications

1. Visual Introduction

An MPA is a shopping mall: every shop is a separate room (page). Walking to a new shop means leaving the old one. An SPA is one big room where the shelves change.

  MULTI PAGE APP (MPA)                 SINGLE PAGE APP (SPA)
  --------------------                 ---------------------
  click "Movies"                       click "Movies"
     |                                    |
     v                                    v
  GET /movies   -> full HTML           JS changes URL (pushState)
     |                                    |
  page unloads, screen redraws         fetch('/api/movies') -> JSON
     |                                    |
  click "Cart"                         React swaps <Movies /> in place
     |
     v
  GET /cart     -> full HTML           one document, many views
  (another full page)                  state stays in memory

2. Why Do We Need It?

  • Not every site needs a JavaScript app. Blogs, news, docs, and shop product pages are mostly reading.
  • Search engines and link previews read finished HTML best.
  • An MPA works even with JavaScript slow or off, and each page starts fast.
Wrong
<!-- Recipe blog built as a pure SPA -->
<body>
  <div id="root"></div>
  <script type="module" src="/bundle.js"></script>
</body>
<!-- crawler / chat link preview may see an empty page
     until all JS downloads and runs -->
Fixed
<!-- Recipe blog as an MPA: HTML is complete -->
<body>
  <h1>Masala Dosa Recipe</h1>
  <p>Soak rice and urad dal for 6 hours...</p>
  <a href="/recipes/idli">Next: Idli</a>
</body>
<!-- readable instantly, by people and bots -->

3. Core Concept

  • Every URL is its own HTML document, built on the server or stored as a static file (static site).
  • Clicking a link makes the browser throw away the page and load a new one (full page load).
  • JavaScript memory is reset on every page; shared data must live on the server, in cookies, or in localStorage.
  • SEO (search ranking): strong by default, because every page arrives as finished HTML with its own title and meta tags.
  • Speed: fast first view per page; each navigation pays a full reload (browser cache helps for CSS/JS).
  • Complexity: simple client; no client router, no global client state.
  • React can still be used in an MPA: mount small React widgets (islands) on server-made pages.
  • Modern frameworks blend both: server HTML first, then SPA-style navigation (framework feature).

4. Syntax

MPA navigation is just HTML

<!-- /index.html -->
<a href="/cart.html">Go to cart</a>   <!-- browser loads a new document -->

<!-- /cart.html -->
<a href="/index.html">Back to menu</a>

Carry data between pages

// page 1: save
localStorage.setItem("cart", JSON.stringify(["Pizza"]));

// page 2: read (memory from page 1 is gone)
const cart = JSON.parse(localStorage.getItem("cart") ?? "[]");

A React island on an MPA page

import { createRoot } from "react-dom/client";
import CartBadge from "./CartBadge.jsx";

// mount React only inside one box on a server-made page
createRoot(document.getElementById("cart-badge")).render(<CartBadge />);

5. Practical Example

The same pizza shop built two ways. First as an MPA (two plain HTML files), then as a React SPA in a Vite app.

MPA version: index.html

<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Menu · PizzaPoint</title></head>
<body>
  <h1>Menu</h1>
  <p>Margherita - Rs 249 <button id="add">Add</button></p>
  <p>Cart items: <span id="count">0</span></p>
  <a href="cart.html">View cart</a>
  <script>
    const read = () => JSON.parse(localStorage.getItem("cart") ?? "[]");
    const count = document.getElementById("count");
    count.textContent = read().length;
    document.getElementById("add").onclick = () => {
      const cart = [...read(), "Margherita"];
      localStorage.setItem("cart", JSON.stringify(cart));
      count.textContent = cart.length;
    };
  </script>
</body>
</html>

MPA version: cart.html

<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Cart · PizzaPoint</title></head>
<body>
  <h1>Cart</h1>
  <ul id="list"></ul>
  <a href="index.html">Back to menu</a>
  <script>
    const cart = JSON.parse(localStorage.getItem("cart") ?? "[]");
    document.getElementById("list").innerHTML =
      cart.map((p) => "<li>" + p + "</li>").join("") || "<li>Empty</li>";
  </script>
</body>
</html>

SPA version: src/App.jsx (Vite + React)

// src/App.jsx
import { useState } from "react";

function Menu({ onAdd, count, onOpenCart }) {
  return (
    <section>
      <h1>Menu</h1>
      <p>Margherita - Rs 249 <button onClick={onAdd}>Add</button></p>
      <p>Cart items: {count}</p>
      <button onClick={onOpenCart}>View cart</button>
    </section>
  );
}

function Cart({ items, onBack }) {
  return (
    <section>
      <h1>Cart</h1>
      <ul>
        {items.length ? items.map((p, i) => <li key={i}>{p}</li>) : <li>Empty</li>}
      </ul>
      <button onClick={onBack}>Back to menu</button>
    </section>
  );
}

export default function App() {
  const [view, setView] = useState("menu");
  const [cart, setCart] = useState([]); // lives in memory, no storage needed

  return view === "menu" ? (
    <Menu
      count={cart.length}
      onAdd={() => setCart([...cart, "Margherita"])}
      onOpenCart={() => setView("cart")}
    />
  ) : (
    <Cart items={cart} onBack={() => setView("menu")} />
  );
}
The SPA version here swaps views with state only (no URL change) to keep the comparison small. Lesson INTRO-009 shows URL-based switching.

7. Execution Flow

 MPA
 1. GET /index.html        -> server sends full HTML
 2. Browser paints Menu    -> inline script reads localStorage
 3. Click "Add"            -> localStorage = ["Margherita"]
 4. Click "View cart"
        |
        v
    index page UNLOADS (JS variables destroyed)
        |
        v
 5. GET /cart.html         -> new HTML, new script
 6. Script reads localStorage -> renders the list

 SPA
 1. GET /                  -> index.html + JS bundle
 2. createRoot().render(<App />) -> Menu
 3. Click "Add"            -> setCart -> re-render
 4. Click "View cart"      -> setView("cart") -> <Cart /> (no request)

9. Common Mistakes

Mistake 1: Expecting JS variables to survive an MPA page change

Wrong
// index.html
window.cart = ["Pizza"];
// cart.html
console.log(window.cart); // undefined - new page, new memory
Fixed
// index.html
localStorage.setItem("cart", JSON.stringify(["Pizza"]));
// cart.html
JSON.parse(localStorage.getItem("cart") ?? "[]"); // ["Pizza"]

Mistake 2: "SPA is always faster"

Wrong
// one-page landing site shipped as a 400 KB SPA bundle
// user waits for JS before seeing a single word
Fixed
// static HTML page + one small React island where needed
createRoot(document.getElementById("newsletter"))
  .render(<NewsletterForm />);

Mistake 3: Same title on every page

Wrong
<title>PizzaPoint</title>   <!-- on menu.html AND cart.html -->
Fixed
<title>Menu · PizzaPoint</title>  <!-- menu.html -->
<title>Cart · PizzaPoint</title>  <!-- cart.html -->

10. Practice

Beginner 1

Which of these is an MPA navigation: (a) <a href="/about.html"> (b) history.pushState({}, "", "/about")?

Solution

(a). The browser requests and loads a new document. (b) only changes the URL inside an SPA.

Beginner 2

Add a "Clear cart" button to cart.html.

Solution 
<button id="clear">Clear cart</button>
<script>
  document.getElementById("clear").onclick = () => {
    localStorage.removeItem("cart");
    location.reload(); // reload this page to redraw
  };
</script>

Intermediate 1

Make the React SPA cart survive a refresh, like the MPA one.

Solution 
import { useEffect, useState } from "react";

const [cart, setCart] = useState(
  () => JSON.parse(localStorage.getItem("cart") ?? "[]")
);
useEffect(() => {
  localStorage.setItem("cart", JSON.stringify(cart));
}, [cart]);

Intermediate 2

A movie review site has 50,000 movie pages and must rank on search engines. Pick MPA, pure SPA, or SSR framework and justify in 2 bullets.

Solution
  • MPA or SSR framework: every movie URL arrives as full HTML with its own title/description.
  • A pure SPA would send an empty shell; some crawlers and link previews will not run the JS.

Challenge

Build a CartBadge React island that reads the cart from localStorage and updates when another tab changes it.

Solution 
// CartBadge.jsx
import { useEffect, useState } from "react";

const read = () => JSON.parse(localStorage.getItem("cart") ?? "[]").length;

export default function CartBadge() {
  const [count, setCount] = useState(read);
  useEffect(() => {
    // "storage" fires in OTHER tabs when localStorage changes
    const onStorage = (e) => { if (e.key === "cart") setCount(read()); };
    window.addEventListener("storage", onStorage);
    return () => window.removeEventListener("storage", onStorage);
  }, []);
  return <span>Cart ({count})</span>;
}

11. Quick Revision

  • MPA = one HTML document per URL; each click = full page load.
  • SEO: MPA strong by default; pure SPA needs SSR or prerendering.
  • Speed: MPA fast first view; SPA faster later navigation.
  • Complexity: MPA simpler client; SPA needs router and client state.
  • MPA pages share data via server, cookies or localStorage.
  • React fits both: full SPA, or islands inside MPA pages.

12. Interview Corner

Q1. What is a Multi Page Application?

A site where each URL returns a separate HTML document and every navigation triggers a full page load.

Q2. Why are MPAs better for SEO by default?

Crawlers receive complete HTML with unique titles and meta tags without needing to run JavaScript.

Q3. When would you choose an SPA over an MPA?

For app-like products with long sessions and rich interaction: chat, email, editors, dashboards behind login.

Q4. Can you use React in an MPA?

Yes. Mount React with createRoot into specific elements on each page (islands), or use a framework that renders pages on the server.

C. Must-Know Points

  • Each URL = its own document; browser does a full load.
  • Back/Forward may restore pages instantly from the browser's back-forward cache.
  • JS state does not survive page changes.
  • Strong SEO and link previews out of the box.
  • Less JavaScript sent = better on slow phones.
  • Every navigation re-renders header/footer.
  • No client-side router needed.
  • Hybrid (SSR frameworks) gives server HTML plus SPA navigation.

D. Interview Questions

Basic

Name two MPA examples.

A news site and a documentation site: each article is its own HTML page.

Intermediate

How do MPA pages keep a logged-in user?

The server sets a session cookie; the browser sends it with each page request.

Advanced

What are "islands" in an MPA?

Mostly static server HTML with small, independent interactive components mounted only where needed, so most of the page ships no JS.

Tricky

"MPA means no JavaScript." True?

False. MPAs can use plenty of JS per page; the difference is how navigation works, not whether JS exists.

F. Debugging Questions

<!-- cart.html -->
<script>
  document.getElementById("list").textContent = "loaded";
</script>
<ul id="list"></ul>
// Error: Cannot set properties of null
Fix

The script runs before <ul> exists. Move the script below the element, or use <script defer src="...">.

H. Coding Challenges

Write a helper cartStore with get(), add(item), clear() that any MPA page can use.

Solution 
export const cartStore = {
  get: () => JSON.parse(localStorage.getItem("cart") ?? "[]"),
  add(item) {
    localStorage.setItem("cart", JSON.stringify([...this.get(), item]));
  },
  clear: () => localStorage.removeItem("cart"),
};
