React ecosystem overview

1. Visual Introduction

  • React itself is just the engine of a car: it turns data into UI.
  • The ecosystem is everything else you bolt on: GPS (routing), fuel line (data fetching), dashboard memory (state), paint (styling), crash tests (testing), and the factory that builds the whole car (frameworks).

React is a library (library), not a full framework. It only renders UI. You pick the other parts — or let a framework pick them for you.

2. Why Do We Need It?

  • A real app needs more than components: several pages, server data, shared state, styles, tests.
  • Building each piece yourself = more bugs, more code, re-inventing solved problems.
  • Knowing the “map” tells you which tool solves which problem — and which one you do not need yet.
Wrong
// DIY "router" + DIY fetching
const [page, setPage] = useState('home');
const [menu, setMenu] = useState(null);
const [loading, setLoading] = useState(true);
useEffect(() => {
  fetch('/api/menu')
    .then((r) => r.json())
    .then((d) => { setMenu(d); setLoading(false); });
}, []);
// no URLs, no back button, no caching,
// no retry, no error state, refetch on every mount
Fixed
// Routing: real URLs + back button
<Route path="/menu" element={<Menu />} />

// Data: caching, loading, errors, retries
const { data, isPending, error } = useQuery({
  queryKey: ['menu'],
  queryFn: fetchMenu,
});

3. Core Concept

  • Build tool (bundler / dev server): Vite — fast dev server, production build. Create React App is deprecated (Feb 2025); don’t use it.
  • Routing (client-side routing): map URLs to components. React Router 7 (package react-router), TanStack Router.
  • Server data (server-state / data fetching): load, cache, refetch API data. TanStack Query, SWR, RTK Query. React 19 also has use() + Suspense.
  • App state (client state): data that lives only in the browser. Start with useState, useReducer, Context; add Zustand or Redux Toolkit when it grows.
  • Forms: React 19 form Actions + useActionState; libraries like React Hook Form; validation with Zod.
  • Styling: plain CSS, CSS Modules (built into Vite), Tailwind CSS, component kits (MUI, Chakra, shadcn/ui on Radix).
  • Testing: Vitest (test runner), React Testing Library (component tests), Playwright (end-to-end, E2E).
  • Frameworks (meta-frameworks): React Router 7 framework mode, Next.js — add SSR/SSG, file routing, data loading. Expo / React Native for mobile.
  • Tooling: ESLint (with eslint-plugin-react-hooks), TypeScript, React DevTools, React Compiler (automatic memoization).

5. Practical Example

A tiny food-delivery app using three ecosystem pieces: React Router (pages), TanStack Query (menu data), Zustand (cart). The “API” is a fake async function so it runs offline.

src/App.jsx

import { BrowserRouter, Routes, Route, Link } from 'react-router';
import {
  QueryClient,
  QueryClientProvider,
  useQuery,
} from '@tanstack/react-query';
import { create } from 'zustand';

// ---------- fake API (pretend this is fetch('/api/menu')) ----------
function fetchMenu() {
  return new Promise((resolve) =>
    setTimeout(
      () =>
        resolve([
          { id: 1, name: 'Margherita Pizza', price: 249 },
          { id: 2, name: 'Masala Dosa', price: 120 },
          { id: 3, name: 'Veg Burger', price: 149 },
        ]),
      800
    )
  );
}

// ---------- client state: the cart (Zustand) ----------
const useCart = create((set) => ({
  items: [],
  add: (dish) => set((s) => ({ items: [...s.items, dish] })),
  clear: () => set({ items: [] }),
}));

// ---------- server state: the menu (TanStack Query) ----------
function Menu() {
  const { data, isPending, error } = useQuery({
    queryKey: ['menu'],
    queryFn: fetchMenu,
  });
  const add = useCart((s) => s.add);

  if (isPending) return <p>Loading menu…</p>;
  if (error) return <p>Could not load menu.</p>;

  return (
    <ul>
      {data.map((dish) => (
        <li key={dish.id}>
          {dish.name} – ₹{dish.price}{' '}
          <button onClick={() => add(dish)}>Add</button>
        </li>
      ))}
    </ul>
  );
}

function Cart() {
  const items = useCart((s) => s.items);
  const clear = useCart((s) => s.clear);
  const total = items.reduce((sum, d) => sum + d.price, 0);

  return (
    <section>
      <p>{items.length} item(s) · Total ₹{total}</p>
      <button onClick={clear} disabled={items.length === 0}>
        Clear cart
      </button>
    </section>
  );
}

function Home() {
  return <p>Hungry? Open the menu and add something tasty.</p>;
}

// ---------- app shell: providers + routes ----------
const queryClient = new QueryClient();

export default function App() {
  const count = useCart((s) => s.items.length);

  return (
    <QueryClientProvider client={queryClient}>
      <BrowserRouter>
        <nav>
          <Link to="/">Home</Link> | <Link to="/menu">Menu</Link> |{' '}
          <Link to="/cart">Cart ({count})</Link>
        </nav>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/menu" element={<Menu />} />
          <Route path="/cart" element={<Cart />} />
        </Routes>
      </BrowserRouter>
    </QueryClientProvider>
  );
}

src/main.jsx (unchanged from the Vite template)

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Loading menu…

After loading, and after clicking “Add” on Pizza and Dosa:

  • Margherita Pizza – ₹249
  • Masala Dosa – ₹120
  • Veg Burger – ₹149

At /cart:

Go back to /menu: the list appears instantly, no “Loading…”. TanStack Query served it from its cache (and refetches quietly in the background when the data is considered stale).

7. Execution Flow

 user opens /menu
     │
 BrowserRouter reads URL "/menu"
     │
 Routes picks <Menu />
     │
 useQuery(['menu']) → cache empty → calls fetchMenu()
     │                              returns isPending = true
 Menu renders "Loading menu…"
     │
  … 800 ms …  fetchMenu resolves
     │
 Query cache stores data → Menu re-renders → list of dishes
     │
 click "Add" on Pizza
     │
 Zustand add(dish) → store.items = [pizza]
     │
 components subscribed to that slice re-render:
   App reads items.length → nav shows "Cart (1)"
     │
 click Link "Cart"
     │
 URL → /cart (no page reload) → Routes picks <Cart />
     │
 Cart reads items from Zustand → "1 item(s) · Total ₹249"

9. Common Mistakes

Mistake 1: Starting a new project with Create React App

Wrong
npx create-react-app my-shop
# deprecated since Feb 2025, unmaintained
Fixed
npm create vite@latest my-shop -- --template react
# or a framework, e.g.:
npx create-react-router@latest my-shop

Mistake 2: Putting server data into a global store by hand

Wrong
// re-implementing caching, loading and refetch
const useStore = create((set) => ({
  movies: [], loading: false,
  load: async () => {
    set({ loading: true });
    const res = await fetch('/api/movies');
    set({ movies: await res.json(), loading: false });
  },
}));
Fixed
// server data belongs in a data library
const { data: movies, isPending } = useQuery({
  queryKey: ['movies'],
  queryFn: () => fetch('/api/movies').then((r) => r.json()),
});

Mistake 3: Mixing old React Router imports

Wrong
// v5 API — Switch does not exist in v6/v7
import { Switch, Route } from 'react-router-dom';
<Switch><Route path="/" component={Home} /></Switch>
Fixed
// v7: import from 'react-router'
import { Routes, Route } from 'react-router';
<Routes><Route path="/" element={<Home />} /></Routes>

Mistake 4: Forgetting the provider

Wrong
// Error: No QueryClient set,
// use QueryClientProvider to set one
export default function App() {
  return <Menu />;   // Menu calls useQuery
}
Fixed
const queryClient = new QueryClient();
export default function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <Menu />
    </QueryClientProvider>
  );
}

Beginner 1

Match each need to a category: (a) “/movies/42” shows one movie, (b) unit-test a button, (c) load weather from an API with caching.

Solution
  • (a) Routing — React Router.
  • (b) Testing — Vitest + React Testing Library.

Beginner 2

Which of these ships with React itself: useState, Link, useQuery, createRoot?

Solution

useState (package react) and createRoot (package react-dom/client). Link is React Router; useQuery is TanStack Query.

Intermediate 1

Add a /dish/:id route to the example that shows one dish name using useParams.

Solution 
import { useParams } from 'react-router';

function Dish() {
  const { id } = useParams();
  const { data } = useQuery({ queryKey: ['menu'], queryFn: fetchMenu });
  const dish = data?.find((d) => d.id === Number(id));
  return <p>{dish ? dish.name : 'Loading…'}</p>;
}

// inside <Routes>
<Route path="/dish/:id" element={<Dish />} />

Both components share the ['menu'] key, so the second one reuses the cache.

Intermediate 2

Write a Vitest + React Testing Library test that checks Home shows the word “Hungry”.

Solution

import { render, screen } from '@testing-library/react';
import { test, expect } from 'vitest';
import Home from './Home.jsx';

test('shows greeting', () => {
  render(<Home />);
  expect(screen.getByText(/hungry/i)).toBeTruthy();

Challenge

Pick a stack for a movie-ticket site: public film pages (SEO), seat picker (lots of UI state), logged-in booking history, mobile app later.

Solution
  • Framework with pre-rendering/SSR for film pages: React Router 7 framework mode or Next.js.
  • Seat picker state: useReducer locally; Zustand if many components share it.

  • Mobile later: Expo / React Native, sharing business logic and API code.

11. Quick Revision

  • React = UI library only; ecosystem fills the gaps.
  • Build: Vite. Never Create React App for new projects.
  • Routing: React Router 7 (react-router package).
  • Server data: TanStack Query / SWR. Client state: useState → Context → Zustand/Redux Toolkit.
  • Styling: CSS Modules (built-in), Tailwind, component kits.
  • Testing: Vitest + React Testing Library + Playwright.
  • Frameworks (React Router 7 framework mode, Next.js) add SSR/SSG and file-based routing.

12. Interview Corner

Q1. Is React a framework or a library?

A library for building UI. Frameworks like Next.js or React Router 7 framework mode are built on top of it.

Q2. Server state vs client state?

Server state lives on a backend and can go stale (menu, orders) — use a data library. Client state lives only in the browser (modal open, form input, cart before checkout).

Q3. Why is Create React App not recommended?

It was officially deprecated in February 2025 — no active maintenance. The React docs recommend a framework, or a build tool like Vite for a plain SPA.

Q4. When would you add Redux Toolkit or Zustand?

When many distant components share and update the same client state and Context causes too many re-renders or too much prop wiring.

Q5. What does React Router 7 framework mode add over declarative mode?

Route modules with loader/action, type-safe route config, code splitting, and SSR/pre-rendering via its Vite plugin.

C. Must-Know Points

  1. React = library; you choose routing, data, styling.
  2. Vite is the default build tool for SPAs; CRA is deprecated (Feb 2025).
  3. React Router 7 imports from react-router (react-router-dom still works as a re-export).
  4. React Router 7 has declarative, data, and framework modes.
  5. TanStack Query v5 uses a single object: useQuery({ queryKey, queryFn }).
  6. Most libraries need a Provider near the root.
  7. Start with built-in hooks; add state libraries only when needed.
  8. CSS Modules work in Vite with zero config (*.module.css).
  9. Server Components / Server Functions are framework-only features.

D. Interview Questions

Basic

Name a routing library for React.

React Router (v7) or TanStack Router.

What is Vite?

A build tool: fast dev server with hot module replacement (HMR) and an optimised production build.

Intermediate

Why use TanStack Query instead of useEffect + fetch?

It handles caching, deduping, background refetch, retries, loading/error state and race conditions for you.

Context vs Zustand?

Context passes a value down; every consumer re-renders when it changes. Zustand lets components subscribe to a slice, so only those using that slice re-render.

Advanced

What is the React Compiler?

A build-time tool (stable v1.0, 2025) that automatically memoizes components and values, reducing the need for manual useMemo/useCallback/memo.

When choose a framework over Vite SPA?

When you need SEO, SSR/SSG, server data loading close to routes, or Server Components.

Tricky

Is Redux required to use React?

No. Many apps never need it; built-in hooks plus a data library cover most cases.

Can React Router do SSR?

Yes — in framework mode (React Router 7, successor to Remix). Declarative mode is client-only.

F. Debugging Questions

“useNavigate() may be used only in the context of a <Router> component.”

The component is rendered outside <BrowserRouter>. Wrap the app (or the test) in a router, e.g. <MemoryRouter> in tests.

Two components use useQuery for the same data but fetch twice.

Different queryKeys (e.g. ['menu'] vs ['Menu']). Use the same key to share the cache.

Clicking a link reloads the whole page.

Using <a href> instead of <Link to>. Link changes the URL without a full reload.

G. Scenario-Based Questions

A weekend todo app for yourself.

Vite + useState + plain CSS. No routing or state library needed.

An online grocery shop needing Google ranking for product pages.

A framework with SSR/SSG (React Router 7 framework mode or Next.js), TanStack Query or loaders for data, Tailwind for styling.

A team keeps breaking the checkout flow.

Add Playwright end-to-end tests for checkout, and Testing Library tests for key components; run them in CI.

H. Coding Challenges

Create a Zustand store for a movie watchlist with add, remove, and a component that shows the count.

Solution 
import { create } from 'zustand';

const useWatchlist = create((set) => ({
  movies: [],
  add: (m) => set((s) => ({ movies: [...s.movies, m] })),
  remove: (id) => set((s) => ({ movies: s.movies.filter((m) => m.id !== id) })),
}));

export function WatchCount() {
  const count = useWatchlist((s) => s.movies.length);
  return <span>Watchlist: {count}</span>;
}
