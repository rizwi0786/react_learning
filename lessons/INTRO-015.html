Understanding React architecture

1. Visual Introduction

Think of a restaurant:

  • Components (components) = recipes. They describe the dish; they don’t cook it.
  • react package = the recipe language: how to write recipes (elements, hooks).
  • Reconciler (reconciler) = the head chef. Compares today’s order with what is already on the table and decides what to change.
  • react-dom (renderer) = the waiter who actually puts plates on the table (the browser DOM).
  • Swap the waiter and the same recipes can be served elsewhere: React Native puts them on a phone screen.
  YOUR CODE          function App() { return <Cart /> }
     │  components return elements (plain objects)
     ▼
 ┌──────────────────────────────────────────────┐
 │ react          createElement / jsx, hooks,  │  ← renderer-agnostic
 │                Component types, memo, lazy   │
 └──────────────────────┬───────────────────────┘
                        │ hooks are forwarded to the active renderer
 ┌──────────────────────┴───────────────────────┐
 │ react-dom  (a renderer)                      │
 │  ┌────────────────────────────────────────┐  │
 │  │ RECONCILER (Fiber)                     │  │
 │  │  render phase: call components, diff   │  │
 │  │  commit phase: apply changes           │  │

2. Why Do We Need It?

  • Knowing the layers explains confusing errors: “Invalid hook call”, double logs in Strict Mode, stale DOM.
  • It explains why components must be pure (pure functions) — React may call them more than once before committing.
  • It explains why react and react-dom versions must match.
Wrong
// Mental model: "my component edits the page"
function Counter() {
  const [n, setN] = useState(0);
  // touching the DOM during render
  document.title = 'Count ' + n;
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
Fixed
// Correct model: render describes, commit applies,
// effects run after commit
function Counter() {
  const [n, setN] = useState(0);
  useEffect(() => {
    document.title = 'Count ' + n;
  }, [n]);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}

3. Core Concept

  • Component (function component): a function that returns elements. No DOM work inside.
  • Element (React element): a small, immutable object like { type: 'h1', props: { children: 'Hi' } }. Cheap to create.
  • react: defines elements, hooks (useState, useEffect…), memo, lazy, Suspense. Knows nothing about the DOM.
  • react-dom: the DOM renderer. Entry points: react-dom/client (createRoot, hydrateRoot), react-dom/server, react-dom/static.
  • Reconciler (reconciliation): compares the new element tree to the previous one and works out the minimum changes. Lives inside each renderer.
  • Fiber (Fiber tree): React’s internal tree — one “fiber” node per component/element, holding state, hooks, and pending work.
  • Render phase: React calls your components and diffs. Can be paused, restarted or thrown away. Must be pure.
  • Commit phase: React applies DOM changes in one go, then runs useLayoutEffect, then (after paint, usually) useEffect.
  • Scheduler (scheduling): gives urgent updates (typing, clicks) priority over slower ones (transitions).

5. Practical Example

A weather card that logs every architectural step, so you can watch render → commit → effects in the console.

src/App.jsx

import { useState, useEffect, useLayoutEffect } from 'react';

function TempLabel({ city, celsius }) {
  console.log(`  render TempLabel (${city})`);
  return (
    <p>
      {city}: {celsius}°C
    </p>
  );
}

export default function App() {
  const [celsius, setCelsius] = useState(24);
  console.log(`render App (celsius=${celsius})`);

  // 1) element = plain object describing UI
  const element = <TempLabel city="Pune" celsius={celsius} />;
  console.log('  element.type is TempLabel?', element.type === TempLabel);
  console.log('  element.props', element.props);

  // 2) runs after DOM is updated, before the browser paints
  useLayoutEffect(() => {
    console.log(`layout effect: DOM shows ${celsius}°C`);
  }, [celsius]);

  // 3) runs after commit (usually after paint)
  useEffect(() => {
    console.log(`effect: celsius=${celsius}`);
  }, [celsius]);

  return (
    <main>
      <h1>Weather</h1>
      {element}
      <button onClick={() => setCelsius((c) => c + 1)}>Warmer +1°</button>
    </main>
  );
}

src/main.jsx

import { createRoot } from 'react-dom/client';
import App from './App.jsx';

// StrictMode removed on purpose so the log is not doubled.
// Put it back afterwards — see the note in Expected Output.
createRoot(document.getElementById('root')).render(<App />);

7. Execution Flow

 createRoot(#root).render(<App/>)
        │
 ── RENDER PHASE (pure, may be interrupted) ──────────────
        │
 reconciler creates fiber for App → calls App()
        │   useState → 24  (hook state stored on App's fiber)
        │   returns elements: main > h1, TempLabel, button
        │
 reconciler visits TempLabel fiber → calls TempLabel()
        │   returns: p "Pune: 24°C"
        │
 builds list of changes ("effects list"):
   create main, h1, p, button; set text; attach onClick
        │
 ── COMMIT PHASE (synchronous, cannot be interrupted) ────
        │
 react-dom host config → document.createElement(...),
   appendChild(...) into #root
        │
 run useLayoutEffect callbacks   → "layout effect: 24°C"
        │
 browser paints pixels
        │
 run useEffect callbacks         → "effect: celsius=24"

 ── CLICK "Warmer" ───────────────────────────────────────
 setCelsius(c => c + 1)  → scheduler queues a high-priority update
        │
 RENDER: App() again → new elements; TempLabel() again
 DIFF:   h1 same → skip; p text "24" → "25"; button same → skip
        │
 COMMIT: update ONE text node; run layout effect; paint; effect

8. Real-World Application

  • Same components, different screens: a food-delivery company shares hooks and logic between a web app (react-dom) and a phone app (React Native renderer).
  • Snappy search box: typing in a movie search is urgent; filtering 5,000 movies is wrapped in startTransition so the scheduler can interrupt it.
  • Measuring layout: a chat app scrolls to the newest message in useLayoutEffect (DOM is updated but not yet painted → no flicker).
  • Server rendering: the same reconciler logic produces HTML strings via react-dom/server for SSR/SSG.
  • Custom renderers: libraries build on the react-reconciler package to render React to canvas, 3D scenes (react-three-fiber), terminals (Ink) or PDFs.

9. Common Mistakes

Mistake 1: Side effects in the render phase

Wrong
function OrderBadge({ count }) {
  // render may run more than once (Strict Mode,
  // interrupted renders) → duplicate sends
  fetch('/api/log?count=' + count);
  return <span>{count}</span>;
}
Fixed
function OrderBadge({ count }) {
  useEffect(() => {
    fetch('/api/log?count=' + count);
  }, [count]);
  return <span>{count}</span>;
}

Mistake 2: Mismatched or duplicate React copies

Wrong
// package.json
"react": "^18.3.1",
"react-dom": "^19.2.0"
// → errors / "Invalid hook call":
// hooks from one copy of react, renderer
// expects another
Fixed
// package.json — same version, one copy
"react": "^19.2.0",
"react-dom": "^19.2.0"

// check for duplicates:
// npm ls react

Mistake 3: Using the removed legacy render API

Wrong
import ReactDOM from 'react-dom';
// removed in React 19
ReactDOM.render(<App />, document.getElementById('root'));
Fixed
import { createRoot } from 'react-dom/client';
createRoot(document.getElementById('root')).render(<App />);

Mistake 4: Calling a component like a normal function

Wrong
// TempLabel gets no fiber of its own;
// its hooks attach to the PARENT → breaks
// when called conditionally
return <main>{TempLabel({ city: 'Pune', celsius })}</main>;
Fixed
// let React call it → own fiber, own state
return <main><TempLabel city="Pune" celsius={celsius} /></main>;

10. Practice

Beginner 1

Which package does each come from: useState, createRoot, hydrateRoot, Suspense?

Solution

useState, Suspense → react. createRoot, hydrateRoot → react-dom/client.

Beginner 2

Put in order: browser paints, useEffect runs, component function runs, DOM is updated, useLayoutEffect runs.

Solution
  1. Component function runs (render)
  2. DOM is updated (commit)
  3. useLayoutEffect runs
  4. Browser paints
  5. useEffect runs

(useEffect usually runs after paint; for updates caused by a click React may flush it earlier, but always after commit.)

Intermediate 1

Log a JSX element and describe its shape: console.log(<li key="1" className="dish">Dosa</li>).

Solution 
{ $$typeof: Symbol(react.transitional.element),
  type: 'li',
  key: '1',
  props: { className: 'dish', children: 'Dosa' },
  ... (dev-only fields such as _owner, _store) }

key is kept outside props. It is just data — nothing on screen yet.

Intermediate 2

In the example, click “Warmer” 3 times. How many DOM nodes does React change per click?

Solution

One: the text inside <p>. The h1, button and main elements are equal to last time, so the reconciler skips them (though the component functions still run).

Challenge

Prove render and commit are separate: show that a component can render without its effect running yet. Hint: log inside the body and inside useEffect, and use startTransition with a slow list.

Solution 
import { useState, useEffect, startTransition } from 'react';

function SlowList({ query }) {
  console.log('render SlowList', query);
  const start = performance.now();
  while (performance.now() - start < 200) {} // fake slow render
  useEffect(() => console.log('commit+effect SlowList', query));
  return <p>Results for "{query}"</p>;
}

export default function App() {
  const [text, setText] = useState('');
  const [query, setQuery] = useState('');
  return (
    <>
      <input
        value={text}
        onChange={(e) => {
          setText(e.target.value);
          startTransition(() => setQuery(e.target.value));
        }}
      />
      <SlowList query={query} />
    </>
  );
}
// Type fast: you may see "render SlowList" for a value
// whose "commit+effect" line never appears — React threw that
// render away because a newer one arrived. Exact logs vary.

11. Quick Revision

  • Components return elements (plain objects), never touch the DOM directly.
  • react = elements + hooks (no DOM). react-dom = DOM renderer.
  • The reconciler (Fiber) diffs old vs new trees and finds minimal changes.
  • Render phase is pure and may repeat; commit phase applies changes once.
  • Order: render → DOM commit → useLayoutEffect → paint → useEffect.
  • react and react-dom versions must match; one copy only.
  • Strict Mode double-renders and re-runs effects in development only.

12. Interview Corner

Q1. Why are react and react-dom separate packages?

react defines what UI is (elements, hooks) independent of platform. react-dom is one renderer for the browser; React Native is another. Splitting lets the same components target multiple platforms.

Q2. What is reconciliation?

The process of comparing the new element tree with the previous one (using element type and key) to decide which host nodes to create, update or delete.

Q3. What is Fiber?

React’s internal data structure and algorithm (since React 16). Each fiber is a unit of work for one component/element; work can be split, prioritised, paused and resumed.

Q4. Why must components be pure?

The render phase can be repeated or discarded (Strict Mode, transitions, Suspense). Side effects there would run an unpredictable number of times.

Q5. useEffect vs useLayoutEffect timing?

Both run after commit. useLayoutEffect runs synchronously before the browser paints; useEffect usually runs after paint. Prefer useEffect unless you must measure or adjust layout before paint.

A. Concept in 30 Seconds

Your components return elements (plain objects). The react package defines elements and hooks. A renderer such as react-dom contains the reconciler (Fiber), which diffs the new tree against the old in the render phase, then applies the minimum DOM changes in the commit phase, then runs effects.

B. Important Syntax

import { useState, useEffect, useLayoutEffect } from 'react';   // core
import { createRoot, hydrateRoot } from 'react-dom/client';       // browser
import { renderToPipeableStream } from 'react-dom/server';       // SSR
import { prerender } from 'react-dom/static';                    // SSG

const root = createRoot(document.getElementById('root'));
root.render(<App />);
root.unmount();

// JSX → element object
const el = <h1 className="t">Hi</h1>;
el.type;   // 'h1'
el.props;  // { className: 't', children: 'Hi' }

C. Must-Know Points

  1. react has no DOM code.
  2. react-dom is a renderer; React Native is another.
  3. Reconciler lives inside the renderer; react-reconciler lets you build custom renderers.
  4. Elements are immutable descriptions; fibers are mutable internal work nodes.
  5. Render phase: call components + diff (pure, interruptible).
  6. Commit phase: mutate DOM, run layout effects (synchronous).
  7. useEffect runs after commit, usually after paint.
  8. Diffing uses element type and key.
  9. ReactDOM.render was removed in React 19 — use createRoot.
  10. Matching versions of react and react-dom; one copy.

D. Interview Questions

Basic

What does a component return?

React elements (or strings, numbers, null, arrays of these).

Where does createRoot come from?

react-dom/client.

Intermediate

What happens if element type changes between renders (e.g. <div> → <section>)?

React destroys the old subtree (including its state) and builds a new one.

Why does a hook “know” which component it belongs to?

While rendering a component, the renderer sets the current fiber; hook calls read/write the hook list on that fiber in call order.

Advanced

What makes the render phase interruptible?

Fiber splits work into units; with concurrent features (transitions, Suspense) the scheduler can yield to the browser between units and discard stale work.

What is the “host config” in a renderer?

The platform-specific functions the reconciler calls — e.g. create instance, append child, commit update. For react-dom they wrap DOM APIs.

Tricky

Does a re-render always change the DOM?

No. If the diff finds no changes, the commit makes no DOM mutations.

Is the virtual DOM what makes React fast?

Not by itself — diffing has a cost. Its benefit is a declarative model with batched, minimal updates; speed also comes from scheduling and avoiding unnecessary work (memoization, React Compiler).

E. Output-Based Questions

function App() {
  console.log('A render');
  useLayoutEffect(() => console.log('B layout'));
  useEffect(() => console.log('C effect'));
  return <Child />;
}
function Child() {
  console.log('D render');
  useEffect(() => console.log('E effect'));
  return null;
}
// production build, first mount
Answer
A render
D render
B layout
E effect
C effect

Parents render first; effects run child-first. Layout effects all run before passive effects. In development with Strict Mode you’ll see extra repeats.

F. Debugging Questions

“Invalid hook call. Hooks can only be called inside of the body of a function component.” — but the code looks fine.

Likely two copies of React (e.g. a linked local library with its own react) or mismatched react/react-dom versions. Run npm ls react and dedupe.

“TypeError: ReactDOM.render is not a function” after upgrading.

Removed in React 19. Use createRoot(container).render(<App />).

Analytics event fires twice in dev only.

Strict Mode re-runs effects once on mount in development. Make the effect idempotent or add cleanup; production fires once.

G. Scenario-Based Questions

A tooltip flickers in the wrong position before jumping into place.

Measure and position it in useLayoutEffect so the change is applied before paint.

Your team wants the same cart logic on web and mobile.

Put the logic in custom hooks (they only use react), then render with react-dom on web and React Native on mobile.

Typing in a movie search lags because the result list is heavy.

Mark the list update as a transition (startTransition or useDeferredValue) so the scheduler keeps the input responsive.
