What is JSX?

1. Visual Introduction

  • JSX looks like HTML, but it is really JavaScript in a costume.
  • Like writing a food order in shorthand: “1× Masala Dosa, extra chutney”. The kitchen (build tool) rewrites it into the full ticket (function calls) before cooking.
  • The browser never sees JSX. Vite converts it to plain JavaScript first.
 YOU WRITE (JSX)                  BUILD TOOL (Vite)            BROWSER RUNS
 ───────────────                  ─────────────────            ────────────
 <h1 className="title">     ──►   jsx('h1', {          ──►    returns an object:
   Hello, {name}!                   className: 'title',         { type: 'h1',
 </h1>                              children: ['Hello, ',        props: {...} }
                                       name, '!']                    │
                                   })                               ▼
                                                              react-dom turns it
                                                              into a real <h1>
One-line definition: JSX (JavaScript XML) is a syntax extension that lets you write UI descriptions inside JavaScript. Each tag becomes a function call that returns a React element (a plain object).

2. Why Do We Need It?

  • Without JSX you write nested function calls by hand — hard to read for anything bigger than a button.
  • JSX keeps markup and the logic that drives it in one place (the component).
  • It is still JavaScript, so you can use variables, map, ternaries — no separate template language to learn.
Wrong
// Without JSX: correct, but hard to read
import { createElement as h } from 'react';

function MovieCard({ movie }) {
  return h('div', { className: 'card' },
    h('h2', null, movie.title),
    h('p', null, 'Rating: ', movie.rating),
    h('button', { onClick: () => alert('Booked!') }, 'Book')
  );
}
Fixed
// With JSX: same result, reads like the UI
function MovieCard({ movie }) {
  return (
    <div className="card">
      <h2>{movie.title}</h2>
      <p>Rating: {movie.rating}</p>
      <button onClick={() => alert('Booked!')}>Book</button>
    </div>
  );
}

3. Core Concept

  • JSX = JavaScript (syntax extension): not HTML, not a string, not a template.
  • Compiled away (transpiled): Vite’s React plugin turns each tag into a call to jsx() / jsxs() imported automatically from react/jsx-runtime (automatic JSX runtime). In development it uses jsxDEV from react/jsx-dev-runtime.
  • Result = element (React element): a plain object { type, props, key }. Describes UI; doesn’t draw anything.
  • Curly braces { } (JSX expression): insert any JavaScript expression — variables, maths, function calls, ternaries. Not statements (if, for).
  • Lowercase tag = HTML element (<div>); Capitalised tag = your component (<MovieCard />).
  • Attributes are props: camelCase names — className, htmlFor, onClick.
  • One root: a component returns one parent element (or a Fragment <>…</>).
  • Every tag closes: <img />, <br />, <input />.
  • Optional: React works without JSX, but almost everyone uses it.
  • File extension: in a Vite project put JSX in .jsx (or .tsx) files.

4. Syntax

Basic tag, attribute, expression

const name = 'Asha';
const greeting = <h1 className="title">Hello, {name}!</h1>;

What it compiles to (automatic runtime)

import { jsxs as _jsxs } from 'react/jsx-runtime';   // added by the compiler

const name = 'Asha';
const greeting = _jsxs('h1', {
  className: 'title',
  children: ['Hello, ', name, '!'],
});

Self-closing, fragment, comment, style

<>
  {/* this is a JSX comment */}
  <img src="/pizza.png" alt="Pizza" />
  <p style={{ color: 'tomato', fontSize: 18 }}>Hot & fresh</p>
</>

JSX is a value — store it, pass it, return it

const badge = isVeg ? <span>🟢 Veg</span> : <span>🔴 Non-veg</span>;
const items = dishes.map((d) => <li key={d.id}>{d.name}</li>);

5. Practical Example

A food-order card. Every JSX feature from this lesson, in one runnable Vite file. The comments show what each line becomes.

src/App.jsx

// No "import React" needed — the automatic runtime adds
// "import { jsx } from 'react/jsx-runtime'" for you.
import { useState } from 'react';
import './App.css';

const dishes = [
  { id: 1, name: 'Masala Dosa', price: 120, veg: true },
  { id: 2, name: 'Chicken Biryani', price: 280, veg: false },
  { id: 3, name: 'Paneer Wrap', price: 160, veg: true },
];

function DishRow({ dish, onAdd }) {
  // Capitalised tag → React calls this function
  return (
    <li className="dish">
      <span>{dish.veg ? '🟢' : '🔴'}</span>{' '}
      <b>{dish.name}</b> – ₹{dish.price}{' '}
      <button onClick={() => onAdd(dish)}>Add</button>
    </li>
  );
}

export default function App() {
  const [cart, setCart] = useState([]);
  const total = cart.reduce((sum, d) => sum + d.price, 0);

  // JSX is just a value: we can build it before returning
  const status =
    cart.length === 0 ? (
      <p className="muted">Your cart is empty.</p>
    ) : (
      <p>
        {cart.length} item(s) · Total: <b>₹{total}</b>
      </p>
    );

  return (
    <main>
      {/* expression: string + function call */}
      <h1>Order from {'Spice Corner'.toUpperCase()}</h1>

      <ul>
        {dishes.map((dish) => (
          <DishRow
            key={dish.id}
            dish={dish}
            onAdd={(d) => setCart([...cart, d])}
          />
        ))}
      </ul>

      {status}

      <label htmlFor="note">Note for the kitchen</label>
      <input id="note" placeholder="Less spicy, please" />
    </main>
  );
}

src/App.css (optional)

.dish { margin: 6px 0; }
.muted { color: gray; }

7. Execution Flow

 1. You save App.jsx
        │
 2. Vite dev server transforms the file (JSX → JS):
      <li className="dish">…</li>
        → jsxDEV('li', { className: 'dish', children: [...] })  (dev)
        → jsx / jsxs(...)                                        (prod build)
        │
 3. Browser loads the plain JS module
        │
 4. createRoot(...).render(<App />)  →  React calls App()
        │
 5. App() runs the jsx() calls → returns an element tree (objects):
      { type: 'main', props: { children: [
          { type: 'h1', ... },
          { type: 'ul', props: { children: [ {type: DishRow, key: '1'}, ... ] } },
          ... ] } }
        │
 6. React sees type DishRow (a function) → calls DishRow() for each
        │
 7. react-dom commits: creates <main>, <h1>, <li class="dish">, ...
        │
 8. Click "Add" → setCart → App() runs again → new objects
        → React diffs → updates only the status <p>

8. Real-World Application

  • Lists from data: a movie app turns an API array into cards with movies.map(m => <MovieCard key={m.id} … />).
  • Conditional UI: a weather app shows {temp > 35 ? <HeatAlert /> : null}.
  • Reusable pieces: a chat app composes <ChatWindow><MessageList /><Composer /></ChatWindow>.
  • Safe by default: values in { } are escaped, so a user typing <script> in a chat message is shown as text, not run (protects against XSS, cross-site scripting).
  • Tooling: because JSX is structured, editors and linters can catch mistakes (missing key, unclosed tags) before you run the app.

9. Common Mistakes

Mistake 1: Returning two roots

Wrong
function Header() {
  // SyntaxError: Adjacent JSX elements must be
  // wrapped in an enclosing tag
  return (
    <h1>Pizza Palace</h1>
    <p>Open till 11 pm</p>
  );
}
Fixed
function Header() {
  return (
    <>
      <h1>Pizza Palace</h1>
      <p>Open till 11 pm</p>
    </>
  );
}

Mistake 2: Using if / for inside braces

Wrong
return (
  <p>
    {if (isOpen) { 'Open' } else { 'Closed' }}
  </p>
);
// SyntaxError: braces take an expression,
// not a statement
Fixed
return <p>{isOpen ? 'Open' : 'Closed'}</p>;

// or decide before the return:
// let label = 'Closed';
// if (isOpen) label = 'Open';
// return <p>{label}</p>;

Mistake 3: HTML habits — class, unclosed tags, string styles

Wrong
<div class="card" style="color: red">
  <img src="dosa.png">
  <br>
</div>
// unclosed <img>/<br> → syntax error
// style string → runtime error
// class → works but React warns:
// "Invalid DOM property `class`. Did you mean `className`?"
Fixed
<div className="card" style={{ color: 'red' }}>
  <img src="dosa.png" alt="Masala dosa" />
  <br />
</div>

Mistake 4: Rendering an object directly

Wrong
const order = { id: 7, dish: 'Biryani' };
return <p>{order}</p>;
// Error: Objects are not valid as a React child
Fixed
const order = { id: 7, dish: 'Biryani' };
return <p>Order #{order.id}: {order.dish}</p>;

Mistake 5: Lowercase component name

Wrong
function weatherCard() { return <p>24°C</p>; }
// <weatherCard /> is treated as an unknown
// HTML tag; React warns and renders nothing useful
Fixed
function WeatherCard() { return <p>24°C</p>; }
// <WeatherCard /> → React calls the function

Solution 
import { jsx as _jsx, jsxs as _jsxs } from 'react/jsx-runtime';

_jsxs('ul', {
  children: [
    _jsx('li', { children: 'Tea' }),
    _jsx('li', { children: 'Coffee' }),

// jsxs = element with several static children; jsx = one child.

Render a weather list from [{ city: 'Delhi', temp: 31 }, { city: 'Shimla', temp: 12 }], adding “🧥” when temp is below 15.

Solution

  { city: 'Delhi', temp: 31 },
  { city: 'Shimla', temp: 12 },
];

export default function App() {
  return (
    <ul>
      {forecast.map((f) => (
        <li key={f.city}>
          {f.city}: {f.temp}°C {f.temp < 15 ? '🧥' : null}
        </li>
      ))}
    </ul>
  );
}

Challenge

Without running it, predict what this logs, then explain why key is not inside props.

const el = <li key="m1" className="movie">Inception</li>;
console.log(el.type, el.key, el.props);
Solution 
li m1 {className: 'movie', children: 'Inception'}

The compiler passes key as a separate argument: jsx('li', { className: 'movie', children: 'Inception' }, 'm1'). React uses it for reconciliation, so components never receive key as a prop.

11. Quick Revision

  • JSX = JavaScript syntax that describes UI; the browser never sees it.
  • Vite compiles tags to jsx() calls from react/jsx-runtime (no import React needed).
  • Each tag → a React element: plain object { type, props, key }.
  • { } holds expressions only — use ternaries, &&, map.
  • One root (or <>…</>), close every tag, camelCase attributes.
  • Lowercase = HTML tag; Capitalised = component.
  • { } values are escaped → safe from injected HTML by default.

12. Interview Corner

Q1. What is JSX?

A syntax extension for JavaScript that looks like HTML. It compiles to function calls (jsx() in the automatic runtime) that return React elements.

Q2. Can browsers run JSX directly?

No. A compiler (Vite’s React plugin, Babel, SWC, Oxc, TypeScript) must transform it into plain JavaScript first.

Q3. Why don’t we need import React from 'react' anymore?

Since the new JSX transform (React 17+), the compiler auto-imports jsx from react/jsx-runtime. The old classic runtime called React.createElement, which required React in scope.

Q4. Why className instead of class?

JSX attributes map to DOM properties and JavaScript names; class is a reserved word in JavaScript and the DOM property is className.

Q5. Is JSX required for React?

No. You can call createElement yourself, but JSX is far more readable and is the standard.

A. Concept in 30 Seconds

JSX is JavaScript that describes UI. You write HTML-like tags; Vite compiles each tag into a jsx() call (from react/jsx-runtime) that returns a plain object — a React element. Put JavaScript expressions in { }, close every tag, use camelCase attributes, and return one root.

B. Important Syntax

<h1 className="title">Hi {name}</h1>        // attribute + expression
<img src={url} alt="Pizza" />               // self-closing
<><A /><B /></>                             // fragment (one root)
<p style={{ color: 'red' }}>Hot</p>          // style object
{/* comment */}                              // JSX comment
{isOpen ? <Open /> : <Closed />}             // conditional
{items.map((i) => <li key={i.id}>{i.name}</li>)}  // list
<label htmlFor="q">Search</label>            // htmlFor, not for

// compiled (automatic runtime):
import { jsx } from 'react/jsx-runtime';
jsx('h1', { className: 'title', children: 'Hi' });

C. Must-Know Points

  1. JSX is not HTML and not a string — it’s JavaScript syntax.
  2. It must be compiled; browsers can’t run it.
  3. Automatic runtime: jsx/jsxs from react/jsx-runtime; dev uses jsxDEV.
  4. Every JSX expression evaluates to a React element object.
  5. { } accepts expressions, not statements.
  6. Return one root element or a Fragment.
  7. All tags must close.
  8. className, htmlFor, onClick, tabIndex — camelCase.
  9. Capitalised names are components; lowercase are HTML tags.
  10. Strings in { } are escaped automatically (XSS protection).

D. Interview Questions

Basic

What does JSX stand for?

JavaScript XML.

How do you add a comment in JSX?

{/* comment */} inside the markup.

Intermediate

Difference between jsx and jsxs?

Both create elements. jsxs is used when an element has multiple static children (an array literal written in source), so React can skip key warnings for them.

Why can’t you use if inside { }?

Braces become a value inside a function call argument; only expressions produce values. Use a ternary, &&, or compute a variable before return.

Advanced

What is the shape of a React 19 element?

{ $$typeof: Symbol.for('react.transitional.element'), type, key, props }, plus dev-only fields. In React 19 ref is read from props.

How does React tell <button> from <Button>?

The compiler emits a string 'button' for lowercase tags and a variable reference Button for capitalised ones. React renders strings as host elements and calls functions as components.

Tricky

What does <p>{0 && 'Items'}</p> render?

0. 0 && … evaluates to 0, and numbers are rendered. Use count > 0 && ….

Do true, false, null, undefined render anything?

No — they render nothing. That’s why {cond && <X />} works when cond is a boolean.

0 is rendered; arrays of numbers render each item side by side. (Literal array children have no keys; numbers/strings don’t trigger the key warning — only elements do.)

F. Debugging Questions

“[plugin:vite:...] Failed to parse source … contains invalid JS syntax” in utils.js.

JSX is inside a .js file. Vite expects JSX in .jsx/.tsx; rename the file.

“Objects are not valid as a React child (found: object with keys {city, temp})”.

You rendered an object. Render its fields ({w.city}) or map an array to elements.

“Unterminated JSX contents” pointing at the end of the file.

(Exact wording depends on the compiler.) An unclosed tag, e.g. <input> or <br>. Self-close it: <input />.

G. Scenario-Based Questions

A chat user sends <b>hi</b>. What does <p>{msg}</p> show?

The literal text <b>hi</b> — React escapes strings. Only dangerouslySetInnerHTML would parse it (avoid with user input).

You paste a large HTML snippet from a designer into a component.

Convert it: class → className, for → htmlFor, close void tags, inline styles → objects, HTML comments → {/* */}, wrap in one root.

A shop page should show “Out of stock” instead of the Buy button when stock === 0.

{stock === 0 ? <p>Out of stock</p> : <button>Buy</button>}

Write a TodoList component that shows “Nothing to do 🎉” when the list is empty, otherwise the todos with done ones struck through.

Solution 
export default function TodoList({ todos }) {
  if (todos.length === 0) return <p>Nothing to do 🎉</p>;
  return (
    <ul>
      {todos.map((t) => (
        <li
          key={t.id}
          style={{ textDecoration: t.done ? 'line-through' : 'none' }}
        >
          {t.text}
        </li>
      ))}
    </ul>
  );
}
