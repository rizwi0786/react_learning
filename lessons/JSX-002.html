Why JSX?

1. Visual Introduction

  • Think of ordering food. You can say "one margherita pizza, large, extra cheese" (JSX) — or fill a form with fields item, size, toppings (a function call).
  • Both reach the same kitchen. One is just much easier for humans to read and write.
  • JSX is the "say it naturally" version. React.createElement (create element function) is the "fill the form" version.
  What YOU write (JSX)                 What the browser runs (plain JS)
 ┌────────────────────────────┐       ┌──────────────────────────────────────┐
 │ <h1 className="title">     │       │ createElement(                       │
 │   Today's Menu             │ ────► │   "h1",                              │
 │ </h1>                      │ build │   { className: "title" },            │
 └────────────────────────────┘ tool  │   "Today's Menu"                     │
                                      │ )                                    │
                                      └──────────────────────────────────────┘
                    Same result: a React element (a plain JS object)
Browsers do not understand JSX. A build tool (compiler) turns it into normal JavaScript function calls before it runs.

2. Why Do We Need It?

  • UI is a tree (nested boxes). Writing trees as nested function calls gets messy fast.
  • JSX looks like the HTML you already know, so the shape of the UI is visible at a glance.
  • JSX is optional — but almost every React codebase uses it.
Without JSX
import { createElement as h } from 'react';

const card = h(
  'div',
  { className: 'card' },
  h('h2', null, 'Paneer Tikka'),
  h('p', null, 'Price: ₹249'),
  h(
    'button',
    { onClick: () => alert('Added!') },
    'Add to cart'
  )
);
With JSX
const card = (
  <div className="card">
    <h2>Paneer Tikka</h2>
    <p>Price: ₹249</p>
    <button onClick={() => alert('Added!')}>
      Add to cart
    </button>
  </div>
);

3. Core Concept

  • JSX (JavaScript XML) = HTML-like syntax inside JavaScript.
  • Every JSX tag becomes a function call that returns a React element (a plain object describing UI).
  • Old way: React.createElement(type, props, ...children).
  • Modern way (React 17+): the compiler calls jsx() from react/jsx-runtime (automatic runtime) — covered in JSX-004.
  • JSX is just JavaScript: you can store it in variables, return it, pass it as props, and put {expressions} inside.
  • Benefits: readable nesting, familiar look, compile-time errors for typos like unclosed tags, better editor support.
  • createElement still exists and is fully supported — JSX is sugar (syntactic sugar) on top.

4. Syntax

// createElement signature
React.createElement(type, props, ...children)
//   type     → 'div' (HTML tag as string) or MyComponent (a function)
//   props    → object of attributes, or null
//   children → text, numbers, elements, arrays...

// The same thing in JSX
<type {...props}>children</type>

// Examples side by side
React.createElement('p', null, 'Hi')          // <p>Hi</p>
React.createElement('img', { src: 'a.png', alt: 'Pizza' }) // <img src="a.png" alt="Pizza" />
React.createElement(MovieCard, { title: 'Dune' })         // <MovieCard title="Dune" />

5. Practical Example

A small weather widget written both ways in one Vite React app. Create the app with npm create vite@latest weather -- --template react, then replace src/App.jsx.

// src/App.jsx
import { createElement } from 'react';
import { useState } from 'react';

// Version A — plain createElement calls
function WeatherNoJsx({ city, temp }) {
  return createElement(
    'section',
    { className: 'weather' },
    createElement('h2', null, 'Weather in ', city),
    createElement('p', null, temp, '°C'),
    createElement('small', null, temp > 30 ? 'Hot day ☀️' : 'Pleasant 🌤️')
  );
}

// Version B — the same component in JSX
function WeatherJsx({ city, temp }) {
  return (
    <section className="weather">
      <h2>Weather in {city}</h2>
      <p>{temp}°C</p>
      <small>{temp > 30 ? 'Hot day ☀️' : 'Pleasant 🌤️'}</small>
    </section>
  );
}

export default function App() {
  const [temp, setTemp] = useState(28);

  return (
    <main>
      <h1>JSX vs createElement</h1>
      <button onClick={() => setTemp(temp + 3)}>+3°C</button>
      {/* Both render the SAME DOM */}
      <WeatherNoJsx city="Delhi" temp={temp} />
      <WeatherJsx city="Delhi" temp={temp} />
    </main>
  );
}
You can mix both styles in one app. React only sees the resulting element objects — it cannot tell which syntax made them.

7. Execution Flow

 1. You write JSX in App.jsx
        │
        ▼
 2. Vite's compiler turns each tag into a function call
    <h2>Weather in {city}</h2>  ──►  jsxs("h2", { children: ["Weather in ", city] })
        │
        ▼
 3. Browser runs plain JS → each call returns an object
    { type: "h2", props: { children: ["Weather in ", "Delhi"] }, key: null, ... }
        │
        ▼
 4. React compares the element tree with the last one (reconciliation)
        │
        ▼
 5. react-dom updates only the changed DOM nodes (the temperature text)

8. Real-World Application

  • Food delivery apps: restaurant cards, menus and cart rows are deeply nested — JSX keeps them readable.
  • Code review: teammates can "see" the layout in JSX without running it.
  • When createElement still appears: small libraries that avoid a build step, generated code, or dynamic tag choice like createElement(level, null, text) (though JSX can do this too with a capitalised variable).
  • Reading compiled output in DevTools / bundle analysis — knowing the function-call form helps you debug.

9. Common Mistakes

Mistake 1: Running JSX directly in the browser

Wrong
<!-- index.html, no build tool -->
<script>
  const el = <h1>Hello</h1>;
  // SyntaxError: Unexpected token '<'
</script>
Fixed
// Use a Vite React project:
// npm create vite@latest shop -- --template react
// src/App.jsx is compiled before the browser sees it
export default function App() {
  return <h1>Hello</h1>;
}

Mistake 2: Passing children inside props wrongly with createElement

Wrong
// Children passed as one array → React warns:
// "Each child in a list should have a unique key"
createElement('ul', null, [
  createElement('li', null, 'Milk'),
  createElement('li', null, 'Bread'),
]);
Fixed
// Pass static children as separate arguments
createElement(
  'ul',
  null,
  createElement('li', null, 'Milk'),
  createElement('li', null, 'Bread')
);

Mistake 3: Thinking JSX is HTML (it is JavaScript)

Wrong
// "It's HTML, so if/else goes inside"
return (
  <p>
    if (isOpen) { 'Open now' }
  </p>
); // renders the text literally
Fixed
// JSX children take EXPRESSIONS in { }
return (
  <p>{isOpen ? 'Open now' : 'Closed'}</p>
);

Challenge

Render a menu list: given const dishes = ['Dosa', 'Idli', 'Vada'], render a <ul> twice — once with createElement + map, once with JSX. Both need keys.

Show solution
import { createElement as h } from 'react';

const dishes = ['Dosa', 'Idli', 'Vada'];

export function MenuNoJsx() {
  return h(
    'ul',
    null,
    dishes.map((d) => h('li', { key: d }, d)) // array → needs keys
  );
}

export function MenuJsx() {
  return (
    <ul>
      {dishes.map((d) => <li key={d}>{d}</li>)}
    </ul>
  );
}

11. Quick Revision

  • JSX = HTML-like syntax that compiles to JavaScript function calls.
  • Browsers can't run JSX; Vite compiles it for you.
  • createElement(type, props, ...children) is the long-hand form.
  • Both produce the same React element objects.
  • JSX wins on readability for nested UI; it's optional, not required.
  • Inside JSX, { } holds any JavaScript expression (not statements).

12. Interview Corner

Is JSX required to write React?

No. You can call createElement directly. JSX is a convenient syntax that a compiler turns into function calls.

What does a JSX expression evaluate to?

A React element — a plain, immutable JavaScript object describing what to render (type, props, key). It is not a DOM node.

Why can't the browser read JSX?

JSX is not part of the JavaScript standard (ECMAScript). Browsers' JS engines throw a SyntaxError on < in that position, so a compiler must transform it first.

Name two advantages of JSX over createElement.

Readable nested structure that mirrors the UI, and compile-time checks (e.g. unclosed tags are a syntax error) plus richer editor tooling.

A. Concept in 30 Seconds

JSX is a friendly way to write createElement calls. <p className="x">Hi</p> becomes a function call that returns a plain object. Same result, far easier to read when UI is nested.

B. Important Syntax

import { createElement } from 'react';

createElement('button', { onClick: buy, disabled: !inStock }, 'Buy');
// ≡
<button onClick={buy} disabled={!inStock}>Buy</button>

createElement(CartItem, { name: 'Tea', qty: 2 });
// ≡
<CartItem name="Tea" qty={2} />

C. Must-Know Points

  1. JSX is syntax sugar, not a template language or HTML.
  2. Each tag → one function call → one React element (object).
  3. Lowercase tag → string type ('div'); Capitalised tag → component reference.
  4. createElement takes children as extra arguments.
  5. A null props argument means "no props".
  6. JSX needs a compiler (Vite does it automatically).
  7. { } accepts expressions only — use ternary / &&, not if.
  8. Elements are immutable descriptions; React decides how to update the DOM.

D. Interview Questions

Basic

What is JSX short for?

JavaScript XML — an XML-like syntax extension for JavaScript.

What are the three main arguments of createElement?

type, props, and any number of children.

Intermediate

Is a React element the same as a DOM element?

No. A React element is a lightweight JS object. react-dom later creates or updates real DOM nodes to match it.

Why does <myCard /> not render your component?

Lowercase tags compile to strings ('myCard'), so React treats it as an unknown HTML tag. Components must start with a capital letter.

Advanced

Is createElement deprecated in React 19?

No, it is still supported. But compilers no longer emit it by default — the automatic runtime uses jsx() from react/jsx-runtime.

Tricky

Can JSX be used without React?

Yes. JSX is just syntax; compilers can target other libraries (e.g. Preact, Solid) by changing the import source. The meaning comes from whichever function it compiles to.

E. Output-Based Questions

const el = <h1 id="t">Pizza</h1>;

Answer

F. Debugging Questions

Why does this throw "Unexpected token"?

// utils.js (plain .js file loaded by a script tag, no build step)
export const Tag = () => <span>New</span>;
Answer

JSX was never compiled. Import it from a file processed by Vite (a .jsx file inside src/), or use createElement.

Why is the button text missing?

createElement('button', 'Order now');
Answer

The second argument is props. The text was treated as props, not a child. Fix: createElement('button', null, 'Order now').

G. Scenario-Based Questions

A teammate wants to drop JSX "to avoid a build step". Is that realistic?

Possible for a tiny widget, but nested UI becomes unreadable. A real app still needs bundling, imports and minification — Vite gives that plus JSX for free.

You must render a heading level from data (h1–h3). How?

Store the tag in a capitalised variable: const Tag = `h${level}`; return <Tag>{text}</Tag>; — or createElement(`h${level}`, null, text).
