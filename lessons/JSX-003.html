JSX vs HTML

1. Visual Introduction

  • JSX and HTML are like British vs American English: 95% the same words, but a few spellings differ (colour vs color).
  • Copy-paste HTML into JSX and most of it works — the few differences cause most beginner errors.
      HTML                               JSX
 ┌──────────────────────────┐      ┌──────────────────────────────────┐
 │ class="card"             │ ───► │ className="card"                 │
 │ for="email"              │ ───► │ htmlFor="email"                  │
 │ onclick="buy()"          │ ───► │ onClick={buy}                    │
 │ tabindex="0"             │ ───► │ tabIndex={0}                     │
 │ style="color:red"        │ ───► │ style={{ color: 'red' }}         │
 │ <img src="a.png">        │ ───► │ <img src="a.png" />              │
 │ <br>                     │ ───► │ <br />                           │
 │ <!-- note -->            │ ───► │ {/* note */}                     │
 │ aria-label / data-id     │ ───► │ aria-label / data-id (unchanged) │
 └──────────────────────────┘      └──────────────────────────────────┘
Why the changes? JSX is JavaScript. class and for are reserved JS words, and React props follow the JS/DOM property names (element.className, element.tabIndex).

2. Why Do We Need It?

  • Pasting HTML from a design mock straight into a component often throws errors or warnings.
  • Knowing the rules lets you convert HTML in seconds and read React warnings correctly.
Wrong
// Raw HTML pasted into App.jsx
return (
  <div class="login">
    <label for="email">Email</label>
    <input id="email" type="email">
    <button onclick="login()"
            style="color: white">Login</button>
  </div>
);
// ✗ Syntax error: <input> not closed
Fixed
return (
  <div className="login">
    <label htmlFor="email">Email</label>
    <input id="email" type="email" />
    <button onClick={login}
            style={{ color: 'white' }}>Login</button>
  </div>
);

3. Core Concept

  • className instead of class; htmlFor instead of for.
  • camelCase for multi-word attributes and all events: onClick, onChange, tabIndex, maxLength, autoComplete.
  • Exceptions: aria-* and data-* keep their dashes.
  • Every tag must close: <img />, <input />, <br />, <hr />. Any element may self-close: <div />.
  • style takes an object, keys in camelCase: style={{ backgroundColor: 'teal', fontSize: 18 }} (numbers → px for most properties).
  • Events take a function, not a string: onClick={addToCart}.
  • One parent per returned JSX (use a Fragment <>…</> if no wrapper is wanted).
  • Dynamic values go in { }; comments are {/* … */}.
  • Form defaults: defaultValue / defaultChecked for uncontrolled inputs; value needs an onChange (or readOnly).

4. Syntax

// Attributes
<div className="cart" id="cart-1" data-items="3" aria-live="polite" />

// Label linked to input
<label htmlFor="qty">Qty</label>
<input id="qty" type="number" maxLength={2} autoFocus />

// Boolean attributes
<button disabled>Sold out</button>          // disabled={true}
<button disabled={!inStock}>Buy</button>

// Inline style (object, camelCase)
<p style={{ color: 'green', marginTop: 8 }}>Delivered</p>

// Events
<button onClick={() => setQty(qty + 1)}>+</button>

// Comment
{/* only inside braces */}

// Fragment (no extra DOM node)
<>
  <h2>Title</h2>
  <p>Body</p>
</>

5. Practical Example

A newsletter sign-up for a movie site, converted from HTML to JSX. Vite React app, replace src/App.jsx.

// src/App.jsx
import { useState } from 'react';

export default function App() {
  const [email, setEmail] = useState('');
  const [agree, setAgree] = useState(false);
  const [done, setDone] = useState(false);

  function handleSubmit(e) {
    e.preventDefault();          // stop page reload
    setDone(true);
  }

  const boxStyle = {
    maxWidth: 320,               // → 320px
    padding: 16,
    border: '1px solid #ccc',
    borderRadius: 8,
  };

  return (
    <>
      {/* HTML: <h1 class="title"> */}
      <h1 className="title">🎬 CineWeekly</h1>

      <form style={boxStyle} onSubmit={handleSubmit}>
        <label htmlFor="email">Email</label>
        <br />
        <input
          id="email"
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          autoComplete="email"
          aria-describedby="hint"
        />
        <p id="hint" style={{ fontSize: 12, color: 'gray' }}>
          One email per week. No spam.
        </p>

        <label>
          <input
            type="checkbox"
            checked={agree}
            onChange={(e) => setAgree(e.target.checked)}
          />{' '}
          I agree
        </label>
        <br />

        <button type="submit" disabled={!agree || email === ''} tabIndex={0}>
          Subscribe
        </button>
      </form>

      {done && <p data-testid="thanks">Thanks, {email}! 🍿</p>}
    </>
  );
}

6. Expected Output

🎬 CineWeekly


One email per week. No spam.


Thanks, riya@mail.com! 🍿

  • The button stays disabled until an email is typed and the box is ticked.
  • After submit, the thank-you line appears. In DevTools > Elements you see class="title" and for="email" — React writes normal HTML attributes to the DOM.

8. Real-World Application

  • Converting design templates: shop landing pages often start as HTML/CSS from a designer — you rename attributes and close tags.
  • Accessible forms: htmlFor + id and aria-* keep sign-up and checkout forms screen-reader friendly.
  • Testing: data-testid stays dashed and is used by testing tools.
  • Dynamic styling: a delivery tracker changes style={{ width: progress + '%' }} as the order moves.

9. Common Mistakes

Mistake 1: Unclosed void tags

Wrong
<img src="/pizza.jpg" alt="Pizza">
<br>
// ✗ Expected corresponding JSX closing tag
Fixed
<img src="/pizza.jpg" alt="Pizza" />
<br />

Mistake 2: Style as a string

Wrong
<p style="color: red; font-size: 20px">Sale!</p>
// ✗ Error: The `style` prop expects a mapping
//   from style properties to values, not a string.
Fixed
<p style={{ color: 'red', fontSize: 20 }}>Sale!</p>

Mistake 3: Event as a string, or calling it immediately

Wrong
<button onclick="addTodo()">Add</button>  // wrong case + string
<button onClick={addTodo()}>Add</button>  // runs during render!
Fixed
<button onClick={addTodo}>Add</button>
<button onClick={() => addTodo('Milk')}>Add</button>

Mistake 4: Using class / for

Wrong
<div class="menu">...</div>
// Dev console warning:
// Invalid DOM property `class`. Did you mean `className`?
Fixed
<div className="menu">...</div>

Intermediate 1

Convert this HTML chat input:

<!-- send message -->
<textarea maxlength="200" readonly>Hi!</textarea>
<button onclick="send()" disabled>Send</button>
Show solution
<>
  {/* send message */}
  <textarea maxLength={200} readOnly defaultValue="Hi!" />
  <button onClick={send} disabled>Send</button>
</>

In React, a textarea's text goes in value/defaultValue, not children.

Intermediate 2

Build a progress bar for a food order where progress (0–100) sets the inner bar width and colour turns green at 100.

Show solution
function OrderProgress({ progress }) {
  return (
    <div style={{ background: '#eee', height: 10, borderRadius: 5 }}>
      <div
        style={{
          width: progress + '%',
          height: '100%',
          borderRadius: 5,
          backgroundColor: progress === 100 ? 'green' : 'orange',
        }}
        aria-valuenow={progress}
        role="progressbar"
      />
    </div>
  );
}

11. Quick Revision

  • class → className, for → htmlFor.
  • camelCase attributes and events; aria-* / data-* stay dashed.
  • Close every tag: <img />, <input />, <br />.
  • style = object with camelCase keys; numbers mean px for most properties.
  • Pass functions to events, don't call them: onClick={fn}.
  • Comments: {/* … */}. One parent or a Fragment.
  • Textarea / select use value or defaultValue.

12. Interview Corner

Why className and not class?

class is a reserved word in JavaScript, and React follows the DOM property name element.className.

Why must <img> be self-closed in JSX?

JSX follows XML rules: every element must be explicitly closed. HTML's "void elements" don't exist as a concept in JSX's parser.

How does style differ from HTML?

It's a JavaScript object with camelCase keys and string/number values, e.g. {{ backgroundColor: 'red', padding: 8 }}. Outer braces = JSX expression, inner = object literal.

Which attributes keep dashes?

aria-* and data-*. (Custom elements / web components also receive attributes as you write them.)

A. Concept in 30 Seconds

JSX looks like HTML but follows JavaScript rules: className, htmlFor, camelCase names, function event handlers, style objects, and every tag closed.

B. Important Syntax

<div className="row" data-id={id} aria-hidden={false}>
  <label htmlFor="q">Search</label>
  <input id="q" autoComplete="off" maxLength={40} />
  <button onClick={search} style={{ fontWeight: 600 }}>Go</button>
  {/* comment */}
</div>

C. Must-Know Points

  1. className, htmlFor.
  2. Events are camelCase and take functions.
  3. Multi-word attributes are camelCase: tabIndex, readOnly, autoFocus.
  4. aria-*, data-* keep hyphens.
  5. All tags close; any tag can self-close.
  6. style={{ }} object; unitless numbers → px (except unitless props like lineHeight, opacity, zIndex).
  7. Return one parent or a Fragment.
  8. Use { } for JS values and {/* */} for comments.
  9. value without onChange → read-only warning; use defaultValue for uncontrolled.

D. Interview Questions

Basic

Convert onclick to JSX.

onClick={handler} — camelCase, function reference.

How do you write a comment in JSX?

{/* comment */} inside the markup.

Intermediate

Why double braces in style={{ color: 'red' }}?

Outer braces open a JS expression; inner braces are the object literal.

What does <input value="x" /> without onChange do?

It renders a read-only field and React warns in development. Add onChange, readOnly, or use defaultValue.

Advanced

What happens if you use class in React 19?

React DOM warns in development (“Invalid DOM property `class`. Did you mean `className`?”). Use className — it is the supported prop.

Tricky

Does <div /> work in JSX even though it doesn't in HTML?

Yes. In JSX any element can self-close; React renders an empty <div></div>.

Is style={{ zIndex: 2 }} rendered as 2px?

No. zIndex is unitless, so it stays z-index: 2.

E. Output-Based Questions

What HTML appears in DevTools?

<p className="tag" style={{ marginTop: 4, opacity: 0.5 }}>New</p>
Answer
<p class="tag" style="margin-top: 4px; opacity: 0.5;">New</p>

What shows on screen?

<p>Total {/* hidden note */} ₹{2 * 50}</p>
Answer
Total ₹100

The comment renders nothing. The DOM text has two spaces ("Total " + " ₹"), but the browser collapses them into one.

F. Debugging Questions

Why does the alert fire on page load, not on click?

<button onClick={alert('Ordered!')}>Order</button>
Answer

alert(...) is called during render. Wrap it: onClick={() => alert('Ordered!')}.

Why is clicking the label not focusing the input?

<label for="name">Name</label><input id="nm" />
Answer

Two bugs: use htmlFor, and the ids don't match (name vs nm).

G. Scenario-Based Questions

A designer sends a 200-line HTML checkout page. Fastest safe conversion?

Rename class/for, close void tags, convert inline styles to objects, replace onclick strings with handlers, wrap in one parent. Editor HTML-to-JSX converters help, but review the output.

A grocery list needs a test hook on each row. Which attribute?

data-testid="row-milk" — data-* stays dashed in JSX.

H. Coding Challenges

Convert to JSX:

<select id="size" onchange="pick()">
  <option value="s">Small</option>
  <option value="l" selected>Large</option>
</select>
Solution
<select id="size" defaultValue="l" onChange={pick}>
  <option value="s">Small</option>
  <option value="l">Large</option>
</select>

React uses value/defaultValue on <select> instead of selected on options.
