Embedding JavaScript in JSX

1. Visual Introduction

  • Think of a shop price tag with a blank slot: "Price: ____". The tag is fixed; the number in the slot changes every day.
  • In JSX, the blank slot is a pair of curly braces { }. Whatever JavaScript you put inside is worked out, and the result is shown on screen.
  • Outside the braces = fixed text (static markup). Inside the braces = live JavaScript (embedded expression).
   JSX you write                         What appears on screen
 ┌──────────────────────────────┐      ┌──────────────────────────┐
 │ <p>                          │      │                          │
 │   Hello, {user.name}!        │ ───► │  Hello, Priya!           │
 │   Cart: {items.length} items │      │  Cart: 3 items           │
 │   Total: ₹{getTotal()}       │      │  Total: ₹747             │
 │ </p>                         │      │                          │
 └──────────────────────────────┘      └──────────────────────────┘
        ▲ fixed text                 ▲ { } = "run this JS, show the result"
One rule to remember: curly braces switch you from "HTML mode" back into "JavaScript mode" for one value.

2. Why Do We Need It?

  • Real apps show changing data: user names, prices, weather, chat messages.
  • Without braces you would have to hard-code every value, or build HTML strings by hand (string concatenation) and inject them — slow and unsafe.
  • With braces, the value comes straight from your variables, and React escapes it for you (protects against script injection, called XSS).
Before (vanilla JS)
// Vanilla JS: build a string, inject HTML
const user = { name: 'Priya' };
const items = ['Tea', 'Bread', 'Milk'];

document.getElementById('app').innerHTML =
  '<p>Hello, ' + user.name + '!</p>' +
  '<p>Cart: ' + items.length + ' items</p>';
// Easy to break quotes, and unsafe
// if user.name contains <script>
After (JSX)
// React + JSX: drop values into { }
const user = { name: 'Priya' };
const items = ['Tea', 'Bread', 'Milk'];

function Greeting() {
  return (
    <>
      <p>Hello, {user.name}!</p>
      <p>Cart: {items.length} items</p>
    </>
  );
}
// React escapes text automatically

3. Core Concept

  • { } holds one JavaScript expression (a piece of code that produces a value).
  • You can use braces in two places: between tags (children) and as an attribute value (props): <img src={url} />.
  • Allowed inside: variables, maths {a + b}, object properties {user.name}, function calls {format(price)}, template literals, ternaries.
  • Strings and numbers are shown as text. 0 shows as "0".
  • true, false, null, undefined show nothing (render empty).
  • Arrays are shown item by item (each item must be renderable).
  • Plain objects cannot be shown — React throws "Objects are not valid as a React child".
  • Write a function call {getTotal()} to show its result. {getTotal} (no brackets) passes the function itself, which is not renderable as a child.
  • Comments inside JSX use braces too: {/* note */}.

4. Syntax

// 1. Variable
<h1>{title}</h1>

// 2. Maths / string joining
<p>Total: {price * qty}</p>
<p>{firstName + ' ' + lastName}</p>

// 3. Object property and array item
<p>{movie.title} ({movie.year})</p>
<p>First topping: {toppings[0]}</p>

// 4. Function call — note the ()
<p>{formatPrice(249)}</p>
<p>{new Date().getFullYear()}</p>

// 5. Template literal (backtick string)
<p>{`${city}: ${temp}°C`}</p>

// 6. In an attribute (no quotes around the braces)
<img src={poster} alt={movie.title} />

// 7. A comment inside JSX
{/* this is ignored */}

5. Practical Example

A food-order summary card. Create the app with npm create vite@latest food-app -- --template react, then replace src/App.jsx.

// src/App.jsx
const restaurant = {
  name: 'Spice Garden',
  rating: 4.4,
  logo: 'https://placehold.co/64x64?text=SG',
};

const order = [
  { id: 1, dish: 'Paneer Tikka', price: 249, qty: 1 },
  { id: 2, dish: 'Butter Naan', price: 49, qty: 4 },
  { id: 3, dish: 'Mango Lassi', price: 99, qty: 2 },
];

const DELIVERY_FEE = 30;

// Helper functions — called from inside JSX
function formatPrice(amount) {
  return '₹' + amount.toFixed(2);
}

function getSubtotal(items) {
  return items.reduce((sum, item) => sum + item.price * item.qty, 0);
}

export default function App() {
  const subtotal = getSubtotal(order);
  const itemCount = order.reduce((n, item) => n + item.qty, 0);

  return (
    <main>
      {/* Attribute values from JS */}
      <img src={restaurant.logo} alt={restaurant.name} width={64} />

      {/* Object properties */}
      <h1>{restaurant.name}</h1>
      <p>Rating: {restaurant.rating} / 5</p>

      {/* Maths and a template literal */}
      <p>{`You ordered ${itemCount} items`}</p>

      {/* Function calls */}
      <p>Subtotal: {formatPrice(subtotal)}</p>
      <p>Delivery: {formatPrice(DELIVERY_FEE)}</p>
      <h2>Total: {formatPrice(subtotal + DELIVERY_FEE)}</h2>

      {/* A method call on a built-in object */}
      <small>Ordered at {new Date().toLocaleTimeString()}</small>
    </main>
  );
}
Everything inside { } runs every time the component renders. Keep it quick — heavy work belongs in a variable above the return (or later, in useMemo).

7. Execution Flow

 1. Vite compiles the JSX. Each { } becomes a normal JS value in props:
      <p>Subtotal: {formatPrice(subtotal)}</p>
        ──►  jsxs("p", { children: ["Subtotal: ", formatPrice(subtotal)] })
        │
        ▼
 2. App() runs. JS evaluates the arguments first:
      getSubtotal(order)    → 643
      formatPrice(643)      → "₹643.00"
        │
        ▼
 3. jsxs(...) returns a React element (plain object):
      { type: "p", props: { children: ["Subtotal: ", "₹643.00"] } }
        │
        ▼
 4. react-dom turns the element tree into real DOM
      text nodes are escaped (no HTML injection)
        │
        ▼
 5. Screen shows:  Subtotal: ₹643.00

8. Real-World Application

  • Shopping app: {product.name}, {formatPrice(product.price)}, {cart.length} badge on the cart icon.
  • Weather app: {Math.round(temp)}°C and an icon chosen by a function: <img src={iconFor(condition)} />.
  • Chat app: {message.sender} and {timeAgo(message.sentAt)} next to each message.
  • Movie site: poster src={movie.posterUrl}, title, and {movie.runtime / 60} style calculations.
  • Safety: user-typed text (a chat message) shown via {text} is escaped, so <script> appears as plain text.

9. Common Mistakes

Mistake 1: Trying to render a whole object

Wrong
const user = { name: 'Priya', city: 'Pune' };

function Profile() {
  return <p>{user}</p>;
}
// Error: Objects are not valid
// as a React child
Fixed
const user = { name: 'Priya', city: 'Pune' };

function Profile() {
  return <p>{user.name} from {user.city}</p>;
}
// Or for debugging:
// <pre>{JSON.stringify(user, null, 2)}</pre>

Mistake 2: Forgetting to call the function

Wrong
function getGreeting() {
  return 'Good morning!';
}

<h1>{getGreeting}</h1>
// Shows nothing; React logs
// "Functions are not valid as a React child"
Fixed
function getGreeting() {
  return 'Good morning!';
}

<h1>{getGreeting()}</h1>
// Good morning!

Mistake 3: Putting quotes around the braces

Wrong
<img src="{movie.poster}" alt="poster" />
// src is literally the text "{movie.poster}"
Fixed
<img src={movie.poster} alt="poster" />
// src is the variable's value

Mistake 4: Rendering a Date object directly

Wrong
<p>Delivered: {new Date()}</p>
// Error: Objects are not valid
// as a React child
Fixed
<p>Delivered: {new Date().toLocaleDateString()}</p>
// e.g. Delivered: 11/5/2026 (en-US; format depends on locale)

11. Quick Revision

  • { } = "evaluate this JavaScript and show the result".
  • Works in children <p>{x}</p> and attributes <img src={x} />.
  • Strings and numbers show; true/false/null/undefined show nothing; 0 shows "0".
  • Objects (including Date) cannot be shown directly — pick a property or convert to a string.
  • Call functions with (): {getTotal()}, not {getTotal}.
  • No quotes around braces: src={url}, not src="{url}".
  • React escapes text from { }, which protects against XSS.

12. Interview Corner

What do curly braces do in JSX?

They let you insert the value of a JavaScript expression into the markup, either as a child (text/elements) or as an attribute value.

Why does <p>{user}</p> crash when user is an object?

React does not know how to display a plain object. Valid children are strings, numbers, elements, arrays/iterables of those, and empty values (null, undefined, booleans). An object throws "Objects are not valid as a React child".

Is it safe to show user-typed text with {text}?

Yes. React escapes strings before inserting them as text, so <script> shows as literal characters. Only dangerouslySetInnerHTML bypasses this.

What is the difference between {format()} and {format}?

{format()} calls the function and renders its return value. {format} passes the function object itself — fine as an event handler (onClick={format}), but not renderable as a child.

Does the code inside braces run once or every render?

Every render. The component function runs again, so every expression in its JSX is evaluated again.

A. Concept in 30 Seconds

Curly braces { } in JSX are a window back into JavaScript. Put any single expression inside — variable, maths, property, function call — and React shows the result. Strings/numbers show, booleans/null/undefined show nothing, plain objects crash.

B. Important Syntax

<p>{name}</p>                  // variable
<p>{price * qty}</p>           // maths
<p>{user.address.city}</p>     // nested property
<p>{formatPrice(total)}</p>    // function call
<p>{`${n} items`}</p>          // template literal
<img src={url} alt={title} />  // attribute values
{/* comment */}                // JSX comment

C. Must-Know Points

  1. Braces hold exactly one expression.
  2. Use braces in children and in attribute values.
  3. Do not wrap braces in quotes in attributes.
  4. 0 and NaN render as text; true, false, null, undefined render nothing.
  5. Plain objects and Date objects throw when rendered as children.
  6. Arrays render each item in order (give list items a key — covered in the lists lessons).
  7. Functions are not valid children — call them.
  8. Expressions run on every render.
  9. Text from braces is auto-escaped (XSS protection).

D. Interview Questions

Basic

What can go inside JSX curly braces?

Any JavaScript expression: variables, literals, operators, property access, function calls, ternaries, template literals, arrow functions, other JSX.

How do you write a comment inside JSX?

{/* comment */} — braces with a block comment inside.

Intermediate

What renders for {['a', 'b', 3]}?

"ab3" — arrays render each item. (React only warns about missing keys when the items are elements, not plain strings.)

Why does {new Date()} throw but {Date.now()} work?

new Date() is an object. Date.now() returns a number, which renders as text.

Advanced

How does {formatPrice(total)} look after compilation?

It becomes part of the children prop: jsxs("p", { children: ["Total: ", formatPrice(total)] }) from react/jsx-runtime. The function runs while building the arguments.

Tricky

What shows for <p>{undefined}{null}{false}{0}</p>?

Just 0. The first three render nothing.

What does <img src="{url}" /> produce?

An <img> whose src attribute is the literal text {url} — a broken image.

F. Debugging Questions

Bug 1

const movie = { title: 'Inception', year: 2010 };
return <h2>{movie}</h2>;
Show answer

Objects are not valid children. Fix: <h2>{movie.title} ({movie.year})</h2>.

Bug 2

function todayLabel() { return 'Today'; }
return <span>{todayLabel}</span>;
Show answer

Function not called — nothing renders and React logs an error. Fix: {todayLabel()}.

Bug 3

<a href="{shop.url}">Visit</a>
Show answer

Quotes make it a literal string. Fix: href={shop.url}.

G. Scenario-Based Questions

Scenario 1

Your weather card shows "Temp: 23.456789°C". How do you show "23°C"?

Show answer

{Math.round(temp)}°C, or {temp.toFixed(0)}°C.

Scenario 2

A chat message from a user contains <b>hi</b>. A teammate fears it will render bold. Will it?

Show answer

No. {message.text} is escaped and shows the tags as plain text. Only dangerouslySetInnerHTML would interpret it as HTML — avoid it for user content.

Scenario 3

A product's price calculation is long (tax, discount, rounding). Where should it go?

Show answer

In a named helper function or a variable above return, then insert with {finalPrice}. Keeps JSX readable.
