JSX expressions

1. Visual Introduction

  • Think of a vending machine slot: it only accepts a coin (a value). You cannot push in a set of instructions like "if hungry, give chips".
  • JSX braces are that slot. They accept an expression (something that becomes a value). They reject a statement (an instruction that does something but is not a value).
  • So {isOpen ? 'Open' : 'Closed'} fits, but {if (isOpen) { ... }} does not.
             { ...  }  ← the slot only takes VALUES
               │
   ┌───────────┴─────────────┐
   ▼                         ▼
 EXPRESSION  ✔               STATEMENT  ✘
 produces a value            performs an action
 ─────────────────           ─────────────────
 count + 1                   if (x) { ... }
 isOpen ? 'Open' : 'Closed'  for (...) { ... }
 items.map(i => <li/>)       const total = 5;
 user?.name ?? 'Guest'       switch (day) { ... }
 getTotal()                  while (...) { ... }

2. Why Do We Need It?

  • UIs need decisions ("show Sold Out or Add to Cart?") and repetition ("one row per todo").
  • Beginners reach for if and for inside JSX — and get a syntax error.
  • Knowing the expression forms (ternary, &&, map) lets you write decisions and loops right inside the markup.
Before (statement)
function Stock({ inStock }) {
  return (
    <button>
      {if (inStock) { 'Add to cart' } else { 'Sold out' }}
    </button>
  );
}
// SyntaxError: Unexpected token "if"
After (expression)
function Stock({ inStock }) {
  return (
    <button>
      {inStock ? 'Add to cart' : 'Sold out'}
    </button>
  );
}
// Works: the ternary is an expression

3. Core Concept

  • Expression = code that evaluates to a value. Test: could you write const x = ___; with it? If yes, it is an expression.
  • Statement = code that performs an action: if, for, while, switch, const/let declarations, return.
  • Why: JSX compiles to a function call. {...} becomes an argument in that call, and JavaScript arguments must be expressions.
  • Expression tools for decisions: ternary a ? b : c, logical AND cond && <X/>, nullish coalescing value ?? 'fallback', optional chaining user?.name.
  • Expression tool for loops: array methods like items.map(...) and items.filter(...).map(...).
  • Need a real if or switch? Put it above the return (or in a helper function), store the result, and insert the variable.
  • JSX itself is an expression, so you can store it in a variable or return it from a function.

4. Syntax

// ✔ Expressions that work inside { }
{count}                              // variable
{count + 1}                          // arithmetic
{isVip ? 'VIP' : 'Member'}           // ternary (if/else)
{hasCoupon && <span>10% off</span>}  // && (if, no else)
{user?.name ?? 'Guest'}              // optional chaining + ??
{todos.map(t => <li key={t.id}>{t.text}</li>)}   // loop
{getLabel(status)}                   // function call
{(() => { if (a) return 'A'; return 'B'; })()}  // IIFE: works, but hard to read

// ✘ Statements — syntax errors inside { }
{if (x) { ... }}
{for (const t of todos) { ... }}
{const total = 5}
{switch (s) { ... }}

// ✔ Statement moved ABOVE the return
let badge;
if (score > 90) badge = 'Gold';
else badge = 'Silver';
return <span>{badge}</span>;

5. Practical Example

A todo list that uses every expression form plus a switch done the right way. In a Vite React app (npm create vite@latest todo -- --template react), replace src/App.jsx:

// src/App.jsx
import { useState } from 'react';

const initialTodos = [
  { id: 1, text: 'Buy milk', done: true, priority: 'high' },
  { id: 2, text: 'Book movie tickets', done: false, priority: 'low' },
  { id: 3, text: 'Pay electricity bill', done: false, priority: 'high' },
];

// A switch statement lives in a normal function...
function priorityIcon(priority) {
  switch (priority) {
    case 'high':
      return '🔴';
    case 'low':
      return '🟢';
    default:
      return '⚪';
  }
}

export default function App() {
  const [todos, setTodos] = useState(initialTodos);
  const [user] = useState(null); // nobody logged in

  // ...and an if statement lives ABOVE the return
  const pending = todos.filter((t) => !t.done).length;
  let summary;
  if (pending === 0) {
    summary = 'All done! 🎉';
  } else {
    summary = `${pending} left to do`;
  }

  function toggle(id) {
    setTodos(todos.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
  }

  return (
    <main>
      {/* ?? and ?. — fallback when user is null */}
      <h1>Hi, {user?.name ?? 'Guest'}</h1>

      {/* variable computed with if */}
      <p>{summary}</p>

      {/* .map() is the "loop" */}
      <ul>
        {todos.map((t) => (
          <li key={t.id} onClick={() => toggle(t.id)}>
            {priorityIcon(t.priority)}{' '}
            {/* ternary for if/else */}
            {t.done ? <s>{t.text}</s> : t.text}
            {/* && for "only if" */}
            {t.priority === 'high' && !t.done && <b> (urgent)</b>}
          </li>
        ))}
      </ul>
    </main>
  );
}

Hi, Guest

2 left to do

  • 🔴 Buy milk
  • 🟢 Book movie tickets
  • 🔴 Pay electricity bill (urgent)
  • Click "Pay electricity bill" → it is struck through, "(urgent)" disappears, summary becomes "1 left to do".

7. Execution Flow

 1. App() runs (on first render and after every setTodos)
        │
        ▼
 2. Statements run first, above return:
      pending = 2   →  if/else  →  summary = "2 left to do"
        │
        ▼
 3. return (...) builds ONE big expression. For each { }:
      user?.name ?? 'Guest'      → "Guest"
      summary                    → "2 left to do"
      todos.map(...)             → [<li>, <li>, <li>]
         ├─ t.done ? <s/> : text → picks one branch
         └─ cond && <b/>         → <b> or false (renders nothing)
        │
        ▼
 4. Compiled form: jsxs("main", { children: [ ...values... ] })
    Every { } is an ARGUMENT → must be an expression
        │
        ▼
 5. React renders the elements; false/null are skipped

8. Real-World Application

  • Food delivery: {restaurant.isOpen ? <OrderButton/> : <p>Opens at 11 am</p>}.
  • Shopping: {cart.length > 0 && <CartBadge count={cart.length} />}.
  • Chat: {messages.map(m => <Bubble key={m.id} {...m} />)} for the message list.
  • Weather: a switch on the condition code inside iconFor(code), then <img src={iconFor(code)} />.
  • Profiles: {profile?.avatarUrl ?? defaultAvatar} while data is still loading.

9. Common Mistakes

Mistake 1: Using if inside JSX

Wrong
return (
  <p>
    {if (temp > 30) 'Hot' else 'Cool'}
  </p>
);
Fixed
return <p>{temp > 30 ? 'Hot' : 'Cool'}</p>;

// or, for more complex logic:
const label = temp > 30 ? 'Hot' : 'Cool';
return <p>{label}</p>;

Mistake 2: Using a for loop inside JSX

Wrong
<ul>
  {for (const m of movies) {
    <li>{m.title}</li>
  }}
</ul>
Fixed
<ul>
  {movies.map((m) => (
    <li key={m.id}>{m.title}</li>
  ))}
</ul>

Mistake 3: && with a number shows "0"

Wrong
{cart.length && <p>Items in cart</p>}
// cart is empty → renders "0" on screen
Fixed
{cart.length > 0 && <p>Items in cart</p>}
// empty → false → renders nothing

Mistake 4: map with curly body but no return

Wrong
{todos.map((t) => {
  <li key={t.id}>{t.text}</li>;
})}
// renders nothing: returns undefined
Fixed
{todos.map((t) => (
  <li key={t.id}>{t.text}</li>
))}
// ( ) = implicit return

  preparing: () => 'Preparing',
  shipping: (o) => `On the way (ETA ${o.eta} min)`,

function OrderStatus({ order }) {
  if (!order) return <p>No orders yet</p>;   // early return (statement, outside JSX)
  return <p>{STATUS_TEXT[order.status]?.(order) ?? 'Unknown'}</p>;
}

11. Quick Revision

  • Braces accept expressions only — things that produce a value.
  • Statements (if, for, switch, const) cause a syntax error inside braces.
  • Reason: {...} becomes a function-call argument after compilation.
  • if/else → ternary. "only if" → &&. fallback → ??. loop → .map().
  • Complex logic → variables above return, helper functions, or early returns.
  • Beware 0 && ... — it renders "0".

12. Interview Corner

What is the difference between an expression and a statement?

An expression produces a value (a + b, fn(), x ? y : z). A statement performs an action and does not produce a usable value (if, for, variable declarations).

Why can't you use if inside JSX braces?

JSX compiles to jsx(type, props) calls. Each {...} becomes part of the arguments, and arguments must be expressions. if is a statement, so the compiler rejects it.

How do you loop in JSX?

Use an array method that returns an array of elements, usually .map(), with a stable key on each item.

When would you use && vs a ternary?

&& when there is nothing to show in the "false" case. Ternary when you need two different outputs. Make sure the left side of && is a real boolean, not a number.

Can an IIFE be used in JSX?

Yes — it is an expression, so it works. But it hurts readability; a named helper function or a variable above return is preferred.

A. Concept in 30 Seconds

JSX braces take values, not instructions. Expressions (ternary, &&, ??, .map(), function calls) work. Statements (if, for, switch, const) fail because each {...} becomes a function argument after compilation. Put statements above return.

B. Important Syntax

{cond ? <A /> : <B />}                 // if / else
{cond && <A />}                        // if only
{value ?? 'default'}                   // fallback for null/undefined
{obj?.deep?.prop}                      // safe access
{list.map(x => <li key={x.id}>{x.name}</li>)}   // loop

// statements go outside JSX
if (!data) return <p>Loading…</p>;     // early return
const label = getLabel(status);        // helper + variable

C. Must-Know Points

  1. Expression = produces a value; statement = performs an action.
  2. Quick test: can it go on the right side of const x = ...?
  3. if, for, while, switch, let/const are not allowed in braces.
  4. JSX compiles to function calls; braces become arguments.
  5. Ternary for two outcomes, && for one.
  6. 0 && x renders "0"; use n > 0 &&.
  7. .map() returns an array of elements — remember key.
  8. Arrow function with { } body needs return.
  9. JSX itself is an expression — store it in variables.
  10. Early returns are a clean way to handle loading/empty states.

D. Interview Questions

Basic

Give three expressions you can use inside JSX.

Ternary a ? b : c, logical AND a && b, and a function call fn(). Also .map(), template literals, arithmetic.

Intermediate

Is {x = 5} valid inside JSX?

Syntactically yes — an assignment is an expression (it evaluates to 5). But it mutates a variable during render, which you should never do.

Why is .forEach() useless for rendering lists?

forEach returns undefined, so nothing renders. .map() returns a new array of elements.

Advanced

Show what <p>{ok ? 'Yes' : 'No'}</p> compiles to.

jsx("p", { children: ok ? "Yes" : "No" }) — the ternary sits directly as a property value, which is why it must be an expression.

Tricky

What renders: {'' && <b>Hi</b>}?

Nothing visible. '' is falsy, so the expression is '' — an empty string renders as empty text.

What renders: {NaN && <b>Hi</b>}?

"NaN" — like 0, NaN is falsy but is a number, so React prints it.

export default function TodoGroups({ todos }) {
  const done = todos.filter((t) => t.done);
  const pending = todos.filter((t) => !t.done);
  return (

        </section>
      )}
    </>
  );
}
