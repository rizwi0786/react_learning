JSX attributes

1. Visual Introduction

  • Think of a pizza order form. Each field (size, crust, extra cheese) is an attribute. Some answers are fixed words ("Large"), some are worked out ("₹" + price), and sometimes you hand over a whole pre-filled form at once.
  • JSX attributes (also called props when passed to components) work the same: quoted strings, braced expressions, and spread ({...obj}) to pass many at once.
 <input  type="search"  maxLength={30}  disabled  {...extraProps}  />
          ────┬──────   ──────┬──────   ───┬───  ──────┬───────
              │               │            │           │
       string literal   JS expression  boolean     spread: copy every
       (fixed text)     (any value)    shorthand   key/value of an object
                                       = {true}
              └───────────────┴────────────┴───────────┘
                                │
                                ▼
     props object: { type: "search", maxLength: 30, disabled: true, ...extraProps }

2. Why Do We Need It?

  • Elements need configuration: image sources, link targets, input limits, click handlers.
  • Values often come from data (a movie's poster URL), so you need expressions, not only fixed text.
  • Components frequently receive a bag of options — spread saves writing each one by hand.
Before (vanilla JS)
// Vanilla JS: set attributes one by one
const img = document.createElement('img');
img.setAttribute('src', movie.poster);
img.setAttribute('alt', movie.title);
img.setAttribute('width', '200');
img.addEventListener('click', openTrailer);
document.body.appendChild(img);
After (JSX)
// JSX: attributes inline, values from JS
<img
  src={movie.poster}
  alt={movie.title}
  width={200}
  onClick={openTrailer}
/>

3. Core Concept

  • String literal: title="Hello" — double or single quotes, no braces. Fixed text only.
  • Expression: price={249}, src={url}, onClick={handleClick} — any JS value: number, boolean, object, array, function, JSX.
  • Never both: src="{url}" is the literal string {url}.
  • Boolean shorthand: <input disabled /> means disabled={true}.
  • Spread attributes: <Card {...movie} /> copies every property of movie as a prop.
  • Order matters: later attributes win. <Btn {...props} type="button" /> forces type; <Btn type="button" {...props} /> lets props override it.
  • Names are camelCase for DOM properties: className, htmlFor, onClick, tabIndex, maxLength. Exception: aria-* and data-* keep their dashes.
  • style takes an object, not a string: style={{ color: 'red' }} (outer braces = expression, inner = object).
  • key is special: React uses it and does not pass it into props. (ref is a normal prop for function components in React 19.)

4. Syntax

// 1. String literal
<a href="https://example.com" target="_blank" rel="noreferrer">Shop</a>

// 2. Expressions: number, boolean, function, object, array
<input maxLength={20} required={true} onChange={handleChange} />
<div style={{ padding: 12, backgroundColor: '#fffbe6' }} />
<Chart data={[3, 5, 8]} />

// 3. Boolean shorthand (true only)
<button disabled>Pay</button>          // disabled={true}

// 4. Template literal for a mixed string
<img alt={`Poster of ${movie.title}`} src={movie.poster} />

// 5. Spread
const linkProps = { href: '/cart', title: 'Open cart' };
<a {...linkProps}>Cart</a>

// 6. Spread + override (last one wins)
<a {...linkProps} title="Your basket">Cart</a>   // title = "Your basket"

// 7. Rest + spread to forward the remaining props
function TextInput({ label, ...rest }) {
  return <label>{label} <input {...rest} /></label>;
}

5. Practical Example

A movie search form that uses every attribute style. In a Vite React app, replace src/App.jsx:

// src/App.jsx
import { useState } from 'react';

// Reusable input: takes "label", forwards everything else to <input>
function Field({ label, id, ...inputProps }) {
  return (
    <p>
      <label htmlFor={id}>{label}</label>{' '}
      <input id={id} {...inputProps} />
    </p>
  );
}

const movie = {
  title: 'Interstellar',
  poster: 'https://placehold.co/120x180?text=Poster',
  year: 2014,
};

export default function App() {
  const [query, setQuery] = useState('');
  const tooShort = query.trim().length < 2;

  // A bag of shared attributes
  const searchAttrs = {
    type: 'search',
    placeholder: 'Search movies…',
    maxLength: 30,
    autoComplete: 'off',
  };

  return (
    <main style={{ fontFamily: 'sans-serif', padding: 16 }}>
      <Field
        label="Movie"
        id="q"
        {...searchAttrs}
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        aria-describedby="hint"
      />
      <small id="hint">Type at least 2 letters</small>

      <p>
        <button type="submit" disabled={tooShort}>
          Search
        </button>
      </p>

      <img
        src={movie.poster}
        alt={`Poster of ${movie.title} (${movie.year})`}
        width={120}
        data-movie-year={movie.year}
      />
    </main>
  );
}

8. Real-World Application

  • Shopping: <ProductCard {...product} onAdd={addToCart} /> — spread the product object from the API.
  • Design systems: a Button that accepts variant and forwards the rest (...rest) to the real <button> so type, disabled, aria-* all work.
  • Forms: <input required maxLength={10} inputMode="numeric" /> for a phone number field.
  • Testing/analytics: data-testid="checkout" or data-track="add-to-cart" attributes.
  • Accessibility: aria-label={Remove ${item.name}} on icon-only buttons.

9. Common Mistakes

Mistake 1: Quoting an expression

Wrong
<input maxLength="{limit}" />
<img src="{movie.poster}" />
Fixed
<input maxLength={limit} />
<img src={movie.poster} />

Mistake 2: Passing a number as a string to a component

Wrong
<Rating stars="4" />
// inside: stars + 1  →  "41"
Fixed
<Rating stars={4} />
// inside: stars + 1  →  5

Mistake 3: Spread in the wrong order

Wrong
// Wanted: always a safe type="button"
function Btn(props) {
  return <button type="button" {...props} />;
}
<Btn type="submit">Pay</Btn>
// props.type overrides → submits the form!
Fixed
function Btn(props) {
  return <button {...props} type="button" />;
}
// type is forced last → always "button"

Mistake 4: HTML-style attribute names and style strings

Wrong
<label for="email" class="lbl"
  style="color: red">Email</label>
// style string → React error;
// class/for → dev warnings
Fixed
<label htmlFor="email" className="lbl"
  style={{ color: 'red' }}>Email</label>

Mistake 5: Expecting key in props

Wrong
function Row({ key, name }) {
  return <li>{key}: {name}</li>; // key is undefined
}
<Row key={7} name="Tea" />
Fixed
function Row({ id, name }) {
  return <li>{id}: {name}</li>;
}
<Row key={7} id={7} name="Tea" />

11. Quick Revision

  • Strings: attr="text". Anything else: attr={expression}.
  • No quotes around braces.
  • Bare attribute = true: <input disabled />.
  • Spread {...obj} passes every key; the last attribute written wins.
  • camelCase DOM names (className, htmlFor, onClick), but aria-* / data-* keep dashes.
  • style is an object: style={{ fontSize: 14 }}.
  • key never reaches your component's props.

12. Interview Corner

What are the three ways to give a JSX attribute a value?

A string literal (a="x"), an expression in braces (a={x}), and spread ({...obj}). Plus the boolean shorthand (a means a={true}).

In <Btn {...props} color="red" />, who wins if props.color is "blue"?

"red" — attributes are applied left to right, so the later one overwrites.

Why className and htmlFor instead of class and for?

JSX is JavaScript, and React's prop names follow DOM property names (element.className, label.htmlFor). class and for are also reserved words in JS.

What is a downside of spreading props onto a DOM element?

Unknown or component-only props can leak onto the DOM (warnings or junk attributes), and it hides which props are actually used. Destructure what you need, then spread the rest.

Can you pass key through spread?

If the spread object contains key, React warns in development ("A props object containing a \"key\" prop is being spread into JSX"). Pass key directly: <Row key={x.id} {...x} />.

A. Concept in 30 Seconds

Attributes configure an element. Use quotes for fixed text, braces for any JavaScript value, and spread {...obj} to pass many at once. Later attributes override earlier ones. Names are camelCase, except aria-* and data-*.

B. Important Syntax

<img src={url} alt="Logo" width={64} />   // expression + string + number
<input disabled />                        // = disabled={true}
<p style={{ color: 'teal' }} />            // object
<a {...linkProps} />                      // spread
<Btn {...props} type="button" />          // override after spread
function Field({ label, ...rest }) {      // rest + spread
  return <input aria-label={label} {...rest} />;
}

C. Must-Know Points

  1. String literal: attr="..."; anything else in braces.
  2. "{x}" is a literal string, not the value.
  3. Bare attribute means true.
  4. To pass false, write disabled={false} (or leave it out).
  5. Number props need braces: count={3}, not count="3".
  6. Spread copies own enumerable properties of an object.
  7. Last writer wins in attribute order.
  8. camelCase for DOM props; aria-*, data-* stay dashed.
  9. style takes an object with camelCase CSS keys.
  10. key is consumed by React; ref is a normal prop in React 19 function components.

D. Interview Questions

Basic

How do you pass a number prop?

With braces: <Stars count={5} />. Quotes would make it the string "5".

Intermediate

What does <Card {...movie} /> do?

Passes each property of movie as a separate prop — the same as writing title={movie.title} year={movie.year} and so on.

Why does style="color:red" fail in React?

React expects style to be an object. A string throws an error telling you to use a mapping from style properties to values.

Advanced

How does <A x="1" {...p} y={2} /> compile?

Roughly jsx(A, { x: "1", ...p, y: 2 }) — a normal object literal with spread, so normal JS overwrite rules apply.

Tricky

<input value="5" /> vs <input value={5} /> in the DOM?

Both end up as the string "5" in the DOM, because DOM attributes are strings. The difference matters for components, which receive the raw JS value.

Does <Checkbox checked="false" /> uncheck it?

No. "false" is a non-empty string, which is truthy. Use checked={false}.

F. Debugging Questions

Bug 1

<img src="{product.image}" alt="{product.name}" />
Show answer

Literal strings. Use src={product.image} alt={product.name}.

Bug 2

<div style="background: yellow; padding: 8px">Offer!</div>
Show answer

Use an object: style={{ background: 'yellow', padding: 8 }}. Numbers get "px" added automatically for most size properties.

Bug 3

function Input(props) {
  return <input {...props} />;
}
<Input label="Email" />
// No label text appears; label="Email" just sits on <input> as an attribute
Show answer

Unknown lowercase props are passed to the DOM as attributes, so label leaks onto <input> and is never shown. Destructure component-only props: function Input({ label, ...rest }) { return <label>{label}<input {...rest} /></label>; }.
