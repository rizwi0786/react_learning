JSX fragments

1. Visual Introduction

  • A delivery rider can only carry one bag. To deliver a burger and fries, you put both in a bag.
  • A component can only return one thing. A <div> works as the bag, but that bag stays on the page as an extra box.
  • A fragment (<>...</>) is a bag that disappears on arrival: React groups the items, but adds nothing to the real page (the DOM).
  With a <div> wrapper                  With a fragment <>...</>
  ─────────────────────                  ──────────────────────────
  return (                               return (
    <div>                                  <>
      <h2>Burger</h2>                        <h2>Burger</h2>
      <p>₹199</p>                           <p>₹199</p>
    </div>                                 </>
  );                                     );

  DOM:  <div>                           DOM:  <h2>Burger</h2>
          <h2>Burger</h2>                   <p>₹199</p>
          <p>₹199</p>                    (no extra box)
        </div>   ← extra box

2. Why Do We Need It?

  • A component returns one value. Two side-by-side elements are two values → syntax error.
  • Extra <div>s can break HTML rules: a <tr> may only contain <td>/<th>, a <ul> only <li>.
  • Extra wrappers can break CSS layouts (flex and grid see the wrapper, not your items).
Before
// Error: Adjacent JSX elements must be
// wrapped in an enclosing tag
function Price() {
  return (
    <td>Pizza</td>
    <td>₹299</td>
  );
}

// "Fix" with div → invalid table HTML
function Price() {
  return (
    <div>
      <td>Pizza</td>
      <td>₹299</td>
    </div>
  );
}
After
// Fragment: groups without a DOM node
function Price() {
  return (
    <>
      <td>Pizza</td>
      <td>₹299</td>
    </>
  );
}

// <tr><Price /></tr>
// → <tr><td>Pizza</td><td>₹299</td></tr>

3. Core Concept

  • Short syntax: <>...</>. No import needed.
  • Long syntax: <Fragment>...</Fragment>, imported from 'react'.
  • Only the long syntax accepts a key (needed inside .map()).
  • In stable React 19.2, key is the only attribute a fragment accepts. No className, style or onClick — there is no DOM element to put them on.
  • Behind the scenes: <>a b</> compiles to jsxs(Fragment, { children: [a, b] }) (automatic JSX runtime).
  • Fragments can be nested and can be empty (<></> renders nothing).
  • Returning an array [<a key="1"/>, <b key="2"/>] also works, but every item needs a key. Fragments are cleaner.

4. Syntax

// 1. Short syntax
function Title() {
  return (
    <>
      <h1>Movie Night</h1>
      <p>Friday, 8 PM</p>
    </>
  );
}

// 2. Long syntax (same result)
import { Fragment } from 'react';
function Title() {
  return (
    <Fragment>
      <h1>Movie Night</h1>
      <p>Friday, 8 PM</p>
    </Fragment>
  );
}

// 3. Keyed fragment in a list (long syntax only)
{items.map((item) => (
  <Fragment key={item.id}>
    <dt>{item.name}</dt>
    <dd>{item.price}</dd>
  </Fragment>
))}

// 4. Fragment inside conditional JSX
{isLoggedIn ? (
  <>
    <span>Hi, Asha</span>
    <button>Log out</button>
  </>
) : (
  <button>Log in</button>
)}

5. Practical Example

A food-delivery bill: table rows from a component, a description list built with keyed fragments, and a header that returns two elements. In a Vite React app, replace src/App.jsx:

// src/App.jsx
import { Fragment, useState } from 'react';

const cart = [
  { id: 'b1', name: 'Veg Burger', qty: 2, price: 149 },
  { id: 'f1', name: 'Fries', qty: 1, price: 99 },
  { id: 'c1', name: 'Cola', qty: 2, price: 49 },
];

const offers = [
  { id: 'o1', code: 'FIRST50', text: '50% off first order' },
  { id: 'o2', code: 'FREEDEL', text: 'Free delivery above ₹300' },
];

// Returns two sibling elements → fragment
function Header({ count }) {
  return (
    <>
      <h2>Your order</h2>
      <p>{count} items</p>
    </>
  );
}

// Returns several <td> for one <tr> → fragment keeps the table valid
function Cells({ item }) {
  return (
    <>
      <td>{item.name}</td>
      <td>{item.qty}</td>
      <td>₹{item.qty * item.price}</td>
    </>
  );
}

export default function App() {
  const [showOffers, setShowOffers] = useState(true);
  const total = cart.reduce((sum, i) => sum + i.qty * i.price, 0);

  return (
    <main style={{ fontFamily: 'sans-serif', padding: 16 }}>
      <Header count={cart.length} />

      <table>
        <tbody>
          {cart.map((item) => (
            <tr key={item.id}>
              <Cells item={item} />
            </tr>
          ))}
        </tbody>
      </table>
      <p><strong>Total: ₹{total}</strong></p>

      <button onClick={() => setShowOffers(!showOffers)}>
        {showOffers ? 'Hide offers' : 'Show offers'}
      </button>

      {showOffers && (
        <dl>
          {/* Each offer = one <dt> + one <dd>. Key goes on the Fragment. */}
          {offers.map((o) => (
            <Fragment key={o.id}>
              <dt><code>{o.code}</code></dt>
              <dd>{o.text}</dd>
            </Fragment>
          ))}
        </dl>
      )}
    </main>
  );
}

7. Execution Flow

 1. Vite compiles  <><h2/><p/></>
      ──► jsxs(Fragment, { children: [ jsx("h2"), jsx("p") ] })
        │
        ▼
 2. Header() returns ONE value: a Fragment element holding 2 children
        │
        ▼
 3. React builds its tree:
        App
         └─ main
             ├─ Header
             │   └─ Fragment          ← exists only in React's tree
             │        ├─ h2
             │        └─ p
             └─ table ...
        │
        ▼
 4. react-dom writes to the DOM: Fragment is skipped,
    its children are inserted straight into <main>
        │
        ▼
 5. On re-render, the key on <Fragment key={o.id}> tells React
    which dt/dd pair belongs to which offer

8. Real-World Application

  • Tables: a <Cells> or <Columns> component returning several <td>/<th>.
  • Description lists: product specs as <dt>/<dd> pairs in a keyed fragment.
  • Flex/grid layouts: a chat header returning avatar + name + status as direct flex children.
  • Layout pieces: a page component returning <Header/>, <main>, <Footer/> side by side.
  • Conditional groups: show "Edit" + "Delete" buttons together only for the todo's owner.

9. Common Mistakes

Mistake 1: Key on the short syntax

Wrong
{movies.map((m) => (
  <key={m.id}>        // syntax error
    <h3>{m.title}</h3>
    <p>{m.year}</p>
  </>
))}
Fixed
import { Fragment } from 'react';

{movies.map((m) => (
  <Fragment key={m.id}>
    <h3>{m.title}</h3>
    <p>{m.year}</p>
  </Fragment>
))}

Mistake 2: Unkeyed fragment in a list

Wrong
{movies.map((m) => (
  <>
    <h3>{m.title}</h3>
    <p>{m.year}</p>
  </>
))}
// Warning: Each child in a list should
// have a unique "key" prop.
Fixed
{movies.map((m) => (
  <Fragment key={m.id}>
    <h3>{m.title}</h3>
    <p>{m.year}</p>
  </Fragment>
))}

Mistake 3: Styling a fragment

Wrong
<Fragment className="card">
  <h3>Pasta</h3>
  <p>₹249</p>
</Fragment>
// Warning: Invalid prop `className`
// supplied to `React.Fragment`
Fixed
// Need a box? Use a real element.
<div className="card">
  <h3>Pasta</h3>
  <p>₹249</p>
</div>

Mistake 4: Forgetting the import for the long form

Wrong
// no import
<Fragment key={o.id}>...</Fragment>
// ReferenceError: Fragment is not defined
Fixed
import { Fragment } from 'react';
<Fragment key={o.id}>...</Fragment>

11. Quick Revision

  • A component returns one value; fragments group many elements into one.
  • Fragments add no DOM node.
  • <></> = short, no import, no key.
  • <Fragment key={id}> = long, import from 'react', allows key.
  • No className/style/events on fragments.
  • Use them for table cells, dt/dd pairs, flex/grid children.

12. Interview Corner

Why can't a component return two sibling elements directly?

JSX compiles to function calls. return jsx('h1') jsx('p') is not valid JavaScript — a function returns one value. A fragment wraps them into one value.

Fragment vs <div>?

A <div> is a real DOM node (stylable, clickable, affects layout and HTML validity). A fragment exists only in React's tree and leaves no trace in the DOM.

When must you use <Fragment> instead of <>?

When you need a key, typically inside .map().

What does <><A /><B /></> compile to?

With the automatic runtime: jsxs(Fragment, { children: [jsx(A, {}), jsx(B, {})] }), with jsxs and Fragment imported from react/jsx-runtime.

A. Concept in 30 Seconds

A component must return one thing. A fragment (<>...</> or <Fragment>) groups several elements into one without adding a DOM node. Use <Fragment key> in lists.

C. Must-Know Points

  • Fragments render no DOM element.
  • Short syntax needs no import and takes no attributes.
  • Long syntax: import { Fragment } from 'react'.
  • key is the only attribute you can give a fragment (long syntax).
  • Keep HTML valid: <tr> → <td>, <ul> → <li>, <dl> → <dt>/<dd>.
  • Fragments keep flex/grid items as direct children.
  • Arrays also work as return values but need keys on every item.
  • Compiles to the Fragment type from react/jsx-runtime.

D. Interview Questions

Basic

What is a fragment?

A wrapper that lets a component return several elements without adding an extra node to the DOM.

Intermediate

Can you attach an onClick to a fragment?

No. There is no DOM element to listen on. Use a real element, or put the handler on each child.

Advanced

Fragment vs returning an array?

Both give multiple children. Arrays need a key on every item and use commas; fragments use normal JSX and need no keys for static children.

Tricky

Does switching from <Child /> to <><Child /></> reset Child's state?

No — React's docs say it does not reset state for <Child /> ↔ <><Child /></> or ↔ [<Child />], but only one level deep. <><><Child /></></> ↔ <Child /> does reset it.

E. Output-Based Questions

How many DOM elements? <><li>Tea</li><li>Coffee</li></>

Two <li> elements. The fragment adds none.

What renders? return <></>;

Nothing visible. An empty fragment renders no DOM.

F. Debugging Questions

"Adjacent JSX elements must be wrapped in an enclosing tag."

You returned two siblings. Wrap them in <>...</>.

"Each child in a list should have a unique key" though items are fragments.

Short fragments can't take keys. Switch to <Fragment key={item.id}>.

Dev console warning: "In HTML, <div> cannot be a child of <tr>".

A component inside <tr> returns a <div> wrapper. Replace it with a fragment.

G. Scenario-Based Questions

A grid card component returns image + title + price, but the wrapper div breaks the grid.

Return a fragment so the three items become direct grid children — or keep the div and make it the grid item intentionally.

Each FAQ question needs a heading and an answer paragraph, rendered from an array.

faqs.map(f => <Fragment key={f.id}><h3>{f.q}</h3><p>{f.a}</p></Fragment>).
