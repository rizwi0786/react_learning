Conditional expressions

1. Visual Introduction

  • A shop sign: if open show "Open", else show "Closed". That is an either/or choice (a ternary: cond ? a : b).
  • A "Sale!" sticker: show it only if there is a sale, otherwise show nothing. That is a show-or-skip choice (logical AND: cond && a).
  • Inside JSX braces you can only put expressions (things that give a value), not statements like if. Ternary and && are expressions.
   Either / or  (ternary)                Show or skip  (&&)
   ──────────────────────                ───────────────────
   {isOpen ? <Open/> : <Closed/>}        {onSale && <SaleBadge/>}

        isOpen?                               onSale?
        /     \                               /     \
     true     false                        true     false
      │         │                            │        │
   <Open/>  <Closed/>                  <SaleBadge/>  false → renders nothing

   React renders nothing for:  null  undefined  false  true  ''
   React DOES render:          0  →  "0"        NaN  →  "NaN"

2. Why Do We Need It?

  • UIs change with data: logged in or not, loading or done, empty cart or full.
  • if cannot go inside JSX braces, so you need expression forms.
  • Without them you would duplicate the whole JSX block in two returns for one small difference.
Before
// if inside JSX → syntax error
function Status({ isOpen }) {
  return (
    <p>
      Shop is {if (isOpen) { 'open' } else { 'closed' }}
    </p>
  );
}

// Workaround: duplicate everything
function Status({ isOpen }) {
  if (isOpen) return <p>Shop is open</p>;
  return <p>Shop is closed</p>;
}
After
function Status({ isOpen, onSale }) {
  return (
    <p>
      Shop is {isOpen ? 'open' : 'closed'}
      {onSale && <strong> · Sale today!</strong>}
    </p>
  );
}

3. Core Concept

  • Ternary cond ? A : B → pick one of two things.
  • AND cond && A → if cond is truthy, the result is A; otherwise the result is cond itself.
  • That last part matters: if cond is 0, React renders "0". Use a real boolean: count > 0 && ....
  • React skips null, undefined, true, false and '' (empty string). It renders numbers, including 0 and NaN.
  • Fallback values: name || 'Guest' (any falsy) or name ?? 'Guest' (only null/undefined, called nullish coalescing).
  • For big branches, use if before the return, or return null early (early return).
  • Conditions work in attributes too: className={done ? 'done' : ''}, disabled={!ready}.
  • Avoid deeply nested ternaries — split into variables or small components.

4. Syntax

// 1. Ternary: either / or
{isLoggedIn ? <Profile /> : <LoginButton />}

// 2. Ternary with text
<p>{stock > 0 ? 'In stock' : 'Sold out'}</p>

// 3. AND: show or skip
{hasUnread && <span className="dot" />}

// 4. AND with a number: compare first!
{cart.length > 0 && <CartBadge count={cart.length} />}

// 5. Ternary with null = explicit "nothing"
{error ? <p className="error">{error}</p> : null}

// 6. Fallbacks
<h2>Hello, {user.name ?? 'Guest'}</h2>

// 7. Conditional attribute
<li className={todo.done ? 'done' : undefined}>{todo.text}</li>

// 8. Logic before return
let content;
if (loading) content = <Spinner />;
else if (error) content = <ErrorBox />;
else content = <WeatherCard data={data} />;
return <main>{content}</main>;

// 9. Early return
if (!movie) return null;

5. Practical Example

A chat inbox: unread badge, online status, empty state, and a "typing…" hint. Buttons let you change the data and watch the UI react. In a Vite React app, replace src/App.jsx:

// src/App.jsx
import { useState } from 'react';

function ChatRow({ chat }) {
  return (
    <li style={{ marginBottom: 8 }}>
      {/* Ternary: either green dot or grey dot */}
      <span style={{ color: chat.online ? 'green' : 'gray' }}>●</span>{' '}
      <strong>{chat.name}</strong>

      {/* AND with a comparison, so 0 never shows */}
      {chat.unread > 0 && <span> ({chat.unread} new)</span>}

      <br />
      <small>
        {chat.typing ? <em>typing…</em> : chat.lastMessage ?? 'No messages yet'}
      </small>
    </li>
  );
}

const startChats = [
  { id: 1, name: 'Asha', online: true, unread: 2, typing: false, lastMessage: 'See you at 7!' },
  { id: 2, name: 'Ravi', online: false, unread: 0, typing: false, lastMessage: null },
  { id: 3, name: 'Meera', online: true, unread: 0, typing: true, lastMessage: 'Ok' },
];

export default function App() {
  const [chats, setChats] = useState(startChats);
  const totalUnread = chats.reduce((sum, c) => sum + c.unread, 0);

  // Early return style for the empty state
  if (chats.length === 0) {
    return (
      <main style={{ fontFamily: 'sans-serif', padding: 16 }}>
        <p>No chats yet. Start a conversation!</p>
        <button onClick={() => setChats(startChats)}>Restore chats</button>
      </main>
    );
  }

  return (
    <main style={{ fontFamily: 'sans-serif', padding: 16 }}>
      <h2>
        Inbox {totalUnread > 0 ? `(${totalUnread} unread)` : '(all read)'}
      </h2>

      <ul style={{ listStyle: 'none', padding: 0 }}>
        {chats.map((c) => (
          <ChatRow key={c.id} chat={c} />
        ))}
      </ul>

      <button onClick={() => setChats(chats.map((c) => ({ ...c, unread: 0 })))}>
        Mark all read
      </button>{' '}
      <button onClick={() => setChats([])}>Clear chats</button>
    </main>
  );
}

8. Real-World Application

  • Food delivery: "Restaurant closed" banner via ternary; "Free delivery" tag via total >= 300 &&.
  • Shop: "Add to cart" vs "Notify me" button based on stock.
  • Weather: loading spinner → error message → weather card (if/else before return).
  • Movies: show "18+" badge only if movie.adult; show rating or "Not rated yet" with ??.
  • Todo app: "Nothing to do 🎉" empty state with early return; strike-through class with a ternary.

9. Common Mistakes

Mistake 1: A number on the left of &&

Wrong
{cart.length && <p>{cart.length} items</p>}
// empty cart → renders "0" on the page
Fixed
{cart.length > 0 && <p>{cart.length} items</p>}
// or: {!!cart.length && ...}
// or: {cart.length ? <p>...</p> : null}

Mistake 2: Using if inside JSX

Wrong
return (
  <div>
    {if (isVeg) { <span>🟢 Veg</span> }}
  </div>
);
// SyntaxError: Unexpected token
Fixed
return (
  <div>
    {isVeg && <span>🟢 Veg</span>}
  </div>
);

Mistake 3: || hiding a valid 0

Wrong
<p>Rating: {movie.rating || 'Not rated'}</p>
// rating 0 → "Not rated" (wrong)
Fixed
<p>Rating: {movie.rating ?? 'Not rated'}</p>
// only null / undefined → "Not rated"

Mistake 4: Nested ternary soup

Wrong
{loading ? <Spinner /> : error ? <Err />
  : data ? data.length ? <List /> : <Empty />
  : null}
Fixed
let body = null;
if (loading) body = <Spinner />;
else if (error) body = <Err />;
else if (data?.length) body = <List />;
else if (data) body = <Empty />;

return <section>{body}</section>;

Challenge

Build a weather widget with three states: loading, error, data. Use buttons to switch state. Show temperature, and "Carry an umbrella ☂️" only when rainChance >= 50.

Show solution 
import { useState } from 'react';

const sample = { city: 'Mumbai', temp: 29, rainChance: 70 };

export default function App() {
  const [status, setStatus] = useState('loading'); // 'loading' | 'error' | 'ok'

  let body;
  if (status === 'loading') body = <p>Loading…</p>;
  else if (status === 'error') body = <p style={{ color: 'crimson' }}>Could not load weather.</p>;
  else body = (
    <>
      <h3>{sample.city}: {sample.temp}°C</h3>
      {sample.rainChance >= 50 && <p>Carry an umbrella ☂️</p>}
    </>
  );

  return (
    <main>
      {body}
      <button onClick={() => setStatus('loading')}>Loading</button>
      <button onClick={() => setStatus('error')}>Error</button>
      <button onClick={() => setStatus('ok')}>Data</button>
    </main>
  );
}

11. Quick Revision

  • Only expressions go inside { } — no if, for, switch.
  • Either/or → cond ? A : B.
  • Show or skip → cond && A (keep cond a real boolean).
  • 0 and NaN render as text; null/undefined/true/false/'' render nothing.
  • Fallback: ?? for null/undefined, || for any falsy.
  • Many branches → if/else before return, or early return null.

12. Interview Corner

Why can't you use if inside JSX?

JSX braces accept expressions only. if is a statement. Use a ternary, &&, or move the if above the return.

Why does {count && <Badge />} show "0"?

&& returns its left side when it is falsy. 0 is a number, and React renders numbers. Use count > 0 && ....

What does a component returning null do?

It renders nothing to the DOM, but the component still exists and its hooks still run. Since React 18, returning undefined is also allowed.

|| vs ?? for defaults?

|| replaces any falsy value (0, '', false). ?? replaces only null/undefined — safer when 0 or empty string are valid.

A. Concept in 30 Seconds

JSX braces take expressions, not statements. Use cond ? A : B to choose, cond && A to show or skip, and ?? for fallbacks. Keep the left side of && boolean so 0 never appears. Bigger logic goes above the return.

B. Important Syntax

{ok ? <Yes /> : <No />}
{ok && <Yes />}
{list.length > 0 && <List />}
{name ?? 'Guest'}
className={on ? 'on' : undefined}
if (!data) return null;

C. Must-Know Points

  • Ternary = two branches; && = one branch or nothing.
  • a && b returns a when a is falsy.
  • Rendered as nothing: null, undefined, true, false, ''.
  • Rendered as text: 0, NaN, any number or non-empty string.
  • Use > 0, !!x or Boolean(x) before &&.
  • ?? keeps 0 and ''; || does not.
  • Early return null for "nothing to show".
  • Hooks must still be called before any early return (Rules of Hooks).
  • Conditions also work in attributes and style values.

D. Interview Questions

Basic

Two ways to conditionally render inside JSX?

Ternary (? :) and logical AND (&&).

Intermediate

When prefer if/else over a ternary?

When there are three or more branches, or each branch is large. Compute a variable before return.

Advanced

Can you return early before calling a hook?

No. Hooks must run in the same order every render. Call all hooks at the top, then do early returns.

Does hiding with && keep the child's state?

No. When the condition becomes false, the child is removed (unmounted) and its state is lost. Hiding with CSS keeps it mounted.

Tricky

What does {'' && <p>Hi</p>} render?

Nothing visible. The result is '', and an empty string renders no text.

F. Debugging Questions

An empty cart shows a lone "0" in the header.

{items.length && ...}. Change to items.length > 0 && ....

"Rendered fewer hooks than expected" after adding if (!user) return null;.

The early return sits above a useState/useEffect call. Move all hooks above the early return.

Price 0 (free item) shows "Price unavailable".

price || 'Price unavailable' treats 0 as missing. Use ??.

G. Scenario-Based Questions

A product page shows "Add to cart" if in stock, "Notify me" if not, and a "Low stock" warning if stock < 5. 
{stock > 0 ? <AddToCart /> : <NotifyMe />}
{stock > 0 && stock < 5 && <p>Only {stock} left!</p>}
A chat input draft should survive when the user toggles the emoji panel.

Conditionally render only the emoji panel, not the input. If a panel's own state must survive, keep it mounted and hide it with CSS or the hidden attribute.
