Rendering lists

1. Visual Introduction

  • Think of a food-delivery menu. The kitchen has a list of dishes (data). The menu card prints one row per dish (UI).
  • In React you turn an array of data into an array of elements with .map() (the array map method).
  • Each row gets a name tag so React can tell rows apart when the list changes (the key prop).
  DATA (array of objects)                 UI (array of elements)
  ┌──────────────────────────┐            ┌──────────────────────────────┐
  │ { id: 'p1', name: Pizza }│ ──map──►   │ <li key="p1">Pizza</li>      │
  │ { id: 'b2', name: Burger}│ ──map──►   │ <li key="b2">Burger</li>     │
  │ { id: 'd3', name: Dosa  }│ ──map──►   │ <li key="d3">Dosa</li>       │
  └──────────────────────────┘            └──────────────────────────────┘
                                                    │
         key = name tag React uses to match ────────┘
         "same row before" with "same row after"

2. Why Do We Need It?

  • Real data comes as arrays: products, messages, movies, todos.
  • Writing one <li> by hand per item does not scale, and the count changes at runtime.
  • Keys let React update only the changed rows (the reconciliation step) and keep each row's state with the right item.
Before (hard-coded)
function Menu() {
  return (
    <ul>
      <li>Pizza - ₹299</li>
      <li>Burger - ₹149</li>
      <li>Dosa - ₹99</li>
    </ul>
  );
}
// New dish? Edit the JSX by hand.
// 200 dishes from an API? Impossible.
After (map + key)
const dishes = [
  { id: 'p1', name: 'Pizza', price: 299 },
  { id: 'b2', name: 'Burger', price: 149 },
  { id: 'd3', name: 'Dosa', price: 99 },
];

function Menu() {
  return (
    <ul>
      {dishes.map((d) => (
        <li key={d.id}>{d.name} - ₹{d.price}</li>
      ))}
    </ul>
  );
}
// Any number of dishes, zero JSX changes.

3. Core Concept

  • JSX can render an array of elements placed inside { }.
  • array.map(item => <Row />) returns a new array of elements.
  • Every element in that array needs a key prop.
  • Key must be unique among siblings (same list), not across the whole app.
  • Key must be stable: the same item gets the same key on every render. Best source: an id from your data.
  • Array index as key is OK only for a list that never reorders, filters, or inserts.
  • Never use Math.random() or crypto.randomUUID() during render as a key: new key each render = React throws away and rebuilds every row.
  • key is read by React, not passed to your component (props.key is undefined). Pass the id again as another prop if the child needs it.
  • The key goes on the outermost element returned from map.
  • Need several elements per item? Use <Fragment key={...}>. The short <> syntax cannot take a key.
  • Filter first, then map: items.filter(...).map(...).

4. Syntax

// 1. Basic map with key
<ul>
  {todos.map((todo) => (
    <li key={todo.id}>{todo.text}</li>
  ))}
</ul>

// 2. Map to a component (key on the component)
{movies.map((m) => <MovieCard key={m.id} movie={m} />)}

// 3. Build the array first, then render it
const rows = products.map((p) => <tr key={p.sku}><td>{p.name}</td></tr>);
return <tbody>{rows}</tbody>;

// 4. Filter, then map
{orders
  .filter((o) => o.status === 'delivered')
  .map((o) => <li key={o.id}>{o.dish}</li>)}

// 5. Several elements per item: keyed Fragment
import { Fragment } from 'react';
{glossary.map((g) => (
  <Fragment key={g.term}>
    <dt>{g.term}</dt>
    <dd>{g.meaning}</dd>
  </Fragment>
))}

// 6. Index as key (static list only)
{['Mon', 'Tue', 'Wed'].map((day, i) => <th key={i}>{day}</th>)}

5. Practical Example

A tiny todo list: add items, tick them off, and remove them. Each row keeps its own checkbox state correctly because keys come from ids.

// src/App.jsx  (Vite + React 19)
import { useState } from 'react';

let nextId = 4;

const starterTodos = [
  { id: 1, text: 'Order groceries', done: false },
  { id: 2, text: 'Book movie tickets', done: true },
  { id: 3, text: 'Check weather for trip', done: false },
];

function TodoItem({ todo, onToggle, onRemove }) {
  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={todo.done}
          onChange={() => onToggle(todo.id)}
        />{' '}
        {todo.done ? <s>{todo.text}</s> : todo.text}
      </label>{' '}
      <button onClick={() => onRemove(todo.id)}>Remove</button>
    </li>
  );
}

export default function App() {
  const [todos, setTodos] = useState(starterTodos);
  const [text, setText] = useState('');

  function addTodo(e) {
    e.preventDefault();
    if (!text.trim()) return;
    setTodos([{ id: nextId++, text, done: false }, ...todos]);
    setText('');
  }

  function toggle(id) {
    setTodos(todos.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
  }

  function remove(id) {
    setTodos(todos.filter((t) => t.id !== id));
  }

  const left = todos.filter((t) => !t.done).length;

  return (
    <main>
      <h1>My Todos</h1>
      <form onSubmit={addTodo}>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <button>Add</button>
      </form>

      {todos.length === 0 ? (
        <p>Nothing to do. Enjoy your day!</p>
      ) : (
        <ul>
          {todos.map((todo) => (
            <TodoItem
              key={todo.id}
              todo={todo}
              onToggle={toggle}
              onRemove={remove}
            />
          ))}
        </ul>
      )}

      <p>{left} of {todos.length} left</p>
    </main>
  );
}
Run with npm create vite@latest my-app -- --template react, replace src/App.jsx, then npm run dev.

7. Execution Flow

 1. App renders → todos = [1, 2, 3]
        │
 2. todos.map(...) → [ <TodoItem key=1/>, <TodoItem key=2/>, <TodoItem key=3/> ]
        │
 3. React mounts 3 <li> rows in the DOM
        │
 4. User adds "Pay bill" → setTodos([4, 1, 2, 3])
        │
 5. App re-renders → map gives keys [4, 1, 2, 3]
        │
 6. React compares OLD keys vs NEW keys
        │   old: 1  2  3
        │   new: 4  1  2  3
        │   key 4 → new   → CREATE one <li>
        │   keys 1,2,3   → SAME rows, just moved down → keep DOM + state
        ▼
 7. DOM: one <li> inserted at top. Nothing else rebuilt.

 With index keys instead:  old 0 1 2  →  new 0 1 2 3
 React thinks row 0 changed text, row 1 changed text ... and a NEW row 3.
 Any state inside rows (typed text, focus) stays at the OLD position → wrong item.

8. Real-World Application

  • Shopping cart: cart.map(item => <CartRow key={item.sku} />).
  • Chat app: messages keyed by message id; new messages append without re-drawing old ones.
  • Movie search: results keyed by movie id; sorting by rating moves rows instead of rebuilding them.
  • Weather: 7-day forecast keyed by date string ("2026-11-05").
  • Food delivery: restaurant list → each restaurant card → its own dish list (nested maps, each with its own keys).

9. Common Mistakes

Mistake 1: No key

Wrong
{movies.map((m) => (
  <li>{m.title}</li>
))}
// Dev warning: Each child in a list
// should have a unique "key" prop.
Fixed
{movies.map((m) => (
  <li key={m.id}>{m.title}</li>
))}

Mistake 2: Key on the wrong element

Wrong
function Row({ dish }) {
  return <li key={dish.id}>{dish.name}</li>;
}
{dishes.map((d) => <Row dish={d} />)}
// Key inside Row is useless here;
// the array element is <Row>.
Fixed
function Row({ dish }) {
  return <li>{dish.name}</li>;
}
{dishes.map((d) => <Row key={d.id} dish={d} />)}

Mistake 3: Curly braces with no return

Wrong
{todos.map((t) => {
  <li key={t.id}>{t.text}</li>;
})}
// Renders nothing: block body
// returns undefined.
Fixed
{todos.map((t) => (
  <li key={t.id}>{t.text}</li>
))}
// or: (t) => { return <li ...>; }

Mistake 4: Random key

Wrong
{chats.map((c) => (
  <ChatRow key={Math.random()} chat={c} />
))}
// Every render: new keys → every row
// unmounts + remounts, state lost.
Fixed
{chats.map((c) => (
  <ChatRow key={c.id} chat={c} />
))}
// No id in data? Add one when the data
// is created, not during render.

Mistake 5: Reading props.key

Wrong
function Card(props) {
  return <p>#{props.key}</p>; // undefined
}
Fixed
<Card key={p.id} id={p.id} />
function Card({ id }) {
  return <p>#{id}</p>;
}

Challenge

Build a chat box: a list of messages and an input. Each message row has its own "Reply" text box. Add a "Reverse order" button. Prove (by typing in a reply box, then reversing) that id keys keep the typed text with the right message and index keys do not.

Show solution 
import { useState } from 'react';

function MessageRow({ msg }) {
  const [reply, setReply] = useState('');
  return (
    <li>
      <b>{msg.from}:</b> {msg.text}{' '}
      <input
        placeholder="Reply..."
        value={reply}
        onChange={(e) => setReply(e.target.value)}
      />
    </li>
  );
}

const start = [
  { id: 'm1', from: 'Asha', text: 'Lunch at 1?' },
  { id: 'm2', from: 'Ravi', text: 'Pizza or biryani?' },
  { id: 'm3', from: 'Meera', text: 'Running late' },
];

export default function App() {
  const [messages, setMessages] = useState(start);
  const [useIndex, setUseIndex] = useState(false);

  return (
    <div>
      <button onClick={() => setMessages([...messages].reverse())}>
        Reverse order
      </button>
      <label>
        <input
          type="checkbox"
          checked={useIndex}
          onChange={(e) => setUseIndex(e.target.checked)}
        />
        Use index as key (buggy)
      </label>
      <ul>
        {messages.map((m, i) => (
          <MessageRow key={useIndex ? i : m.id} msg={m} />
        ))}
      </ul>
    </div>
  );
}
// Type "Yes!" next to Asha, click Reverse.
// id keys:    "Yes!" moves with Asha's message (now at bottom).
// index keys: "Yes!" stays in row 0, now next to Meera's message.

11. Quick Revision

  • Lists: {items.map(item => <El key={item.id} />)}.
  • Keys: unique among siblings, stable across renders.
  • Best key = id from data. Index only for static lists.
  • Never generate keys during render (Math.random()).
  • Key goes on the outermost element in the map callback.
  • key is not a readable prop; pass ids separately.
  • Multiple elements per item → <Fragment key>.

12. Interview Corner

Why does React need keys in lists?

To match each element from the previous render with the same item in the next render. With a stable key, React can move, insert, or remove only the rows that changed and keep each row's state and DOM attached to the right item.

When is the array index acceptable as a key?

When the list is static: never reordered, filtered, or inserted into, and rows hold no state. It is also React's fallback when you give no key, which is why missing keys and index keys behave the same.

Do keys need to be globally unique?

No. Only unique among siblings in the same array. Two different lists can both use key 1.

What happens if you change an element's key?

React treats it as a different element: the old one unmounts (state lost) and a new one mounts. This is sometimes used on purpose to reset a component, e.g. <Profile key={userId} />.

Can a component read its own key?

No. key is consumed by React and not passed in props. Pass the value again under another prop name.

A. Concept in 30 Seconds

  • Turn an array of data into UI with .map().
  • Give each element a key: a stable, sibling-unique id (the key prop).
  • Keys let React match old and new rows (reconciliation) so updates are fast and state stays with the right item.
One line: {list.map(x => <Row key={x.id} {...x} />)}

B. Important Syntax

{items.map((it) => <li key={it.id}>{it.name}</li>)}
{items.map((it) => <Card key={it.id} item={it} />)}
{items.filter(f).map((it) => <li key={it.id}>...</li>)}
{items.map((it) => <Fragment key={it.id}><dt/><dd/></Fragment>)}
{days.map((d, i) => <th key={i}>{d}</th>)}   // static only

C. Must-Know Points

  1. JSX renders arrays of elements directly.
  2. map returns a new array; forEach returns undefined (renders nothing).
  3. Missing key → dev-only console warning; app still renders.
  4. Duplicate keys → dev warning "Encountered two children with the same key"; rows may duplicate or vanish on update.
  5. Keys unique among siblings only.
  6. Keys must be stable: no Math.random(), no Date.now() in render.
  7. Index keys break when the list is reordered, filtered or prepended and rows have state.
  8. key is not available as props.key.
  9. <> cannot take a key; use <Fragment key>.
  10. Changing a key forces a remount (useful to reset state).

D. Interview Questions

Basic

How do you render a list in React?

Call .map() on the array inside JSX braces and return an element per item with a key.

What is a key?

A special string or number prop that identifies an element among its siblings so React can track it between renders.

Intermediate

Why are index keys risky?

The index describes position, not identity. After insert/reorder, the same index points to a different item, so React reuses the wrong component instance and its state (e.g. typed input) shows next to the wrong data.

Where should the key go when mapping to a component?

On the component element in the map: <Row key={x.id} />, not on the element inside Row.

Advanced

How can keys reset a component's state on purpose?

Render <ChatWindow key={contactId} />. When contactId changes, React unmounts the old instance and mounts a fresh one, clearing its state (e.g. a draft message).

Your data has no id. What do you do?

Create ids when the data is created or loaded (e.g. crypto.randomUUID() when adding the item, or a counter) and store them with the item. Do not create them during render.

Tricky

Does a missing key throw an error?

No. It logs a warning in development only and falls back to index behaviour. Production builds print nothing.

Can two separate lists in the same component share keys?

Yes. Uniqueness is only required among siblings of one array.

E. Output-Based Questions

Q1. What renders?

const nums = [1, 2, 3];
return <ul>{nums.forEach((n) => <li key={n}>{n}</li>)}</ul>;
Show answer

An empty <ul>. forEach returns undefined, which renders nothing.

Q2. What renders?

return <p>{['a', 'b', 'c']}</p>;
Show answer

abc. Arrays of strings render as text. Only elements need keys; plain strings in an array do not trigger the warning.

Q3. How many times is "row" logged on first load?

{[1, 2, 3].map((n) => { console.log('row'); return <li key={n}>{n}</li>; })}
Show answer

3 in production. In development with <StrictMode> the component renders twice, so the logs run twice (React 19 dims the second set in the console).

F. Debugging Questions

Q1. The list shows nothing. Why?

{cart.map((item) => {
  <CartRow key={item.sku} item={item} />
})}
Show answer

Block body with no return. Use (item) => (<CartRow ... />) or add return.

Q2. After deleting the first todo, the checkbox ticks jump to the wrong row.

Keys are the index and checkbox state lives inside each row. Use key={todo.id}.

Q3. Error: "Cannot read properties of undefined (reading 'map')".

The array is undefined (data not loaded yet, or wrong field name). Default it: useState([]), or guard with (items ?? []).map(...).

G. Scenario-Based Questions

A movie list can be sorted by rating or year. What key do you use?

The movie's id from the API. Sorting reorders, so index keys would mis-match rows.

A weather app shows 7 days. No ids from the API.

The date string (e.g. "2026-11-05") is unique per day and stable: use it.

Chat messages: duplicate key warning appears.

Two messages share an id (e.g. message sent optimistically and then received from the server). De-duplicate by id before rendering or use a temporary client id until the server id arrives.

1. Price list with total

Render a cart and its total price.

Solution 
function Cart({ items }) {
  const total = items.reduce((sum, i) => sum + i.price * i.qty, 0);
  return (
    <>
      <ul>
        {items.map((i) => (
          <li key={i.id}>{i.name} × {i.qty} = ₹{i.price * i.qty}</li>

}

2. Group by category

Given dishes with category, render one heading per category with its dishes.

Solution 
function GroupedMenu({ dishes }) {
  const groups = Object.groupBy(dishes, (d) => d.category);
  return Object.entries(groups).map(([cat, list]) => (
    <section key={cat}>
      <h3>{cat}</h3>
      <ul>
        {list.map((d) => <li key={d.id}>{d.name}</li>)}
      </ul>
    </section>
  ));
}
// Object.groupBy is ES2024 (modern browsers). Older targets: use reduce.
