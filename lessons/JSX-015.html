JSX restrictions

1. Visual Introduction

  • A food-delivery order goes out in one bag. You cannot hand the rider three loose boxes; you put them in one bag first.
  • A component's return is the same: it must give back one thing (the single-root rule).
  • JSX looks like HTML but is really JavaScript, so it follows stricter rules: every tag closed, some words renamed (reserved words), attributes in camelCase.
   return (                         return (
     <h1>Menu</h1>     ✗              <>                 ✓  one "bag"
     <ul>...</ul>                      <h1>Menu</h1>         (Fragment)
   );                                   <ul>...</ul>
                                      </>
   two loose boxes                  );
   → compile error                  → one value returned

   Why? JSX compiles to a function call:
   jsxs(Fragment, { children: [ jsx('h1', ...), jsx('ul', ...) ] })
   A function can return only ONE value.

2. Why Do We Need It?

  • Knowing the rules turns red compile errors into a 5-second fix.
  • HTML is forgiving (it auto-closes <br>, <li>). JSX is not: it is parsed as JavaScript.
  • Words like class and for already mean something in JavaScript, so JSX uses className and htmlFor.
Before (HTML habits)
function WeatherCard() {
  return (
    <h2 class="title">Delhi</h2>
    <img src="sun.png">
    <p>Sunny, 31°C<br>Humidity 40%
    <label for="unit">Unit</label>
    <input id="unit" onclick="toggle()">
  );
}
// Compile error: adjacent JSX elements
// + unclosed <img>, <br>, <p>, <input>
After (JSX rules)
function WeatherCard({ onToggle }) {
  return (
    <section>
      <h2 className="title">Delhi</h2>
      <img src="/sun.png" alt="Sunny" />
      <p>Sunny, 31°C<br />Humidity 40%</p>
      <label htmlFor="unit">Unit</label>
      <input id="unit" onClick={onToggle} />
    </section>
  );
}

3. Core Concept

  • One root: return one element. Wrap siblings in a <div> or a <>...</> (Fragment, adds no DOM node).
  • Close every tag: <p>...</p>, and empty ones self-close: <img />, <br />, <input />, <hr />.
  • Any element can self-close in JSX: <div /> is fine.
  • Reserved words: class → className, for → htmlFor.
  • camelCase attributes: onclick → onClick, tabindex → tabIndex, maxlength → maxLength.
  • Exceptions keep dashes: aria-label, data-id.
  • Events take functions, not strings: onClick={handleClick}.
  • style takes an object: style={{ color: 'red' }}.
  • Braces hold expressions only (something that gives a value). No if, for or const inside { }; use ternary, &&, map.
  • Comments inside JSX: {/* like this */}. HTML comments <!-- --> are an error.
  • Component names start with a capital: <Cart />. Lowercase = treated as an HTML tag.
  • Objects cannot be rendered as children; true, false, null, undefined render nothing.

5. Practical Example

A restaurant card that follows every JSX rule. Each rule is marked in a comment.

// src/App.jsx  (Vite + React 19)
import { useState } from 'react';

function RestaurantCard({ name, rating, isOpen, dishes }) {
  const [qty, setQty] = useState(1);

  // Statements (if/const) go ABOVE the return, not inside JSX
  let badge = null;
  if (rating >= 4.5) {
    badge = <span className="badge">Top rated</span>;
  }

  return (
    // Rule: one root element
    <article className="card" data-restaurant={name}>
      {/* Rule: comments use braces */}
      <h2>
        {name} {badge}
      </h2>

      {/* Rule: self-close empty tags */}
      <img src="/thali.jpg" alt={name + ' thali'} width={120} />
      <hr />

      {/* Rule: expressions only (ternary, not if) */}
      <p style={{ color: isOpen ? 'green' : 'crimson' }}>
        {isOpen ? 'Open now' : 'Closed'}
      </p>

      <ul>
        {dishes.map((d) => (
          <li key={d}>{d}</li>
        ))}
      </ul>

      {/* Rule: htmlFor + camelCase attributes */}
      <label htmlFor="qty">Plates: </label>
      <input
        id="qty"
        type="number"
        min={1}
        max={20}
        value={qty}
        onChange={(e) => setQty(Number(e.target.value))}
      />

      {/* Rule: events take a function, aria-* keeps dashes */}
      <button
        aria-label={'Add ' + qty + ' plates to cart'}
        disabled={!isOpen}
        onClick={() => alert(`Added ${qty} × ${name}`)}
      >
        Add to cart
      </button>
    </article>
  );
}

export default function App() {
  // Rule: Fragment when you need siblings without a wrapper div
  return (
    <>
      <h1>Order Food</h1>
      <RestaurantCard
        name="Spice Garden"
        rating={4.6}
        isOpen={true}
        dishes={['Paneer Tikka', 'Dal Makhani', 'Butter Naan']}
      />
    </>
  );
}

7. Execution Flow

 1. You write JSX in App.jsx
        │
 2. Vite's React plugin compiles it (automatic JSX runtime)
        │   <><h1/><Card/></>
        │      ↓
        │   jsxs(Fragment, { children: [jsx('h1',..), jsx(Card,..)] })
        │
        ├── Two roots without a wrapper? → parse error, page shows error overlay
        ├── Unclosed <img>?             → parse error
        ├── <!-- comment -->?            → parse error
        │
 3. Code runs in the browser → React gets element objects
        │   'h1'  (lowercase)  → real HTML tag
        │   Card  (Capital)    → call your component function
        │
 4. React DOM maps props to DOM
        │   className → class   htmlFor → for   onClick → click listener
        │   style object → inline CSS   aria-* / data-* → copied as-is
        │
 5. Browser paints the card. Fragment adds no node.

8. Real-World Application

  • Table rows: a component that returns two <td> must use a Fragment; a <div> inside <tr> is invalid HTML.
  • Copy-pasting HTML templates (e.g. a shop landing page): convert class, for, inline style strings, and unclosed tags.
  • Accessible buttons: icon-only buttons in a chat app use aria-label (dashes kept).
  • Analytics tags: data-product-id attributes for click tracking work unchanged.
  • Forms: delivery-address inputs need htmlFor, maxLength, autoComplete, readOnly.

9. Common Mistakes

Mistake 1: Two roots

Wrong
function Movie() {
  return (
    <h2>Inception</h2>
    <p>2010 · Sci-fi</p>
  );
}
// Adjacent JSX elements must be wrapped
// in an enclosing tag.
Fixed
function Movie() {
  return (
    <>
      <h2>Inception</h2>
      <p>2010 · Sci-fi</p>
    </>
  );
}

Mistake 2: Unclosed void tags

Wrong
<form>
  <input type="email">
  <br>
  <img src="/logo.png">
</form>
// Expected corresponding JSX closing
// tag for <input>
Fixed
<form>
  <input type="email" />
  <br />
  <img src="/logo.png" alt="Shop logo" />
</form>

Mistake 3: HTML attribute names

Wrong
<label class="lbl" for="city">City</label>
<input id="city" tabindex="1"
       onchange="save()" />
// Dev warnings: Invalid DOM property
// `class`. Did you mean `className`?
// onchange string is not a function
Fixed
<label className="lbl" htmlFor="city">City</label>
<input id="city" tabIndex={1}
       onChange={save} />

Mistake 4: Statement inside braces

Wrong
<p>
  {if (stock > 0) { 'In stock' }}
</p>
// Unexpected token (syntax error)
Fixed
<p>
  {stock > 0 ? 'In stock' : 'Sold out'}
</p>

Mistake 5: HTML comment

Wrong
<div>
  <!-- Offer banner -->
  <Banner />
</div>
Fixed
<div>
  {/* Offer banner */}
  <Banner />
</div>

11. Quick Revision

  • Return one root: wrap in <div> or <></>.
  • Close every tag; void tags self-close (<img />).
  • class → className, for → htmlFor.
  • camelCase attributes and events; aria-*/data-* keep dashes.
  • Events = functions; style = object.
  • Braces hold expressions, never statements.
  • Comments: {/* */}. Components start with a capital.

12. Interview Corner

Why must a component return a single root element?

JSX compiles to a function call that creates one element object. A function returns one value, so two siblings must be wrapped in a parent element or Fragment (or returned as an array with keys).

Why className instead of class?

class is a reserved word in JavaScript, and React follows the DOM property name element.className. React DOM writes it out as the class attribute.

Fragment vs <div> wrapper?

A Fragment groups children without adding a DOM node. Use it when an extra div would break layout (flex/grid) or HTML rules (inside <tr>, <ul>). Use a div when you need styling or a ref on the wrapper.

Why can't you use if inside JSX braces?

Braces accept JavaScript expressions (things that produce a value). if is a statement. Use a ternary, &&, or compute the value above the return.

B. Important Syntax

<div className="x">  <label htmlFor="id">  // reserved words

C. Must-Know Points

  1. Single root per return; Fragment adds no DOM node.
  2. <> takes no props; <Fragment key> takes only key.
  3. Every tag must close; any element may self-close.
  4. class/for only give a dev warning (no crash), but always use className/htmlFor.
  5. Most attributes are camelCase; aria-* and data-* are exceptions.
  6. Event handlers must be functions, not strings.
  7. style must be an object with camelCase keys; numbers mean px for most properties.
  8. Expressions only inside braces.
  9. Lowercase tag = HTML element; Capitalised = component.
  10. Objects are not valid children; booleans, null, undefined render nothing.

D. Interview Questions

Basic

Name three differences between JSX and HTML.

className vs class; all tags must be closed; camelCase attributes and function event handlers; style as object.

What is a Fragment?

A wrapper (<>...</> or <Fragment>) that groups children without adding a DOM element.

Intermediate

Why do aria-label and data-id keep dashes?

React passes aria-* and data-* attributes straight to the DOM as written; they have no camelCase DOM property mapping.

How do you return siblings without a wrapper and without a Fragment?

Return an array with keys: return [<li key="a">A</li>, <li key="b">B</li>];. Fragments are usually cleaner.

Advanced

Why does <myCard /> not call your component?

The compiler treats lowercase tag names as strings (jsx('myCard')), i.e. an HTML element. Capitalised names compile to a variable reference (jsx(MyCard)).

Can you write <Fragment className="x">?

No. Fragment accepts only key (and children). There is no DOM node to put a class on.

Tricky

Is <div /> valid JSX?

Yes. Any element can self-close in JSX. React DOM renders <div></div>.

Does class crash a React app?

No. React logs a development warning ("Invalid DOM property `class`. Did you mean `className`?") and still applies it, but it is wrong practice and lint tools flag it.

E. Output-Based Questions

Q1. What DOM is produced?

return <><h1>Hi</h1><p>Bye</p></>;
Show answer

<h1>Hi</h1><p>Bye</p> directly inside the parent. No wrapper element.

Q2. What shows on screen?

<p>{true}{null}{undefined}{false}Done</p>
Show answer

Only Done. Booleans, null and undefined render nothing.

Q3. What happens?

<p>{ { city: 'Pune' } }</p>
Show answer

Runtime error: "Objects are not valid as a React child (found: object with keys {city})". Render {data.city} instead.

F. Debugging Questions

Q1. Compile error: "Expected corresponding JSX closing tag for <p>".

<p>Total: ₹450
</div>
Show answer

The <p> was never closed before </div>. Add </p>.

Q2. The button does nothing and the console warns about a string listener.

<button onClick="placeOrder()">Order</button>
Show answer

Pass a function: onClick={placeOrder}. React 19 warns: "Expected `onClick` listener to be a function, instead got a value of `string` type."

Q3. Style crashes the app.

<p style="color: red">Sold out</p>
Show answer

Error: "The `style` prop expects a mapping from style properties to values, not a string." Use style={{ color: 'red' }}.

G. Scenario-Based Questions

A designer gives you an HTML snippet for a product card. What do you change?

Close void tags, class→className, for→htmlFor, inline style strings→objects, event strings→functions, HTML comments→{/* */}, then wrap in one root.

A flex row breaks because your component adds an extra div.

Return a Fragment instead of a div so the children become direct flex items.

A table component returns <div><td/><td/></div> and the browser warns about invalid nesting.

Replace the div with a Fragment. React DOM warns in dev: "In HTML, <div> cannot be a child of <tr>."

function Glossary({ terms }) {
  return (

  );
}
