Common JSX errors

1. Visual Introduction

  • Think of a shop order going wrong at two points: the order form is filled badly (rejected at the counter), or the delivery fails on the road.
  • JSX errors work the same way. Some are caught while Vite compiles your file (compile-time / syntax errors). Others only appear when the code runs in the browser (runtime errors).
  • A third group are warnings: the app works but React tells you, in development only, that something is wrong.
  App.jsx ──► [ COMPILE ]  ──► [ RUN in browser ] ──► [ React DEV checks ]
                 │                    │                       │
         Syntax errors          Runtime errors           Warnings (dev only)
         red Vite overlay       red overlay / blank      yellow/red console text
         page won't load        part of the app breaks   app still works
                 │                    │                       │
   • two roots             • object as child          • missing key
   • unclosed tag          • x is undefined (.map)    • class / for
   • if inside { }         • too many re-renders      • unknown lowercase tag
   • JSX in .js file       • style as string          • onClick is a string

2. Why Do We Need It?

  • Beginners lose hours on a handful of repeated errors.
  • Most React error messages already tell you the fix if you know how to read them.
  • Knowing compile vs runtime vs warning tells you where to look: your syntax, your data, or your habits.
Before (guessing)
// Screen is blank. Console:
// Uncaught Error: Objects are not valid
// as a React child (found: object with
// keys {name, price}).
//
// Beginner: "React is broken?"
// Deletes code until it works...
After (reading the message)
// "Objects are not valid as a React child"
// → I put an object inside { }.
// "keys {name, price}" → it's a dish object.
// Fix:
<p>{dish.name} - ₹{dish.price}</p>
// Done in 10 seconds.

3. Core Concept

  • Read the first line of the error and the file:line it points to.
  • Compile errors (Vite error overlay): broken JSX syntax. Nothing runs until fixed.
  • Runtime errors: syntax is fine but a value is wrong (undefined, object, function).
  • Warnings: printed in development builds only; production builds strip them.
  • Exact compile-error wording depends on the tool (Vite 8 uses Oxc via the React plugin; Babel and ESLint word things slightly differently). The meaning is the same.
  • Top 10 to know:
    1. Adjacent JSX elements (two roots)
    2. Unclosed tag / mismatched closing tag
    3. Statement (if, for) inside { }
    4. JSX inside a .js file (Vite)
    5. Objects are not valid as a React child
    6. Functions are not valid as a React child
    7. Cannot read properties of undefined (reading 'map')
    8. Too many re-renders (onClick={fn()})
    9. style given a string
    10. Lowercase component name
  • Silent bugs (no error at all): {count && ...} showing 0; arrow function with { } and no return.

4. Syntax

// ---------- The 10 fixes at a glance ----------
// 1. Two roots          → wrap
return <><h1 /><p /></>;

// 2. Unclosed tag       → close it
<input />  <li>Tea</li>

// 3. if inside JSX      → ternary / &&
{isVeg ? 'Veg' : 'Non-veg'}

// 4. JSX in .js         → rename the file
App.js  →  App.jsx

// 5. Object as child    → pick a field
{user.name}            // not {user}

// 6. Function as child  → call it as a component
<Header />             // not {Header}

// 7. undefined.map      → default value
const [movies, setMovies] = useState([]);

// 8. Too many re-renders → pass a function
onClick={() => setQty(qty + 1)}   // not onClick={setQty(qty + 1)}

// 9. style string       → style object
style={{ color: 'red' }}

// 10. lowercase name    → Capitalise
function CartBadge() {}  <CartBadge />

5. Practical Example

A movie watch-list with every classic bug fixed. Bug numbers in the comments match the list above.

// src/App.jsx  (file must end in .jsx — bug 4)
import { useState, useEffect } from 'react';

// Bug 10: component names start with a capital letter
function MovieRow({ movie, onRemove }) {
  return (
    <li>
      {/* Bug 5: render fields, not the whole object */}
      {movie.title} ({movie.year}) · ⭐ {movie.rating}{' '}
      {/* Bug 8: pass a function, don't call it */}
      <button onClick={() => onRemove(movie.id)}>Remove</button>
    </li>
  );
}

function Header() {
  return <h1>My Watch-list</h1>;
}

export default function App() {
  // Bug 7: start with [] so .map never runs on undefined
  const [movies, setMovies] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // Fake API: data arrives after 1 second
    const timer = setTimeout(() => {
      setMovies([
        { id: 1, title: 'Inception', year: 2010, rating: 8.8 },
        { id: 2, title: 'Lagaan', year: 2001, rating: 8.1 },
        { id: 3, title: 'Up', year: 2009, rating: 8.3 },
      ]);
      setLoading(false);
    }, 1000);
    return () => clearTimeout(timer);
  }, []);

  function remove(id) {
    setMovies(movies.filter((m) => m.id !== id));
  }

  // Bug 1: one root (Fragment)
  return (
    <>
      {/* Bug 6: render the component, not the function */}
      <Header />

      {/* Bug 3: ternary instead of if */}
      {loading ? (
        <p>Loading movies...</p>
      ) : (
        <ul>
          {movies.map((m) => (
            <MovieRow key={m.id} movie={m} onRemove={remove} />
          ))}
        </ul>
      )}

      {/* Silent bug: 0 && ... would print "0". Compare to a boolean. */}
      {!loading && movies.length === 0 && <p>List is empty.</p>}

      {/* Bug 9: style is an object. Bug 2: every tag closed. */}
      <p style={{ color: 'gray', fontSize: 13 }}>
        {movies.length} movies saved
        <br />
        Tip: open the console to see warnings in dev mode.
      </p>
    </>
  );
}

8. Real-World Application

  • Weather app: API returns { temp, city }; rendering {data} crashes. Render {data.temp}.
  • Shop product page: products load after a fetch; products.map on undefined crashes until you default to [].
  • Chat app: unread badge {unread && <Badge />} shows a stray 0; use unread > 0 &&.
  • Food delivery cart: onClick={addItem(dish)} adds on every render → "Too many re-renders".
  • Migrating an old CRA project to Vite: .js files with JSX must become .jsx.

9. Common Mistakes

Error 1: Objects are not valid as a React child

Wrong
const order = { dish: 'Biryani', qty: 2 };
return <p>Order: {order}</p>;
Fixed
return <p>Order: {order.dish} × {order.qty}</p>;
// Debug view: {JSON.stringify(order)}

Error 2: Too many re-renders

Wrong
const [qty, setQty] = useState(1);
return (
  <button onClick={setQty(qty + 1)}>
    +1
  </button>
);
// setQty runs DURING render →
// render again → setQty → ... loop
// "Too many re-renders. React limits the
//  number of renders to prevent an
//  infinite loop."
Fixed
const [qty, setQty] = useState(1);
return (
  <button onClick={() => setQty(qty + 1)}>
    +1
  </button>
);
// Arrow function runs only on click

Error 3: Cannot read properties of undefined (reading 'map')

Wrong
const [items, setItems] = useState();
// first render: items === undefined
return <ul>{items.map((i) => (
  <li key={i.id}>{i.name}</li>
))}</ul>;
Fixed
const [items, setItems] = useState([]);
return <ul>{items.map((i) => (
  <li key={i.id}>{i.name}</li>
))}</ul>;
// Or guard: items?.map(...)

Error 4: Functions are not valid as a React child

Wrong
function Footer() { return <p>© Shop</p>; }
return <div>{Footer}</div>;
// Dev warning: Functions are not valid
// as a React child. This may happen if
// you return Footer instead of <Footer />
Fixed
function Footer() { return <p>© Shop</p>; }
return <div><Footer /></div>;

Error 5: Lowercase component

Wrong
function cartBadge() { return <b>3</b>; }
return <cartBadge />;
// Warning: The tag <cartBadge> is
// unrecognized in this browser. If you
// meant to render a React component,
// start its name with an uppercase letter.
Fixed
function CartBadge() { return <b>3</b>; }
return <CartBadge />;

Silent bug: stray 0

Wrong
{cart.length && <CartIcon />}
// empty cart → screen shows "0"
Fixed
{cart.length > 0 && <CartIcon />}

11. Quick Revision

  • Three kinds: compile errors (overlay), runtime errors (console + blank), warnings (dev only).
  • Read the first line + file:line. The message usually names the fix.
  • Object as child → render a field. Function as child → <Comp />.
  • undefined.map → default state to [].
  • "Too many re-renders" → onClick={() => fn(x)}, not onClick={fn(x)}.
  • Vite: JSX only in .jsx/.tsx files.
  • Silent bugs: stray 0 from &&; missing return in map.

12. Interview Corner

What does "Objects are not valid as a React child" mean?

You placed a plain object (or a Promise, or a Date) inside JSX braces. React can render strings, numbers, elements, arrays of these, and nothing for booleans/null/undefined. Render a field, map the data, or stringify it.

Why does onClick={handleClick()} cause problems?

The parentheses call the function during render and pass its return value as the handler. If it sets state, each render triggers another render → "Too many re-renders". Pass the function itself or wrap in an arrow.

Do you still need import React from 'react' in every JSX file?

No. With the automatic JSX runtime (default in Vite and React 17+), the compiler imports jsx from react/jsx-runtime for you. "React is not defined" only appears with the old classic runtime setting.

Why are some messages visible in development but not production?

React's development build includes extra checks and readable warnings. The production build removes them for size and speed, and shows short error codes with a link to the full message.

A. Concept in 30 Seconds

  • JSX problems come in three kinds: compile errors (bad syntax, Vite overlay), runtime errors (bad values, console + blank screen), warnings (dev only).
  • Read the first line and the file:line. Most messages name the fix.
  • Top culprits: two roots, unclosed tags, objects/functions as children, undefined.map, onClick={fn()}.
Memory hook: Syntax → overlay. Data → console. Habit → warning.

B. Important Syntax

return <>...</>;                 // two roots → Fragment
<img />  <br />                  // close void tags
{ok ? <A /> : <B />}             // no if in braces
{user.name}                      // not {user}
<Header />                       // not {Header}
useState([])                     // not useState() before .map
onClick={() => add(item)}        // not onClick={add(item)}
style={{ color: 'red' }}         // not style="color:red"
{list.length > 0 && <List />}    // not {list.length && ...}

C. Must-Know Points

  1. Compile errors stop the whole file; fix them first.
  2. Vite only transforms JSX in .jsx/.tsx files by default.
  3. React renders: strings, numbers, elements, arrays; ignores true/false/null/undefined.
  4. Objects, Promises, Dates as children → runtime error.
  5. A component function placed as a child → "Functions are not valid as a React child" warning; nothing renders.
  6. Calling a state setter during render → infinite loop → "Too many re-renders".
  7. Default arrays to [] before .map.
  8. 0 && x renders 0; '' && x renders nothing.
  9. Warnings are dev-only; production shows minified error codes.
  10. In dev with <StrictMode>, components render twice, so console logs from render can appear twice.

D. Interview Questions

Basic

What is the difference between a compile error and a runtime error in React?

Compile errors are invalid syntax caught when Vite transforms the file (nothing runs). Runtime errors happen while rendering, usually from wrong data types or undefined values.

How do you fix "Adjacent JSX elements must be wrapped in an enclosing tag"?

Wrap the siblings in a parent element or a Fragment <>...</>.

Intermediate

Why does an empty list show "0"?

{list.length && <List />} evaluates to 0 when empty, and React renders numbers. Use list.length > 0 && or a ternary.

What causes "Cannot read properties of undefined (reading 'map')"?

Calling .map on a value that is undefined: state with no initial value, data not loaded yet, or a wrong property name from an API. Default to [] or guard with optional chaining.

Advanced

How do you stop one runtime error from blanking the whole app?

Wrap sections in an error boundary. React 19 has no function-component error boundary API built in; you use a class component with getDerivedStateFromError, or a library such as react-error-boundary. Note error boundaries do not catch errors in event handlers or async code.

Why might a Vite project show "Failed to parse source for import analysis"?

The file contains JSX but has a .js extension (or has a genuine syntax error). Vite's message suggests naming the file .jsx/.tsx.

Tricky

Does a missing return inside map throw an error?

No. The callback returns undefined for every item, which React renders as nothing. It is a silent bug.

Does {Header} throw?

No error is thrown; React logs a dev warning ("Functions are not valid as a React child") and renders nothing for it.

Q1. What appears on screen when count = 0?

<p>{count && 'New messages'}</p>

Q2. What appears?

const tags = ['veg', 'spicy'];
return <p>{tags}</p>;
Show answer

vegspicy. An array of strings renders each string with no separator. Use tags.join(', ') for "veg, spicy".

Q3. What happens?

return <p>Ordered on {new Date()}</p>;
Show answer

Runtime error: "Objects are not valid as a React child". A Date is an object. Use {new Date().toLocaleDateString()}.

F. Debugging Questions

Q1. Vite overlay: "Unexpected token".

<ul>
  {for (const d of dishes) { <li>{d}</li> }}
</ul>
Show answer

for is a statement. Use {dishes.map((d) => <li key={d}>{d}</li>)}.

Q2. Button runs placeOrder as soon as the page loads.

<button onClick={placeOrder(cart)}>Pay</button>
Show answer

It is called during render. Use onClick={() => placeOrder(cart)}.

Q3. Weather card crashes only the first time.

const [data, setData] = useState(null);
// ...fetch sets data later
return <p>{data.temp}°C</p>;
Show answer

First render: data is null → "Cannot read properties of null (reading 'temp')". Guard: {data ? data.temp + '°C' : 'Loading...'}.

G. Scenario-Based Questions

You moved a project from Create React App (deprecated) to Vite and every file fails to parse.

CRA allowed JSX in .js files. Rename JSX-containing files to .jsx (and update imports if they include extensions).

A teammate says "it works on my machine but production shows Minified React error #31".

Production replaces messages with codes. Open the linked page (react.dev/errors/31) to read the full text: it is the "Objects are not valid as a React child" error. Reproduce in dev for the full stack trace.

Your chat list shows a "0" under the header when there are no unread messages.

{unread && <Badge />} with unread = 0. Change to {unread > 0 && <Badge count={unread} />}.
